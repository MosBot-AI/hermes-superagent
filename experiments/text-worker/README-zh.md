## 原生宿主授权与包边界

提案现在向 Hermes 现有能力注册表加入**仅通过明确同意授予的 `llm.text_worker` 权限**。实验插件应在 manifest 声明它，以进入普通宿主同意界面。授予记录位于 `plugins.entries.<id>.granted_capabilities`；旧 `allow_*` 标志或只启用 `text_workers` 均不构成授予，宿主不会自动授权。启动及新模型工具披露，同时要求当前权限和准确提供商/模型/base URL opt-in，并从同一配置快照读取。

`PluginContext.has_capability("llm.text_worker")` 从创建该 context 的插件管理器 profile 读取权限。文本生命周期服务也绑定同一规范化 profile home。保留 profile A 的 context 后切换到 B，不能借用 B 的权限或句柄，即使插件 ID 和模型相同。撤销会阻止后续准入/发送/模型工具披露检查，但不能收回已发送数据、旧父会话历史或扣费。普通 `launch()` 行为及其他插件能力保持不变。

消费者和账本现在相对导入同包的 `personal_agent`，不再意外依赖开发仓库的 `PYTHONPATH`。冷启动隔离 `python -I` 测试阻止全局 `personal_agent` 导入，覆盖原生包发现、任务记录、明确授权、通过 mock HTTP transport 的拟议宿主请求、保存草稿和重新加载，并检查模块来源和同包错误类型身份。这修复了实际的包加载缺陷，但仍是**离线安装形态测试，不是官方安装或真实 Gateway 验收**。

原始采用检查单为：审阅/发布本宿主权限约定 → 把实验消费者与其生产同包模块一起打包并声明权限 → 单独批准安装/宿主同意及准确路由 → 授权单任务 → 真实验收。后续[受门控生产包集成](../../docs/55-gated-plan-worker-zh.md)声明权限并接入生产副本，受默认关闭配置、准确宿主约定及当前同意门控限制；干净基线宿主仍不注册 worker。未安装包、未提交上游，也未增加 DNS/代理/TLS 绕行。

## 收窄后的实用流程

[实验消费者](consumer.py)把真实本地任务接到拟议的 `ctx.subagent_lifecycle.launch_text` API：

1. 已授权的原生 LOCAL 会话控制者执行 `/personal-plan-worker allow TASK_UUID REVISION REQUEST_ID`，批准把所选活动任务快照交给 OpenCode Go `deepseek-v4.1-flash` 做一次规划，有效期最长 120 秒，输出上限 1024 token，请求超时 30 秒。正常模型用量可能产生费用。命令本身不发起请求。
2. 在真实主会话轮次中，`personal_task_plan_preview` 可以消耗该准确授权。仅允许 `action`、`request_id` 两个字段。模型不能提供目标、任务、上下文、提供商、模型或权限。准入时观察到任务修订变化、授权过期/撤销、会话/路由/配置档不符或子代理轮次，都会在派发前拒绝。任务存储、领取账本和提供商提交不在同一事务中，修订检查之后的并发编辑不能撤回已批准快照。
3. 消费者先提交持久单次领取记录，再调用宿主。宿主准入一个有界、单请求的纯文本 worker，返回普通生命周期句柄。只有原消费者保留该能力句柄。重复 launch 只检查同一句柄或保存的回执；异常或重启留下结果不明的记录，绝不自动重试。
4. 结果返回**不可信的规划草稿**、快照/当前修订和过时标记。不会更新任务状态、创建提醒、派发可执行工作或发送消息。模型声称完成不构成任务状态变更。

`revoke REQUEST_ID` 阻止尚未开始的调用。已准入的调用可能完成，重新加载/卸载不能收回提供商已接收的数据或取消计费。独立私有 `text-worker-ledger.sqlite3` 保存任务标识、快照哈希、请求范围及已观察到的终态草稿。快照正文和活跃能力句柄仅留在进程内。公共只读 `authorize_text_route` 检查返回不含秘密的指纹，不创建客户端或发起请求。领取时绑定准确提供商/模型/base URL/API 模式指纹，实时和保存草稿在每次新工具返回前，都必须再次匹配批准路由。已保存草稿可在重新加载后读取，并按当前任务修订判断是否过时。已完成但尚未观察的结果可能丢失，仍保持不明。

请求 ID 在配置档内唯一，绑定原会话/路由/任务/修订。每个消费者实例有独立 owner epoch，重启或并发实例可读取匹配范围的保存回执，但不能接管待执行授权、窃取领取记录或重试结果不明的请求。新 key 是新授权，不是旧操作恢复。绝不要换 key 重试结果不明的调用。记录无限期保留，上限 64 条，容量满时拒绝新授权，不自动清理或淘汰。删除账本会破坏去重保障。这是刻意有界的实验，不是持续无人值守编排。观察到配置撤销会永久撤销未启动的授权；未被观察到的关闭→恢复变化，需要宿主单调修订栅栏才能识别。

## 原生请求工作台

这些明确命令让操作者无需让模型调用预览工具，就能找到并检查请求。与 `allow` 一样，要求已认证的 LOCAL 会话控制准入、同配置档和准确会话/路由范围：

| 命令后缀 | 结果 |
|---|---|
| `list [--after KEY]` | 按请求 ID 排序，最多十条元数据及续页 key，不含任务正文、草稿、owner token 或路由指纹 |
| `status KEY` | 授权/回执状态及真实下一步，已消耗请求不证明 worker 仍在运行 |
| `draft KEY` | 已保存终态回执、不可信草稿和当前任务修订/过时信息，不实时轮询或发起模型请求 |
| `stop KEY` | 撤销未启动授权；对已准入/结果不明请求报告取消不可用，且不改变它 |

例如，`/personal-plan-worker list` 找到保留的请求 ID，`/personal-plan-worker draft plan-1` 显示保存草稿。原生输出默认可读文本，`/personal-plan-worker --json status plan-1` 返回结构化数据。不可信草稿被明确分隔，控制字符会转义。模型工具仍只返回 JSON，准确批准路由检查不变。

`receipt_saved` **不表示**任务已执行。重启后，已消耗但没有保存回执的请求仍为 `launch_outcome_unknown`，旧实例拥有的待执行授权不会被静默接管。`stop` 绝不把远端结果不明改称“已取消”。工作台命令不派发、不重试、不采集活跃结果、不删除保留 key，也不更改任务。列表仅显示本会话/路由数量，不暴露共享 64 条账本中其他会话的占用量。

明确的原生草稿查看是独立的操作者读取契约，不是模型路由旁路。在固定宿主中，`gateway/session_commands.py` 以 `exec` 返回插件输出，已审阅 CLI/TUI/Desktop 处理会显示输出，而不是走模型发送分支。本轮实际测试服务器命令路径，客户端分支仅做源码审计，未进行真实 UI 验收。客户端可能保留显示/缓存数据，用户也可自行复制到其他地方。LOCAL 控制者可能是程序，不证明物理真人，也不保证任意未来客户端不记录输出。

原生命令回调不绑定当前模型父对象，因此此处无法取消已准入请求。工作台不会复制旧上下文或冒充父对象绕过该边界。已有模型工具预览路径和宿主生命周期 API 保持不变。

## 宿主约束，而非提示词承诺

现有不受此约束的 agent 启动保持不变。新文本路径默认关闭，按可信插件及准确的提供商/模型/base URL 单独配置，仅接受当前普通 OpenAI SDK chat-completions 路由。不查询已保存的 delegation 路由、回退链或凭据解析器。HTTPS 端点不得含 userinfo/query/fragment。拒绝 SDK provider 适配器、动态认证及 query 覆盖。

宿主现拥有**专用 no-redirect HTTPX 客户端**，关闭环境代理/配置及传输重试。仅使用准确批准的 HTTPS chat-completions 目标和父客户端已解析的静态 API 身份，不读取凭据文件、不解析其他路由、不重新构造 OpenAI SDK 客户端，从而避开 SDK 构造器隐式发现环境请求头的行为。不继承或改变父 sockets、transport、headers、auth、hooks、redirects 或 proxy 设置。默认跟随重定向的父 SDK 客户端可兼容这条隔离路径。TLS 使用显式验证上下文和 certifi 根证书，不发现环境 CA/keylog 配置。拒绝压缩响应，原始响应体上限 512 KB，使用官方响应模型解析后，由宿主 transport 归一化。提供商返回的模型标识不符时，会在响应后拒绝结果，不能撤回先前请求。

文本路径不构造或运行完整 `AIAgent` 子代理，使用真实宿主传输与中间件、不可变请求和单次受控调用回调，仅发送固定规划指令与所选任务快照。不会继承父历史、prefill、工具 schema、请求覆盖、MCP 权限、递归委派、工作区创建、记忆摄入、压缩或辅助模型工作。不派发模型返回的工具调用；任意中间件请求变化或额外尝试均被拒绝。

路由检查阻止在改变后的路由中**通过模型工具新返回**草稿，不删除旧消息，也不能阻止宿主在切换模型后重新使用已有父会话历史。不要把它视为整个会话的跨提供商隔离。

这不是 OS/Python 沙箱，不能防御恶意同进程插件、提供商实现或操作者。配置的插件信任不证明每次调用由真人亲自发起。原生 LOCAL 准入依赖宿主已有的注册来源/会话控制者检查，所有获授权控制者共享该会话权限。提供商内部行为以及实际计费/执行模型仍不能仅由客户端证明。超时/取消是协作式的，不能撤回已发送的请求。

## 安全终态诊断

已观察到的终态回执现在只保留固定失败类别及现有本地提交回调尝试次数（0、1 或不可用）。原生 `draft KEY` 对 DNS、证书校验、连接/读取/写入/连接池超时、连接/读取/写入/协议失败、取消或未分类失败显示固定说明。不会显示原始异常、header、URL、证书路径或提供商响应正文。未知诊断归为一般失败；格式不合法的保存诊断被拒绝。旧回执缺少此字段仍可读取，不虚构历史，不重置 schema。

这些只是本地观察，不证明提供商执行、送达、扣费或取消。任何诊断都不会重新开放授权或允许自动重试，即使次数为零。准确路由披露检查及单次传输保持不变。本功能仍属于未安装实验。

## 提供商兼容性及实际验收尝试

OpenCode Go 要求 session-affinity header。专用客户端现在仅对准确的 `opencode-go` 提供商及 HTTPS `opencode.ai:443` 源站，在空上下文中以全新单次标识调用官方宿主 affinity helper。不继承父/根会话标识或任意 header。已配置的 `/inference/go/openai/v1` 与元数据 `/zen/go/v1` 路径均保留准确目标检查。其他源站、相似域名及其他提供商不会获得此 header。所选离线测试现为 247 项宿主及 109 项消费者测试。

一次明确获授权的合成请求通过官方凭据解析器及本传输路径访问 `https://opencode.ai/inference/go/openai/v1`，只请求 `deepseek-v4.1-flash`。请求以 `ConnectError` 失败，没有 HTTP 状态或模型响应。是否送达未确认；未重试、fallback 或改用其他路由。`config.yaml` 未变；官方解析器可能维护凭据元数据，不能据此声称整个 profile 未变。未使用原生激活、worker 启动或 Gateway。**真实 worker/模型验收仍未完成。**

后续仅本地审阅发现与早期成功 SDK 探针的明确差异：早期使用 HTTPX 环境路由/CA 默认值，本专用客户端则刻意忽略环境代理并使用 certifi 根证书。原始异常原因及早期环境快照未保留，因此路由或 CA 不匹配只是推测，不是已确认根因。未重发请求，也未放宽代理/TLS 策略。

另一次针对生产仓库的官方安装尝试，在全新无凭据离线 profile 中被未修改的扫描器阻断：CAUTION，50 条发现，退出码 1。未接受覆盖；官方列表和文件系统检查确认插件不存在。仓库安装源包含开发文档/测试及这些实验，当时生产注册不导入 worker。离线运行时分发构建器及后续受门控 worker 打包，都不是绕过该结论的许可。安装、激活和受支持宿主 worker 能力尚未验证。

使用全新、可信、无凭据、位于准确基线的可丢弃源代码副本，已准备好的 Python 3.14 测试解释器，以及经过审阅的工件。暂存前先审阅补丁。以下是主动执行的实验步骤，不是生产安装程序：

```bash

COPY="/path/to/disposable-hermes"
```

[运行器](run_tests.py)先验证准确基线、已暂存补丁字节和消费者/测试哈希，再调用宿主标准测试运行器。不应用补丁、不安装包、不创建依赖环境、不配置个人配置档。`--check-only` 只检查上述条件，不执行宿主 Python。测试使用临时 home 与 HTTP mock transport，无监听器、真实模型/提供商请求或凭据。消费者测试运行真实原生命令授权、轮次准入、SQLite 任务存储、宿主生命周期、专用 HTTP 请求序列化及官方响应解析。

实际运行测试还需要 `--clean-checkout` 指向独立且未修改的准确基线宿主，同时提供隔离补丁副本 `--checkout` 和 `--disposable-copy`。`--check-only` 行为不变，不要求干净宿主。宿主/消费者通道之后，运行器单独调用冷启动生产入口测试，避免官方 runner 清除明确的干净/补丁宿主路径。历史消费者文件保留作比较回归；正式生产模块保留其行为，并增加严格注册/操作门控和冻结上下文投影。

CI 使用独立步骤，仅向新建可丢弃 worktree 应用已审阅补丁，再运行所选宿主/消费者及冷启动干净/补丁生产入口检查。这不是安装或真实验收。

普通项目检查器仅验证工件完整性，继续针对**未修改的干净宿主**进行契约测试。准确提交的项目 CI 不是该宿主提案的上游 CI，也不是真实模型验收。隔离实验是单独选定的测试范围，不是全量上游测试。没有重试曾被拒绝的 Gateway socket 测试。

扩大后的受影响宿主回归覆盖 14 个文件：**422 通过、1 失败、0 跳过**。同一数据库路径断言在未修改基线上也失败，原因是本环境 `/var/tmp` 指向 `/tmp`，而官方 runner 使用 `/var/tmp`；未改源码或断言掩盖失败。此前所选工件记录过 356 项通过；这是历史数量，不代表扩展后的生产入口测试通道。两条测试通道都不是完整上游套件，后者还包含不可用或已禁止的真实传输场景。

## 剩余发布门槛

- 独立宿主 API 采纳/安全审阅和受支持版本，而不是向用户安装应用本地补丁。
- 通过获授权配置进行真实 OpenCode Go `deepseek-v4.1-flash` 验收，观察 wire/用量行为；不得换模型或静默回退。
- 在持续自主派发前，完成生产级提供商结果不明核对、提供商持久执行标识、容量/保留交互、并发限制和预算统计。本地原子领取防止自动再次提交，但不能防止未观察结果丢失，也不保证提供商恰好执行一次。
- 合理的取消/超时界面与可靠进度投递。短时轮询结束不能证明远端取消。
- 带工具 worker 仍需单独的可执行能力约束设计。纯文本预览不是代码执行、完整 worker 编排、Gateway 全链路验收、自动记忆或 MVP 完成。
