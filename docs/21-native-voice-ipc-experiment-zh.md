# 21. 原生语音 IPC 实验

[English](21-native-voice-ipc-experiment.md) | 简体中文

## 1. 仓库包含什么

[可审阅补丁和验证清单](../experiments/voice-ipc/README-zh.md) 保存了经过测试的独立 Hermes 宿主原型。**插件不会安装、导入或应用该补丁。** 它不是上游发布版本，也不是已经集成的 Personal Agent 语音功能。项目正式兼容性基线仍为 `90d6b98fd86d20981ee06ddd5b7d93e4320f26a4`。

[正式固定版本契约测试](20-voice-contract-simulator-zh.md) 仍正确观察到不可用的 `Opaque` 流返回对象。实验展示了跨越该限制的具体适配路径，不会改写基线的行为，也不会让生产语音自动可用。

本工件不包含 main 分支合并、上游贡献、部署、provider 账号、麦克风权限或实际通话，不需要 API Key。

## 2. 真实原生消费路径

补丁修改现有宿主行为，而不是增加另一个模拟器或 Agent 循环：

- ASR：`tools.transcription_streaming.open_streaming_session` 获得有类型的宿主 `TranscriptionStreamSession`，通过现有隔离插件宿主管道输入 PCM 并取得部分/最终文本。
- TTS：`tools.tts_streaming.resolve_streaming_provider` 获得配置指定的宿主 provider；现有 streamer 增量拉取 PCM，而不是收到不可用的迭代器占位对象。
- 专用 `voice_open`、`voice_op`、`voice_close` 及批量 `voice_release` 消息只承载已识别的 ASR/TTS 流契约，不创建通用远程对象接口。
- 原生消费者在完成、错误、取消、提前退出及达到字节上限时关闭支持的租约。没有 `close` 的既有进程内对象仍保持兼容。

这些原生消费函数是宿主实现路径，不是新声明的插件公共 API。公开 ASR/TTS registrar 是 producer 注册接口，并不构成通用 `ctx.voice` consumer facade。隔离宿主仍不支持插件 CLI 注册。不要通过导入内部 dispatcher 或关闭隔离来假装这些缺口已经解决。

## 3. 限额与生命周期

原型限制每个宿主最多 32 个活动句柄/会话、每块最多 1 MiB、每条流累计音频最多 32 MiB，打开参数或每个接受的文本字段最多 64 KiB。这些是兼容性限制，不是 [19](19-unified-voice-provider-contracts-zh.md) 中的生产 profile 协商结果。

TTS 每次拉取只推进一块，不提前展开整个流。每条会话只允许一个在途操作；ASR finalize 为单次操作。无效结果、错误、关闭、卸载和宿主 generation 变化会使相关句柄失效。旧流不会在宿主重启后自动恢复。

关闭请求逻辑隔离并安排清理，不会中断阻塞的 provider 计算，也不能证明清理已完成或计费已停止。在途计算和清理继续占用子进程容量，直至返回。清理独立于无关管道调用，关闭确认有有限等待。垃圾回收释放为尽力而为，由后续宿主调用发送。父进程限制待处理句柄/释放记录，并重试结果不确定的清理确认，不会复活已关闭的流。

## 4. 已验证证据

补丁在基线精确匹配的一次性源码副本中测试，使用真实插件发现、独立子进程 PID、现有管道和上述原生消费路径。引擎为确定性 fixture，不是真实语音服务。

- 选定回归：13 个文件通过 120 项测试，无失败，一个模块跳过。
- 两个新增桥接/消费者文件包含 17 项通过的测试，在最后仅注释修改后也重新运行通过。它们已包含在 120 项中，不是额外 17 个不同测试。
- 全部 14 项上游静态检查通过。两处经审阅的 catch-all 注释保留原生错误封装和尽力关闭契约，没有新增 provider 数据日志。
- 跳过的较大 TTS 模块需要环境中没有的 `numpy`。较早一次探索性运行另通过两个现有 loopback WebSocket STT 测试，它们不在最终聚焦管道的测试入口中。此前受限的九项身份 socket 测试未运行或重试。
- 后续经单独授权，按同一 lock 新建了含 NumPy 2.5.4 和 sounddevice 0.5.6 的 PM 环境。此前跳过的 TTS 文件随后通过 44 项测试，无失败/跳过，其中 loopback fixture 通过，真实 provider/播放仍被 mock。原环境和运行依赖未改。这解决了缺少 NumPy 的测试缺口，不代表通过产品门槛，也不是在新环境把全部 164 个不同测试重跑；清单保留两套环境指纹。
- 实验清单记录补丁校验和、精确基线及本地原型版本。本地原型版本用于溯源，不是已发布的上游提交链接。

常规项目检查仍要求正式固定版本的干净源码，必须拒绝修改后的副本。请使用实验独立的审阅步骤，不要放宽 `compatibility.json` 或修改预期 `Opaque` 的测试来制造通过结果。

## 5. 尚未满足的产品门槛

原生 ASR 输入队列仍无界。桥接限制不能证明整条链路的缓冲、内存、并发或 deadline 有界。通用 IPC 异常及分派机制未更改，每 profile 插件进程也不是抵御恶意插件或同一 OS 用户的沙箱。

没有增加生产身份签发、owner 绑定、私人读取、权限授权、主 Bot 激活、原生 turn、外部操作或设备访问。未验证实际识别准确率、可听播放、延迟、在线服务、计费或手机设备行为。

采用受支持的宿主接缝，完成媒体准入/取消、身份/会话/预算/隐私控制，再验证明确选定的真实 provider 和设备，是后续独立步骤。本工件只推进 E0.8/E7.5 的证据。E7.6/E7.7 生产启用仍为 Backlog，任何语音发布门槛都未完成。
