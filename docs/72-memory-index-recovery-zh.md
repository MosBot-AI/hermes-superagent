# 显式本地记忆索引检查与恢复

[English](72-memory-index-recovery.md) | 简体中文

## 用途与操作流程

SQLite 权威记录仍是唯一依据。FTS 索引是派生搜索结构，不是备份。即使 SQLite 和 FTS 内部完整性检查通过，缺失或过时的派生行仍可能使词项搜索漏掉有效记录。本流程检查索引与权威记录的对应关系，并为受支持的派生索引不一致提供显式恢复入口。

```text
/personal-memory index-status
/personal-memory index-rebuild --expected-watermark N
```

使用 index-status 实际返回的权威事件水位，不要猜测数字。决定重建前先检查状态。两项操作均仅限既有可信单用户 profile 边界内的操作人员。不增加模型工具、不选择 provider、不调用模型、不读取来源文档，也不联系远端服务。重建不会自动发生，普通搜索也不会偷偷调用重建。

流程要求已有、归属正确且使用当前 schema 的存储。不会创建缺失的数据库、迁移旧数据库或接管外部 namespace。未知 schema、不安全文件、不支持的存储及关闭持久 FTS secure-delete 的设置仍然会被拒绝，而不是借机修复安全设置。受支持的 schema 升级应通过正常、显式选择的兼容写入流程，不应以索引维护作为捷径。

## 状态能够证明什么

检查在将记录视作重建来源之前，会验证权威结构以及有界的记录/事件一致性。随后双向检查对应关系：FTS 中缺失的活跃权威行、没有活跃权威对应记录的多余 FTS 行，以及正文/主题不匹配。还会检查 FTS 内部一致性。结果仅含数量、状态与当前事件水位，不返回陈旧索引文字或权威正文。

按既有契约，已到期但仍 active 的记录应保留在索引中；新查询仍按 expiry 过滤。已遗忘记录不应在索引中。健康结果仅适用于本次检查快照，不证明之后所有读取、恢复的副本或外部修改都健康。既有 search_terms 的 `index_stale: false` 仍描述同步的受支持写入，不是取证式健康检查。

检查使用新数据库连接，在首次访问 FTS 之前取得共享写入隔离锁，避免把长连接的过时 FTS 配置缓存误当作持久化损坏。FTS 原生完整性检查使用形似 SQL INSERT 的控制命令，因此 status 不是 SQLite query-only 操作。检查在仅回滚的子事务中执行，不提交新的权威或索引内容变化。SQLite 可能恢复中断事务遗留的、安全归属的回滚日志；这不承诺文件逐字节保持不变。它可能短暂与普通写入竞争。若 WAL 格式文件没有已有 sidecar，SQLite 可能在检测并拒绝该模式前创建记账 sidecar；维护不会切换日志模式或继续执行。因此，拒绝不保证没有文件系统副作用。路径检查刻意避免打开再关闭原始数据库文件描述符，因为这样可能释放同进程另一 SQLite 连接的 POSIX 锁。

## 显式重建与恢复限制

重建在同一写事务中重新检查预期水位和权威数据有效性，然后重建并验证索引。只使用当前 active 权威记录，不使用缓存正文或旧索引内容。提交前必须同时通过逻辑对应和 FTS 内部完整性检查。重建仅针对固定的 FTS 虚拟表及其派生影子表，不接受任意表名或 SQL 输入。

权威记录、revision、事件、回执、expiry、Markdown 投影和可编辑草稿均不修改。并发更正或遗忘受共享写入锁排序：重建不能在遗忘提交后发布更早缓存的事实。提交前任何失败都会回滚派生变化。本操作不修复损坏的权威数据、未知数据库格式或不安全设置。若无法确认安全归因，应停止，而不是猜测保留哪些事实。

没有请求 ID，也不持久保存历史维护回执。在相同当前水位下重复重建，可以安全地重建相同派生状态；受支持的权威变更会推进水位，使旧请求过时。结果不确定或重启后，请检查当前状态。新状态是新检查，不证明中断调用当时做了什么。水位是受支持写入的并发约束，不防范任意直接改库或用陈旧备份替换数据库。

这是逻辑索引恢复，不是物理介质擦除、备份恢复、来源级重新提取抑制，也不承诺找回权威存储里已不存在的数据。此前历史、已打开读取、文件复制件和备份仍有既有限制。本流程不包含安装或部署。

## 验证边界

验收矩阵覆盖 FTS 漏行、多余行、错内容、遗忘记录残留、真实倒排索引故障、不安全配置及权威损坏拒绝、旧 schema/缺失文件处理、水位冲突、并发更正/遗忘、事务失败、进程崩溃和安全重复执行。还包括受支持测试构建上的独立新连接 SQLite/FTS 检查，以及 pinned 宿主操作人员准入和模型工具拒绝。

精确运行数量与版本记录在关联 PR。合成故障注入不说明正常受支持写入当前会损坏索引，也不认证生产数据库修复。这是 #44 下有界的恢复切片；更广泛的导入、来源抑制、迁移与实时验收仍未完成。
