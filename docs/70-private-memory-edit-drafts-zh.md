# 私有 Markdown 记忆编辑草稿

[English](70-private-memory-edit-drafts.md) | 简体中文

## 用途与显式流程

本地操作人员可以在编辑器中修改一条现有记忆的正文和主题，不必把长正文塞进命令行。SQLite 仍是唯一权威。本功能不是任意 Markdown 导入、批量迁移或第二套可写记忆存储。本流程不编辑生成的 records.md 投影、Hermes MEMORY.md 或 USER.md。

    /personal-memory edit-status
    /personal-memory edit-create RECORD_ID --expected-revision 3 --request-id edit-create-1
    /personal-memory edit-preview DRAFT_ID
    /personal-memory edit-apply DRAFT_ID --expected-digest SHA256 --request-id edit-apply-1
    /personal-memory edit-discard DRAFT_ID

创建需要目标当前 revision，返回草稿身份和清理提示。每个 profile 最多一个活动草稿。若创建响应或文件丢失，可用 edit-status 找回其 ID 和生命周期状态；该操作不创建草稿，也不读取正文。不安全文件状况以脱敏 file_check_error 返回，同时仍提供已登记草稿 ID；状态查询不会修复或删除文件。重放创建返回生命周期状态，不承诺文件仍存在。请保存草稿 ID 和请求 ID；对于结果不确定的创建/应用，使用原请求 ID 与完全相同的参数重试。原生命令可在省略时生成 ID，但新生成的 ID 不是原操作的重试。

固定文件位于 profile 私有插件目录，与 records.sqlite3 并列的 memory/edit.md。保留路径 .edit.md.pending 是受管理的暂存文件，不是另一个用户文档。不接受任意输入或输出路径。显式创建会将这些固定位置登记为草稿生命周期管理的文件：**应用、丢弃、更正目标或忘记目标都会移除其内容，包括手工编辑。** 没有活动登记时，已有文件属于未知文件，不会被静默接管、覆盖或删除。

## 编辑与审阅

保持生成的标题和身份 JSON 行逐字节不变。Topic 行包含一个 JSON 字符串，可以修改其值但必须保持合法 JSON。接下来的空行分隔元数据和可编辑的多行正文。正文是字面文本，包括 Markdown 语法在内，不是可执行指令。正文和主题分别沿用权威存储的 2,048 和 128 字符上限；预览/应用输入限制为 32 KiB。已登记文件即使超大，只要其他安全归属检查通过，仍可丢弃或随目标忘记清理，不读取其正文。不能通过编辑文件提供或改变记录身份、namespace、基准 revision、来源归属或到期时间。

预览读取当前文件与目标，返回完整的修改前/拟议正文和主题、SHA-256、基准 revision、保持不变的到期时间及清理提示。请审阅这些内容，而不只是成功标记。预览不修改权威记忆。应用会重新读取文件，核实已审阅的准确摘要和目标 revision，然后执行普通权威更正。文件或目标发生变化意味着冲突，不代表允许静默变基。没有自动接受，也不会退化为新建一条记录。

既有到期时间保持不变。更正已到期记录不会续期。接受更正会更新正常事件/回执及 FTS，并使受管理投影失效。非可信草稿正文不会因此变成授权、已验证来源作者或指令。这些命令仅供操作人员使用；模型工具 schema 与会话权限不变。

## 文件、遗忘与恢复

要求当前用户拥有的私有 POSIX 目录和普通单链接文件；危险权限、链接及不支持的文件类型会被拒绝，而不是被修复。编辑器可以原子替换已登记文件。登记后，由固定路径的生命周期归属允许清理手改内容，而不是要求 hash 或 inode 不变。同一用户恶意修改文件系统仍不在可信本地边界内。

Schema v9 新增有界草稿元数据，不存储草稿正文副本。受支持的可写打开过程执行迁移；只读访问不能迁移。最多保留 1,000 行草稿元数据，包括防止重试复活所需的终态身份。该限制影响新建，不阻断普通丢弃、忘记或清理。没有自动到期计时器或后台清理；草稿会保留，直到显式丢弃/应用或目标变化使其失效。

创建先持久化 preparing 意图，再在共享 SQLite 写入隔离范围内发布。发布前重新检查活动意图与目标 revision。暂停的旧发布者不能跨过已提交的目标更正/忘记，重新生成旧明文。目标修改必须先移除已登记草稿/暂存文件并同步目录，才能提交。缺少必要文件适配器的裸 backend 不能绕过此责任。其他记录变化不会静默消耗当前草稿。

SQLite 和文件**不是同一个原子资源**。文件移除后、数据库提交前崩溃，可能留下仍活动但文件缺失的登记。ready 草稿不会静默重建，否则会丢弃用户编辑；预览会报告文件缺失，显式丢弃可清除登记。中断的 preparing 意图仅在目标和身份仍有效时才能恢复。准确终态重试只返回元数据回执，不重新创建文件或再次执行更正。终态之后出现的未知替换文件不属于旧重试可以清理的对象。

忘记不能撤回已经打开的文件描述符、编辑器缓冲区、宿主历史、复制件、备份或物理存储痕迹。受管理文件清理保证仅适用于支持部署条件下登记的本地草稿和暂存文件。不要用这些明文文件存储秘密。

## 验证边界

本切片要求验证创建/编辑/预览/应用/丢弃和重启；过时摘要/revision 与已忘记目标拒绝；发布/忘记及应用/更正竞争；文件和数据库失败窗口；未知文件及链接/权限保护；终态重试隔离；权威 FTS/投影一致性；schema 迁移与真实 pinned 宿主命令准入。最终实际完成的检查以关联 PR 证据为准。

这是 #44 内狭义的编辑器更正流程。通用导入、直接手改生成的 records.md、可迁移备份和来源重新提取抑制仍属独立工作。不意味着选择 provider、调用真实模型、安装或部署。
