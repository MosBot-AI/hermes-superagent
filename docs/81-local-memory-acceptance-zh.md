## 真实的搜索新鲜度

此前 `search_terms` 总是返回 `index_stale: false`，即使缺失 FTS 文档导致静默遗漏匹配。现在读取路径在返回记录的同一事务中检查：

1. canonical 和索引文档集合各不超过 1,000 行。
2. 活跃 canonical 行与已存 FTS 文档精确对应，包括已过期但活跃的行；已遗忘/多余行及 content/topic 差异会被拒绝，不为诊断而将私有正文载入 Python。
3. 在应用分页游标或 limit **之前**，完整当前查询的 canonical-only 字面匹配 ID 与 FTS 加 canonical 复核 ID 相等，采用相同过期过滤。这可发现与当前查询有关的 postings 遗漏，即使已存文档一致。

漂移返回脱敏 `index_stale`，不返回部分结果、不自动写入。先用 `index-status`，再有意使用其当前 watermark 执行 `index-rebuild`；未知损坏仍为失败，不伪造健康状态。普通字面搜索和 canonical 召回不依赖 FTS，在逻辑漂移时仍可用。健康响应以 `logical_documents_and_complete_current_query_coverage` 标明精确范围；它不证明所有倒排 postings 正确，也不替代独立原生完整性检查。额外 canonical 扫描有明确上限，不是隐藏修复或远程回退。

## 预算及完成边界

原始 doc30 §10 明确允许在无法使用已选模型 tokenizer 时采用保守字节/字符上限。当前召回对完整序列化 ASCII JSON **items 数组**计预算，包括每条记录的来源字段、引号、转义 Unicode 和列表分隔符；完整记录被省略而非截断。响应报告 `items_json_chars`、`max_chars`、匹配/遗漏数及预算跳过数。这不是 provider token 数、通用字符到 token 转换，也不是外围宿主 prompt 或对话的预算。另行启用的 session 召回对完整召回上下文 JSON 信封（包括警告、元数据和记录）施加固定 6,000 ASCII 字符上限；lifecycle prefetch 默认为 6,000，可在 2,048–12,000 ASCII 字符之间配置。超大记录整条省略，不截断。三个完整信封测试已列入清单 S5。provider-token 预算仍取决于对应 tokenizer 集成；固定回退是本地验收目标。

双连接竞争证据现在在重建开始前打开 forget 后端，等待实际 forget `BEGIN IMMEDIATE` 尝试，并证明在重建释放写者锁前它不能完成。反向排序在 forget 的 COMMIT 前等待 rebuild 实际 BEGIN 尝试，随后要求 watermark 拒绝。已有投影 prepare/forget/resume 证据覆盖另一类旧任务场景：遗忘先提交，旧发布随后恢复。

支持的来源抑制是 namespace 内对待审核及新关联已接受候选的完整输入精确指纹匹配。不能重建旧版已接受摘要，改变输入不匹配，已接受兄弟记录需要单独遗忘。快照浏览是显式历史访问，不是当前召回或恢复。这些限制属于验收边界，不是全局擦除声明。

原始本地后端工作包已验收，可在本次状态对齐合并并验证后关闭 #44。但不关闭 #43 完整适配器 SDK/替换合同、#45 原生生命周期/覆盖工作、#46 迁移与召回验证、通用可移植后端迁移或生产/用户设备验收。运行时受控写门禁保持阻断。早期评论称这些独立功能未完成，并不为 E2.7 创建循环的新前置条件。
