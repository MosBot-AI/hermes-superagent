# 89. 安装包 Gateway 崩溃恢复验收

[English](89-packaged-gateway-crash.md) | 简体中文

## 精确范围

[#113](https://github.com/MosBot-AI/hermes-superagent/issues/113) 为一个狭窄的 E8.2 失败窗口新增手动真实运行候选：任务修改已提交，但客户端尚未消费 RPC 回复时，测试 Gateway 被突然终止。它扩展[安装包生命周期验收](84-packaged-gateway-live-zh.md)，不替代已有 TaskStore 子进程事务故障矩阵。

合成客户端刻意不接收写入回复。独立测试控制器通过只读 SQLite 观察到持久回执，再终止自己启动的 Gateway 子进程。回复可能已经到达客户端的传输缓冲区。因此证据是**持久提交之后客户端未观察结果**，不是证明网络丢包、提交前崩溃、断电耐久性或所有可能崩溃点。

## 真实运行链

当前生产包经过构建和验证，在隔离私有 profile 中由固定版本、未改动的官方安装器扫描并安装。测试使用真实 control ticket 与认证 WebSocket 协议，不使用伪造 runner。它不提交模型 prompt，也不接收 provider 凭据。

1. 创建原生本地 session，发送带显式持久 request ID 的合成 capture，不消费回复。
2. 只读观察已提交回执，强制终止该测试 Gateway 并核实进程退出。
3. 再次启动未改动的官方运行时，不手动删除控制文件或修复数据库。使用新签发 ticket 恢复原 session。
4. 对账规范任务状态，使用完全相同的原请求重试。要求返回原始历史回执，只有一条任务，不重复事件或回执。同一 key 的不同意图必须拒绝。
5. 对带 revision 检查的 update 执行类似窗口，再次重启与对账。过期写入不能覆盖持久 revision。
6. 正常停止最终实例，核实控制通道与端口清理。独立只读检查数据库完整性与规范记录。

仅使用合成数据。失败清理不算成功恢复；不能重启或对账时验收失败。不绕过安全拒绝，不使用替代未认证传输、伪造身份、直接数据库写入或手动状态修复。

## 操作者对账

写入时连接关闭或进程消失，不能把沉默当作失败，也不能换新 request ID 重发。保留原始显式 key 和完全相同的参数。官方运行时恢复后，若已知任务 ID，先检查规范任务；再使用相同 key 重试相同意图，取回回执。回执是历史证据；`show` 读取当前状态。出现冲突需要检查，不应盲目覆盖或自动换 key 重试。

这是本地回执流程，不是外部“恰好一次”送达保证。它不能撤回外部副作用，也不能解决另一个 provider 的未知结果。

## 验证边界

测试不进入默认单元测试集，仅在显式手动 `Native Gateway acceptance` 工作流中运行。准备测试可以检查结构，不能证明真实恢复。只有精确源码 head 的手动证据、独立审查和普通 CI 均成功后才接受；以后版本需要自己的证据。

本地云执行器的 socket 限制未改变；不在那里启动本测试。受支持的 GitHub 托管 runner 是真实执行目标。不使用 MacBook 或其他个人设备。

本次有界验收不完成 #21 的身份/撤权/送达矩阵、E6.9 自然语言验收、远程 owner 权限、共享 REST 可用性、提醒或整个 Super Agent 目标。它是额外故障证据，不是追溯添加到原始确定性本地 M1 定义的新前置条件。
