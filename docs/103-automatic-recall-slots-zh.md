# 103. 自动召回中的原文字面槽位

[English](103-automatic-recall-slots.md) | 简体中文

[Issue #147](https://github.com/MosBot-AI/hermes-superagent/issues/147) 对显式选用的[会话召回](49-session-memory-recall-zh.md)及可选[原生提供方](41-native-memory-recall-zh.md)做有界生产代码改进。它不会激活任一路径、部署软件包、调用模型，也不完成 #43/#45/#46。

## 行为与边界

在历史中文字符边界规划器之前，小型识别器检查带字面语法槽位的完整单分句问句：主语后接 `谁` 和谓语、主语后接 `喜欢`/`想要` 和选择问句，或带所属标记 `的`、显式 `现在`/`目前` 后缀的属性问句。可选的开头请求短语、句末标点和疑问语气词仅在其语法位置识别。这不是通用中文解析。每个查询词仍是当前原始输入中未经改写、区分大小写的子串。

在已识别槽位内，汉字姓名和属性保持完整；拉丁词语及相邻文字系统保持有界词边界。恰好为 `我` 的自我指称会省略。对识别出的多词问句，每个词都必须在同一返回记录的内容或主题中命中。因此项目名的两个词不能替代缺失的所问属性。这是字面共现，不是实体身份、关系抽取，也不证明记录回答了问题。否定陈述作为证据保留，不会转成肯定事实。

仅有空格不能建立语法角色。并列/歧义标记 `和`、`与`、`及`、`或`、`、`、`分别`、`各自` 会阻止新解释。这一检查刻意保守：名称内部包含标记也可能回退。不支持的句式和多个分句原样保留旧规划器与两词匹配启发式。回退仍可能返回不相关事实，但本次没有新增更宽泛的回退或第二次查询。同义词、繁简转换、词序身份和无限制中文分词仍不支持。使用同义属性的记录可能漏掉。

输入限制仍为 2,048 字符，最多八个不同词，每词不超过 128 字符。已识别计划若超过词数/长度限制会拒绝查询，而非丢弃靠后的主语或属性。新过滤器在现有单次新鲜读取和有界打包之后运行，不补充读取。此前的排序或预算遗漏可能隐藏相关记录；空结果不证明不存在。会话路径仍最多输出六条完整记录和 6,000 字符的 ASCII 转义 JSON。所有激活、配置文件/会话、只读、撤销和模型披露门槛保持不变。显式 `search`、`search_terms`、`recall` 及模型工具操作保持既有字面语义。

对识别出的多词计划，`automatic_filter.required_query_indices` 列出全部必需查询索引，`minimum_matched_terms` 等于其长度，`filtered_returned_records` 统计删除数量，`refilled` 仍为 false。旧计划保持既有元数据。移除记录增加 `omitted_records`；`matched_records` 仍表示后端原始字面匹配快照数量。不改变规范存储 schema 或公共 REST 契约。

## 评测纪律

历史[文档 69 语料](../tests/fixtures/chinese_recall_eval.json)、[文档 102 语料](../tests/fixtures/longitudinal_memory_recall.json)及其已提交报告均未改变。独立作者在实现前，以本地提交 `cf335d1388ded1bfc1bad21c82b1dd23ddaeb9db` 冻结了[首套新语料](../tests/fixtures/automatic_recall_holdout.json)，含 38 条记录、60 个问题，SHA256 为 `00fd6c549e9846593b2b411b8aec096214b637f3de0901498297b1b64cf779ed`。

首个候选使该语料的返回项精确率从 52.00% 提升至 67.57%，但召回从 61.90% 降至 59.52%。两个问题丢失了相关项：一个语法结构不足的多词问句、一个并列属性问句。上述通用识别范围收窄参考了这些观察。因此首套语料属于开发验证集，**不再是未触碰的最终保留集**。没有改动相关性标签。独立代码审查另外发现并修复了疑问语气词被吞入属性，以及句内句末标点处理的问题。

第二套[独立确认语料](../tests/fixtures/automatic_recall_confirmation.json)含 36 条记录和 60 个问题。它在收窄实现之前以本地提交 `2a87bcef922983edbbdb1d1eaa7352ceda46752a` 冻结，SHA256 为 `eedd821fde419954fc08d63f651273d590f3e0b2288124708eac1a3993da5c15`。此后的生产代码没有根据它的结果进一步调整。最终测量、精确来源/语料哈希及逐问题变化记录在[机器可读比较报告](automatic-recall-slots-report.json)中。这些是合成检索测量，不代表总体准确度、模型回答质量、生产延迟或真实用户验收。

## 最终观察结果

生产基线为 `e85d207`；最终本地评测代码为 `93b4cf7`，PR 中发布的生产树内容与之相同。报告记录来源哈希，不把本地提交 ID 当作已发布版本。返回项精确率以相关返回记录数除以全部返回记录数；微召回以相关返回记录数除以标签中的相关问题-记录配对数。

| 冻结语料 | 基线精确率 → 候选 | 基线召回 → 候选 |
| --- | --- | --- |
| 历史 48 问 | 24/24（100%）→ 26/26（100%） | 24/37（64.86%）→ 26/37（70.27%） |
| 首套开发验证 60 问 | 26/50（52.00%）→ 27/42（64.29%） | 26/42（61.90%）→ 27/42（64.29%） |
| 未触碰确认 60 问 | 29/59（49.15%）→ 29/44（65.91%） | 29/45（64.44%）→ 29/45（64.44%） |
| 原生长程，28 条记录 | 16/16（100%）→ 18/18（100%） | 16/32（50.00%）→ 18/32（56.25%） |
| 原生长程，250/1,000 条记录 | 13/14（92.86%）→ 15/15（100%） | 13/28（46.43%）→ 15/28（53.57%） |

历史集、最终开发验证集和长程语料没有丢失相关配对。未触碰确认集有一处逐问退化（`c25`），被一处增益（`c09`）抵消，并非普遍无退化：带所属标记、询问负责人叫什么的问句在属性中残留了字面疑问片段，因而不返回结果。旧计划同时返回相关负责人和不相关预算。新增命中是带明确“由谁负责”结构的短姓名问句。最终候选在所有测试问题中均未新增不相关 ID，但继承的回退仍会返回不相关数据。确认集含不相关结果的问题从 14 个降至 7 个，负样本误召回从 3 个降至 1 个。这些结果支持有界精确率改善，不代表解决了语义召回。

最终原生长程全部硬不变量通过：完整封装、更正/遗忘/到期排除、当前状态一致性、全新进程重启、正常/中断重打包，以及保留来源迁移/恢复。原始报告保持不可变历史证据。新报告中的早期候选摘要保留其退化和精确哈希；重复的原生基线上下文通过原报告的已验证哈希引用。

## 复现

使用准备好的 Python 3.14 解释器和精确干净 Hermes pin `2281116525106e3c109993ccb5dc74d02bfc1427`。对每套短语料，在基线 main 与候选上运行 `scripts/evaluate_memory_recall.py --fixture PATH --repeats 5`，完整原生长程场景运行 `scripts/evaluate_longitudinal_memory.py --hermes PATH`。按 `scripts/compare_automatic_recall.py --results-dir PATH --additional-fixture automatic_recall_confirmation` 消费的命名保存结果。

短评测器在两个版本都将当前自动行为称为 `candidate_conservative`；其更老的 `baseline_1740a85` 策略不是本次比较基线。比较工具检查语料哈希及相同问题标签，报告丢失的相关配对和新增不相关结果，并保留完整原生长程证据。单元反例验证比较工具及必需槽位元数据。完整原生运行器独立验证当前更正/遗忘/到期、单次读取状态、完整封装、全新进程一致性、正常/中断的同配置文件重打包，以及保留来源抑制。这些仍是有界合成检查，不是历史恢复、物理擦除或原生长对话压缩认证。
