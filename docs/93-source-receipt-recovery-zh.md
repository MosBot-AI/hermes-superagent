# 93. 仅供审查的来源回执消费者恢复

[English](93-source-receipt-recovery.md) | 简体中文

## 状态与价值

[Issue #127](https://github.com/MosBot-AI/hermes-superagent/issues/127) 在已合并的 [PR #126](https://github.com/MosBot-AI/hermes-superagent/pull/126) 之后扩展[来源回执提案](92-native-checkpoint-sources-zh.md)。宿主事务已能一起提交来源归档与元数据回执，但若进程在宿主提交后、本地记账前停止，仅此仍不能保存消费者进度。

隔离产物现包含显式 `RecoveryJournal` 和提议宿主公开的 `source_request_identity(session_id, request)` 辅助函数。该函数验证有界请求，在不读写数据库的情况下计算与提交相同的回执标识。标识既不是来源验证，也不授予权限。日志在宿主准入前写入元数据意图，并能在重启后发现待处理尝试；它无需保留请求载荷或重放压缩，即可核对匹配的宿主回执。

本切片已作为仅供审查的实验实现并测试，但未提交上游、未安装、未启用、未发布。交付的 provider 仍为 API v1；兼容性固定版本仍是 Hermes `2281116525106e3c109993ccb5dc74d02bfc1427`。父项 #43/#45 保持未完成。不启用规范记忆写入、摄取、消费者游标推进、provider-v2 检查点、REST 接口、模型调用、外部送达或自动恢复循环。

## 协议与结果

1. 为一个现有原生数据库和 session 显式创建日志；此后默认仅打开现有日志，日志丢失不能静默变为空队列。
2. `stage(request)` 验证精确规范请求，在独立本地 SQLite 事务中提交 attempt ID、预期回执 ID 和来源数量。不复制来源、摘要或完整请求载荷。已有 attempt ID 必须精确匹配；保留行数达到 4,096 时拒绝新准入，不驱逐旧记录。
3. `submit(request)` 先提交该意图，再将同一个私有请求快照交给提议宿主提交。意图写入失败会阻止宿主准入。宿主发生错误时保留待处理意图并返回 `host_commit_unconfirmed`，即使宿主可能已经提交。
4. `pending(after=0, limit=100)` 按稳定序号列出尚未记账的尝试。页大小为 1–100，保留的序号不重新编号。分页是有界观察，不是跨页快照；并发完成可能使后续页不再包含某些行，下一轮遍历可发现新行。
5. `reconcile(attempt_id)` 只读取宿主。匹配回执允许幂等写入本地 `recorded` 标记，即便来源此后已经失效。不匹配会被拒绝；回执缺失时，未记账意图保持待处理。宿主无法访问或已被替换时返回 `host_unavailable`。恢复不会调用压缩、创建宿主数据库或生成新的 attempt key。

如果宿主回执缺失，重试要求显式重新提供**完全相同**的请求和原 attempt ID。日志有意不具备重建或重新生成来源/摘要明文的能力。来源变化或压缩租约丢失仍可能使重试失败。本切片不提供自动重试、放弃、回执垃圾回收或容量重置。日志丢失、手工恢复、克隆写入者与来源接管均不是受支持的恢复流程。

结果区分 `accounting`（`pending` 或历史 `recorded`）、`host_observation` 和 `source_available_at_observation`，并始终返回 `durable_memory_checkpoint: false`。历史已记账不证明宿主回执/来源行仍存在；每次对账都会重新读取宿主，即使该尝试已经记账。若先前已经记账而宿主回执现已缺失，则报告 `recorded`/`absent`，不报告可用。

## 事务与隐私边界

这**不是双数据库原子事务**。顺序是本地意图提交 → 原生归档/回执提交 → 本地历史记账提交。中断可能留下显式待处理意图；在所述信任与保留假设下，精确请求标识和保留的宿主回执使这个缺口可以对账。

宿主状态读取与本地记账提交之间没有跨库屏障，来源可在两者之间被删除。记账仅记录曾观察到匹配的历史宿主事务。可用性明确只是之前某一快照的观察，不是召回授权或持续保留保证。后续读取会观察到原生失效状态，消费者不会恢复已删除文本。规范记忆接受、删除抑制、来源读取授权及游标推进仍需未来独立的协议与测试。

日志是独立的本地元数据数据库，不是第二份会话归档或规范记忆库。其内容包括宿主规范路径/device/inode、session ID、attempt ID、回执哈希、来源数量、序号和已记账标记。标识与哈希是私有元数据，并非匿名或适合公开。载荷隐私限定于日志，不涵盖调用者内存、传入标识、原生历史、导出或文件系统备份；这不是安全擦除保证。

显式测试入口要求日志父目录归用户所有且权限为 0700，日志本身是权限 0600 的普通单链接文件。创建是排他的；符号链接、硬链接、错误绑定或不可用存储都失败关闭。宿主 device/inode 检查可发现普通文件替换，但不是针对恶意同用户代码、并发文件系统篡改、inode 重用或回滚的安全屏障。私有文件不认证操作者身份，原生准入和所有者授权仍由调用方负责。日志事务使用 SQLite `synchronous=FULL`；子进程崩溃证据不证明所有文件系统上的断电持久性。

## 复现与验证范围

按[产物复现说明](../experiments/native-checkpoint-sources/README-zh.md#安全复现)操作。校验和清单覆盖新增日志、测试及宿主标识辅助函数。现有隔离 CI job 在单独暂存精确宿主补丁的 checkout 上调用两个提案测试文件；生产 runtime 打包不包含该实验。

测试使用真实临时 SQLite 数据库与全新子进程，在宿主准入前、宿主归档事务内部、宿主提交后记账前、本地记账中及记账后注入 abrupt exit；同时覆盖宿主返回丢失、本地写入失败、相同 attempt 重复/并发提交、冲突、待处理分页/容量、错误/丢失/被替换存储，以及观察和记账之前、之后或两者之间的来源删除。所有测试均不使用真实模型或个人来源数据。实际执行数量与选定原生回归文件见 manifest；上游全套、生产 provider 与真机验收是独立门槛，本切片不作相应声明。
