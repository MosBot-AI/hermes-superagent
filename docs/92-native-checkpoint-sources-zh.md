# 92. 仅供评审的原生检查点来源回执

[English](92-native-checkpoint-sources.md) | 简体中文

## 状态与依赖

[Issue #125](https://github.com/MosBot-AI/hermes-superagent/issues/125) 接续 [43](43-native-checkpoint-boundary-zh.md) 的有界准备、[76](76-native-memory-contracts-zh.md) 的固定原生版本核验和 [91](91-native-source-resolution-zh.md) 的只读来源解析。[隔离制品](../experiments/native-checkpoint-sources/README-zh.md) 为 Hermes `2281116525106e3c109993ccb5dc74d02bfc1427` 提出宿主持有的事务接口。它仅供评审，尚未提交上游或启用。现有历史文档保留各自受测范围；此提案不会追溯性地将其证据变成持久检查点。

## 更窄的保证

来源读取成功本身不能为未来压缩建立围栏。提案先准备显式有界请求快照，然后在原生提交准入时重新验证绑定的当前会话、来源引用及 revision。兼容 JSON 的请求是可变字典，在提交时深复制并重新验证；每个已准入尝试的摘要固定。受支持的来源覆盖和元数据回执持久化共享现有归档/压缩事务。没有第二份会话档案：原始来源正文仅保留于原生已归档消息行，而回执保存元数据。

受支持的候选是具有无歧义来源身份的准确当前普通用户/助手正文，包括受支持的有序用户合并。未知待持久化来源、不支持的谱系或来源不匹配均关闭式失败。操作仅限显式所有者原地压缩，不支持会话轮换、worker 压缩或 app-server 严格检查点，也不会从会话标识符推断所有者权限。

永久来源更新/删除触发器会在除 `display_order` 外的任一来源列发生变化时使相关元数据回执失效，包括反应变化。同值无操作更新不会使回执失效。旧代码的普通原生/SQL 修改仍会触发这些持久触发器；因无关元数据变化而保守报告不可用是可接受的。只读状态在单个快照中检查，不创建缺失的 schema。有限容量拒绝进一步准入，而不静默淘汰回执历史。在提交准入前检查取消；延迟取消不会撤销已提交结果。进程中断或返回不确定后，应使用同一绑定会话和尝试进行核对。回执是历史事务证据，不是来源仍适合召回或后续记忆写入已成功的证明。

已持久化的 `_compressed_summary` 行不能作为合格来源。调用方仅为单条助手摘要提供 `role` 和 `content`；宿主在新的输出副本上设置 `_compressed_summary=True`，使规范请求在重试之间保持不变。

读取后的准入还将每条原始行中字符串字符数与字节值长度的总和限制为 262,144，完整扫描中的总和限制为 2,097,152。序列化谱系最多为 `1024 * 36 + 2` 个字符；规范请求 JSON 最多为 1,500,000 个字符。这些是读取后的准入限制，不是分配安全保证。

可信宿主存储边界保持明确。直接篡改 schema、手动数据库替换、备份回滚及恶意进程内代码不在保证范围内。不得将来源保留与删除语义宣传为通用安全擦除或通用文件系统持久性保证。

## 核验与剩余工作

制品包含测试/评审消费者及隔离合成测试。核验器在执行前要求准确的已暂存宿主补丁及源码哈希；原生回归通过 `scripts/run_tests.sh` 运行，而非直接调用 pytest。独立 CI 作业使用一次性的打补丁检出，绝不使用生产运行时包。实际选定执行结果见制品 manifest。测试实现、已配置 CI 作业和通过的合成检查，与已完成 CI 运行、上游接纳和部署验收是不同的状态。

生产兼容性固定版本、provider API v1 及运行时配置保持不变。自动采集、采集/保留同意、provider 集成、记忆写入、游标推进、通用 worker/轮换支持及完整 E2.8 验收仍是独立门禁。此切片不添加公共 REST 契约、后台消费者、模型调用、监听器、部署或发布。
