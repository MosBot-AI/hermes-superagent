## 1. 决策与非目标

在稳定、由本项目拥有的 **MemoryService** 后设置一个小型、可替换的 **MemoryBackend**。提供轻量本地后端，使用 SQLite 记录、事件和 FTS，并生成可读的 Markdown 投影。用户可以选择经过审查的替代方案，也可以自行编写适配器。治理、当前授权、来源归属、删除抑制、token 预算及任务和行动权限均不由 provider 生成的文本决定。

默认设计不需要向量服务、外部记忆 API、额外代理循环、并行的转录数据库或自定义手机应用。安装基础包不会改变原生记忆配置。选择在线嵌入、提取、重排序或存储服务，是另一项需要明确决定的数据与费用选择；本地存储不代表所有模型计算都离线进行。

扩展分为两个层次：

| 扩展 | 用途 | 边界 |
|---|---|---|
| 项目 `MemoryBackend` | 通过同一个服务契约存储、检索带版本的个人记录 | 拟议接口；不是现有 Hermes 注册表或 `ctx.memory` API |
| 可选 Hermes `MemoryProvider` 桥接层 | 将服务接入真正的原生预取、同步和检查点生命周期 | 必须有意选择它来占用 Hermes 唯一的外部 provider 槽位；不会自动与另一个外部 provider 并列添加 |

项目可以保留用户现有的 Hermes provider，并提供自身显式、经过授权的领域记忆工具，而不安装该桥接层。在此模式下，**不承诺**自动原生预取和检查点集成。兼容的现有 provider 可以接入同一个服务，但必须遵循其经过测试的契约。不得冒充 `builtin`、暗中串联 provider、使用宿主私有字段，或自动覆盖 `memory.provider` 来规避槽位限制。

## 2. 已核实的原生与 DSH 基础

Hermes 基线为 `90d6b98fd86d20981ee06ddd5b7d93e4320f26a4`；DSH 参考版本为 `8c32a9dc5d72c033816c6a8110b37f40cf94fba4`。源码检查不等同于已部署行为或性能基准。

| 已核实事实 | 对设计的影响 |
|---|---|
| 内置 MEMORY.md / USER.md 默认限制为 2,200 / 1,375 个字符，属于可配置的有界存储 [M1] | 其中只保留高价值偏好和索引提示，而非完整事实图谱或活动历史 |
| 缓存的提示快照会在压缩使其失效后重新加载记忆 [M2] | 不得声称记忆每个 token 都刷新，也不得声称它直到 `/new` 才会刷新、此前永远冻结 |
| 原生原地压缩对旧行做软归档，并以事务方式写入活动摘要和尾部；归档行仍可搜索 [M3] | 原始对话保留和压缩由 Hermes 负责；摘要仍有信息损失，需要证据引用 |
| `session_search` 提供 FTS 发现、读取、滚动、有界内容及来源与排序过滤；显式 `profile=` 可打开另一本地配置档案 [M4] | 原生历史是召回来源，不是自动插件 ACL 执行机制，也不是每个调用方均可无限使用的证据 |
| MemoryManager 拒绝第二个非 `builtin` 的外部 provider [M5] | 只能有一个活动的外部原生 provider；项目适配器不会创建多个原生槽位 |
| 原生 `MemoryProvider` 具备初始化、预取、同步、工具、会话、压缩前钩子和配置档案作用域要求 [M6] | 适配这些真实方法；本文不承诺存在通用的原生 CRUD、事件或导出 API |
| 默认检查点 API 为尽力而为的 v1；可选的必需检查点要求支持 v2 的成功结果 [M7] | 只有获得持久性证据并通过失败测试后，才能宣称支持严格检查点，不能只设置一个标志 |
| Cron 创建代理时使用 `skip_memory=False`、`skip_background_review=True`，provider 上下文为 `cron` [M8] | 后台任务可以加载记忆；适配器必须自行执行 cron 写入策略；宿主不存在通用只读保证 |
| DSH 持久化任务、证据和效果对象，并提供有界的链接资源；其 `core/memory.ts` 是测试用 Map 仓库 [M9] | 借鉴引用上下文与恢复的思路，不宣称 DSH 已提供生产级个人语义记忆 |

默认原生记忆复盘受配置的提示间隔及回合后条件限制，并不保证每条消息之后都提取 [M10]。外部 provider 的同步是异步的，可能失败。一句成功的口头确认不等于已提交的写入回执。本项目未独立审计 DSH 底层的会话压缩依赖。

## 3. 记忆类型与事实权威来源

| 类型 | 内容 | 权威与检索 |
|---|---|---|
| 语义记忆 | 偏好、人物与关系、环境事实和约束 | 带版本的事实记录，包含来源、置信度、有效性及显式或推断状态 |
| 情景记忆 | 对一次讨论或已完成活动的有界描述 | 带引用的情景摘要，包含原生会话或事件范围、覆盖情况和未解决问题；不替代转录 |
| 任务连续性 | 目标、验收条件、约束、当前步骤、决策与阻塞 | 任务服务或原生运行仍是权威；记忆存放引用及带修订标记的工作快照 |
| 程序性记忆 | 可复用、经过测试的工作流或技巧 | 原生 skill 文件和注册表仍是权威；拟议 skill 变更需要经过支持的审查与安装流程 |
| 工作上下文 | 当前回合及近期相关证据 | 为单次调用组装的临时有界上下文；不会自动提升为持久事实 |

记忆不能仅因摘要如此描述，就把授权、批准、任务完成状态或外部效果成功当作事实保存。召回的权限陈述可以帮助定位真实策略或回执，不能替代它们。工作代理声称成功，只是等待任务验收规则核验的证据。

记录区分 `observed_at`、`recorded_at`、`valid_from`、`valid_until`，并在相关时保留原时区和原始措辞。新陈述不必取代不同作用域下的旧事实。冲突事实可以并存并通过冲突关系关联；不得跨人物、项目或时间范围静默采用最后写入获胜规则。

## 4. 默认本地存储与 Markdown

拟议本地后端位于已验证配置档案的 `plugin-data/hermes-personal-agent/memory/` 下。它使用项目拥有的 SQLite 数据库，包含：

- 记录身份、修订和状态、类型化载荷、来源引用及有效性和作用域元数据。
- 最小变更事件日志、幂等回执、墓碑及覆盖和检查点水位。
- 可重建的 FTS 索引和投影作业状态；可选嵌入索引仍是派生数据。
- 自动生成的用户档案、项目或主题笔记及情景摘要 Markdown 视图，包含稳定记录 ID、修订和来源链接。

**在此默认后端中，SQLite 是权威；Markdown 是可读投影和导出，而非第二个并发事实来源。** 一次提交原子写入规范变更、事件或回执以及投影作业。随后通过原子替换渲染 Markdown。若在数据库提交后、文件渲染前崩溃，会留下可重建的脏投影，而不会撤销事实。生成视图显示其修订或水位，过期时不得静默将其视为当前状态。

每个派生产物作业都携带其命名空间检索纪元，以及覆盖的记录修订或水位。发布必须与纠正和遗忘共享确定性的写入隔离机制：在持有该隔离控制直至本地索引提交或原子文件替换完成的期间，重新核验当前修订和墓碑。遗忘操作按相同的发布顺序提交抑制并执行清除，因此先前计算完成的作业不能在之后重新发布已删除文本。仅在作业开始时检查，或将复活的文件标记为过时、留待稍后修复，均不充分。取消操作应丢弃待发布输出及私有临时文件。远程索引发布需要按代次条件写入或等效且经证明的隔离机制；否则必须跟踪、排空并对账较早的在途写入，之后才能报告远程清除完成。在远程结果仍待确认期间，本地抑制立即生效。

手工修改的 Markdown 只能作为针对所记录基础修订的显式变更提议导入。冲突编辑需要审查；任意文件编辑不会成为所有者指令、授权变更或即时数据库覆盖。不得监视宿主上所有 Markdown 文件、导入其他配置档案，或递归索引秘密目录。导入文件必须受允许根目录、大小和类型限制，并标注来源。

原生 MEMORY.md / USER.md 是宿主拥有的独立精选存储。在获得授权时，项目可以通过原生记忆工具提出有界摘要或索引补丁，遵守写入审批和容量限制。项目不会替换这些文件、绕过原生暂存，也不会声称其 Markdown 视图会自动加载到 Hermes 提示中。可选原生摘要失败不会抹除已提交的项目记录。

采用经过测试的私有文件保护及明确的存储平台支持，而非未经核验地声称已加密或具备同 UID 隔离。SQLite 本身不是加密机制。不得在原生兼容性规则禁止的文件系统上强制使用 WAL；应选择并测试受支持的日志模式。备份与保留范围应包括日志、旁路文件和 Markdown 产物。

## 5. 带版本的记录、事件和回执

以下记录仅作示例，不是已实现的 schema：

```json
{
  "schema_version":"personal.memory.record.v1",
  "record_id":"mem_example",
  "revision":3,
  "namespace_id":"namespace_example",
  "kind":"semantic",
  "status":"confirmed",
  "subject_ref":"person_owner",
  "scope":{"project_refs":["project_example"],"data_class":"ordinary_preference"},
  "value":{"predicate":"weekly_report_language","value":"zh-CN"},
  "sources":[{"source_ref":"source_example","relation":"direct_user_statement"}],
  "valid_from":"2026-11-06T00:00:00Z",
  "valid_until":null,
  "supersedes":[],
  "index_revision":3
}
```

`namespace_id` 是服务端绑定的存储与权限命名空间，不是持有者凭据，也不是推断出的所有者 ID。可信本地配置档案与已验证所有者命名空间属于不同模式。模型提供的声明字段必须与调用方上下文和来源权限核对，绝不作为身份验证依据直接接受。

来源引用解析为原生消息或事件、已授权的连接器对象、显式导入或操作者编辑。保留签发方或账户、作者分类、原始事件 ID、内容哈希，以及必要时允许保留的最小摘录。原生行 ID 可能随压缩携带或克隆行而改变 [M3]；存在稳定宿主或来源 ID 时应绑定它们，并保存足够的沿袭关系与哈希证据以安全解析。无法解析的引用标记为 `source_unavailable`，不能编造引文。

事件使用稳定的 `event_id`、命名空间、操作 ID、记录 ID、前后修订、事件类型、来源引用、策略纪元和提交序列。候选状态为 `candidate → confirmed / inferred → superseded / retracted / expired`；遗忘会增加不同于过期的抑制或墓碑状态。变更按提交序列排序，而非客户端时钟。

同一命名空间、操作和键下，载荷哈希相同的精确变更重试返回原始回执。同一键下内容改变则冲突。比较并设置拒绝过时记录修订。一个来源可以产生多个候选；提取键还需包含来源修订、提取器或配置版本和候选身份。重新提取不会产生重复项或覆盖人工纠正。

事件溯源意味着可从依法保留的事件和载荷集合重现当前状态，而非永久保留已删除的私人文本。必要时将载荷与最小事件元数据分开存储；按删除策略清除或删改内容及派生数据。校验和与标识符也可能属于个人数据，同样受保留规则约束。清除载荷后，重放保留其墓碑，而不重建已遗忘内容。

## 6. 可插拔后端契约

以下方法和描述符是本项目的提议。它们不是 Hermes 原生 API、HTTP 规范或第三方 Python 的沙箱。

| 方法 | 必需契约 |
|---|---|
| `describe()` | 静态版本与能力元数据；无网络、秘密或个人内容 |
| `open(bound_context, config)` | 绑定一个已验证命名空间以及经审查的端点和凭据引用；拒绝不支持的能力与配置组合 |
| `apply(mutation, expected_revision, idempotency_key)` | 持久化规范变更，或返回类型化的待处理或未知结果；返回记录或事件修订及提交回执 |
| `get(record_ids, read_scope, snapshot)` | 返回有界当前记录，包含修订、删除与过期检查以及来源引用；不得暗中扩大范围 |
| `search(query, filters, budget, snapshot)` | 返回有界候选记录或片段，包含分数语义和索引水位；明确标记过期、部分或不支持 |
| `changes(after_sequence, limit)` | 已授权、有界的规范变更，包含保留下界和下一游标；不是原始转录流 |
| `checkpoint(coverage, idempotency_key)` | 记录已覆盖的事件或来源范围和持久化证据引用；成功意味着已达到所承诺的持久化边界 |
| `export_snapshot(scope, watermark)` | 带版本、可移植的清单、记录、来源、墓碑和回执；不含凭据或当前授权 |
| `import_snapshot(manifest, migration_id)` | 先验证，再幂等暂存，保留身份与来源沿袭，并要求显式激活 |
| `health(local_only)` / `close(deadline)` | 脱敏的本地就绪状态或明确允许的远程探测；有界排空，提供未保存及待处理数量 |

描述符字段包括 API 与 schema 版本、适配器版本、持久写入、CAS、幂等和快照支持、支持的记忆类型、精确删除语义、事件保留、查询语言或分词器、排序单位、大小上限、导出格式、检查点支持、部署模式及数据接收方。`installed`、`configured`、`healthy`、`index_current` 和 `certified_for_mode` 是不同状态。

可选方法应返回 `unsupported`，而非空的成功结果。未知主版本或必需字段按失败关闭原则拒绝；兼容的次版本增量通过协商处理。命名空间和端点选择来自可信配置，而非模型提供的路径、URL、SQL 或插件模块字符串。应提供小型适配器 SDK、schema 测试样例和一致性测试套件，而非要求用户复制内部服务类。

针对编写适配器，提议 Python entry-point 组 `hermes_personal_agent.memory_backends`，这是新的项目 SDK 机制，**不是** Hermes 定义的组。入口指向 `create_backend(host, config)`，返回实现协商接口、尚未打开的实例。`host` 只提供有作用域的元数据、有界日志和时钟钩子，以及经审查的资源或秘密解析器；不会授予任意所有者身份或全局数据库句柄。内置本地适配器使用相同的一致性测试套件。枚举 entry-point 元数据时不导入模块，拒绝重复或保留适配器 ID，然后只加载明确选中、经审查的软件包。导入自定义代码本身会执行代码，且不受沙箱隔离。软件包与依赖准入遵循安装所有者受支持的 Hermes 环境工作流，而不是运行时的 `pip install` 捷径。可选原生桥接层是独立、真实的 `hermes_agent.memory_providers` 入口或目录 provider [M11]；不得混淆这两种注册机制。

用户编写的后端可以采用不同存储。要替换规范存储，必须实现持久化且带修订的变更、精确重放回执、当前读取与删除语义及可移植导出，否则明确禁用不支持的模式。仅提供搜索的远程服务是**派生索引适配器**，不是规范后端的替代品。核心将当前策略、本地抑制和操作跟踪保存在该搜索索引之外。

使用远程规范存储时，本地操作日志和远程提交无法共享一个 SQLite 事务。应使用待处理操作或 outbox、稳定远程幂等键、回执查询和对账。验证前报告 `pending` 或 `unknown`，不得仅凭 HTTP 接受就宣称“已保存”。不得将尚未确认的新修订当作已提交读取。如果远程后端无法证明当前删除和修订约束成立，严格模式下不得提供缓存结果。

## 7. 配置与安全选择

以下为未来配置示例，**不是当前 plugin.yaml 选项**：

```json
{
  "schema_version":"personal.memory.config.v1",
  "enabled":false,
  "mode":"trusted_profile",
  "backend":{"adapter_id":"local_markdown_sqlite","adapter_api":"1","credential_ref":null},
  "native_bridge":{"enabled":false},
  "extraction":{"automatic":false,"default_state":"candidate","model_ref":null},
  "retrieval":{"token_budget":2400,"max_records":12,"query_timeout_ms":300},
  "network":{"allowed_destinations":[],"automatic_fallback":false},
  "checkpoint":{"required":false},
  "retention":{"raw_transcript_copy":false,"debug_content":false}
}
```

这些数字是建议用于基准测试的初始限制，并非已测性能。本地查询截止时间并不保证能强行停止任意原生或插件代码；应限制输入、结果大小和并发，阻断迟到结果，并报告未完成工作。

选择后端是操作者或用户的配置动作，需要预览受影响配置档案、记录、接收方、费用、凭据处理和重启要求。它不隐含首次运行扫描或云端上传。迁移或激活成功前保留当前活动后端。禁止静默切换 provider、回退到其他配置档案或自动下载模型权重。

发现阶段不导入任意代码。通过受支持的 Hermes 安装和依赖流程接纳经审查的软件包，遵守项目插件主动启用和声明依赖要求 [M11]。除非有经过验证的隔离边界，自定义代码以宿主权限运行。安装批准与数据共享批准彼此独立；只读标签不能证明网络或文件系统受到隔离。

## 8. 原生 MemoryProvider 桥接层

明确选中时，可选桥接层实现真实的 `MemoryProvider` ABC，并与显式工具使用同一个服务和后端，避免重复写入者：

| 原生方法或钩子 | 桥接行为 |
|---|---|
| `is_available()` | 仅检查本地配置与依赖就绪情况；不进行网络探测或付费调用 |
| `initialize(session_id, **kwargs)` | 将新的 provider 实例绑定到提供的 Hermes 主目录与运行时上下文；绝不重新绑定进程全局个人状态 |
| `system_prompt_block()` | 小型静态用法或索引提示，而非不断膨胀的历史转储 |
| `prefetch(query, session_id=...)` | 为受支持信任模式提供已授权、有界上下文包；普通查询失败时安全返回空结果或降级结果 |
| `sync_turn(..., messages=..., turn_author=...)` | 从符合条件的已完成回合中，将绑定来源的候选入队；避免每次调用重新摄取完整消息列表 |
| `on_turn_start(...)` | 观察当前作者和会话元数据，但不将其提升为所有者权限 |
| `on_session_switch(...)` / `on_session_end(...)` | 重新绑定会话覆盖和游标，对持久工作进行对账，并遵守真实的重置、分支和回退边界 |
| `on_pre_compress(...)` | 按协商的 v1/v2 语义提取候选或生成证据检查点；绝不将排队请求说成持久检查点 |
| `get_tool_schemas()` / `handle_tool_call(...)` | 通过 MemoryService 和当前策略提供带命名空间的有界命令；不得遮蔽核心名称 |
| `shutdown()` | 有界排空，持久化重试状态，并明确报告已放弃或待处理结果 |

原生预取接收文本与会话元数据，而非普遍经过身份验证的所有者或授权。`turn_author`、`user_id`、`caller_gsk`、配置档案名称和 `agent_context` 都不能独立证明权限。在可信配置档案模式下，只能在明确接受的单用户安装和会话暴露边界内启用自动召回。在多用户或远程所有者模式下，缺少可信的当前身份或作用域意味着不能自动召回受保护内容。显式工具受自身经验证的原生适配器约束，不是自动绕过限制的办法。

管理器会抑制相关子代理钩子，但 provider 仍必须遵守 `cron` 和其他非主要上下文的契约 [M6, M8]。此桥接层默认禁止 cron 或工作代理自动修改规范事实或 skill。获准的定期分析可通过另行批准的领域路径，输出与原始来源绑定的候选。工作代理摘要不能变成“用户说过”或新的长期偏好。

非主要上下文的自动事实写入限制，不会使必需的连续性检查点变成空操作。原生 v2 压缩前钩子不受子代理回合钩子门控的抑制。对于每个启用的 cron 或子代理模式，要么允许严格限定作用域的持久连续性或证据检查点，且不提升新的语义事实，要么明确拒绝严格压缩。只有其将被回收的来源覆盖已得到持久化解决时，检查点才算成功；未持久化的来源或排队中的保存请求不能算作已覆盖。

内置记忆存储可以与唯一外部桥接层并存。反过来，现有第三方 provider 可以继续活动，而项目工具使用本地后端；必须说明各层分别拥有哪些记录。注册另一个原生 provider、冒充 `builtin` 或隐藏多 provider 路由器，都不是兼容方案。

## 9. 连续对话、压缩与定期运行

每次调用均从持久状态重建有界工作视图，而非寄希望于当前提示仍然包含一切。拟议上下文包包含相关的已确认偏好、当前任务引用和修订、未解决决策、近期适用情景及精简来源指针。简短明确的追问复用当前任务引用；对于不含实质内容的问候，无须广泛搜索。

原生 Hermes 仍负责转录与压缩。不得仅为安装记忆而添加竞争性的上下文引擎。桥接层跨压缩、分支和重置跟踪来源或事件覆盖及任务快照修订。压缩摘要只是派生辅助信息，不是直接用户证据；绝不可递归地将同一摘要提取为新事实。分支不会静默继承全部权限或改写父分支事实。

压缩前，在受支持时保存一个**工作检查点**：任务 ID 和修订、目标与约束、决策、以引用表示的待批准事项和效果、未解决问题、已完成提取水位、证据范围和剩余候选。检查点不会复制原始对话，也不会恢复过期批准权限。缺少原生持久来源映射必须明确列为能力缺口。

严格的 `compression.checkpoint_required` 是可选项，默认关闭，需要经过测试的 API v2 桥接层 [M7]。桥接层必须在报告成功前提交其声明的检查点；严格模式启用时，异常或超时会阻止相应压缩。这可能在存储不可用时使上下文已满的会话停顿，是需要明确接受的持久性与可用性取舍。不得在不支持的原生模式中启用它，包括该固定版本中不兼容的 `codex_app_server` 路径。非严格模式失败时，应报告保存能力降级并保留来源引用；不能宣称检查点成功。

定期工作从持久目标、获准命名空间或任务范围、当前策略及上次成功覆盖水位开始。它查询变更记录和当前任务事实，而非整体导入主对话。调度由原生 cron 负责。作业创建、模型费用、接收方访问和发送权限仍彼此独立。`skip_background_review=True` 表示不能保证定期运行会执行通常的回合后学习复盘。

重启后，从持久回执和水位对待确认提交及提取作业进行对账，再按需重建索引与投影。不得重放结果不确定的外部行动、使过期授权重新生效，或承诺 provider 异步队列在崩溃后仍然存在。“没有找到”“索引落后”“来源缺失”和“后端不可用”是不同结果。

## 10. 检索与 Token 预算

决定哪些内容可以进入上下文的是 MemoryService，而非 provider 文本：

1. 在任何外部查询或私人载荷取回之前，确定当前可信命名空间、获准记录类型或数据类别及任务或项目范围。
2. 优先解析显式任务、记录或来源引用，然后查询精确结构化字段、时间范围和有作用域的 FTS。可选向量或重排序属于之后配置的路径。
3. 检查有效性、墓碑、修订或索引水位及冲突；加载内容前依据权威元数据验证候选。返回上下文包前重新核验当前访问权限。
4. 按任务相关性、明确程度、时效或有效性及来源质量排序。保留有意义的矛盾，而非用一个高分将其隐藏。
5. 对记录、情景和原生摘要的重叠去重，按协商预算打包，并为省略的细节返回可展开引用。

Token 核算包括包装文本、引用和元数据。可用时使用所选模型的分词器；否则采用保守的字节或字符上限并标记为估算。不得将英文单词与 token 的比例套用于中文，也不能在缺少兼容分词器时承诺精确计数。为用户输入、工具结果和输出预留空间；拟议的 2,400-token 记忆预算可以缩小，但不能静默增大到耗尽上下文。

返回 `used_tokens` 或估算用量、预算、已纳入的记录或修订及来源引用、省略数量与原因、索引水位、快照或游标及降级标志。这些诊断信息不得包含敏感内容。超时可以返回较小且已证明安全的上下文包，但不能绕过作用域或提供已撤销的缓存文本。经授权的空包优于未经核验的记忆。

不得通过向远程记忆后端交付不受约束的 `session_search(profile=...)` 调用来绕过 MemoryService。原生跨配置档案搜索仍在宿主独立权限下可用，因此本插件不能声称保障每个原生工具的安全。它自己的历史适配器必须明确限制选定配置档案、会话和内容类别 [M4]。

## 11. 中文检索与质量

默认后端从普通结构化过滤和 SQLite FTS 开始。必须检测实际分词器能力。中文姓名及一字或两字词需要专门测试：原生 Hermes 支持 trigram 和可选 CJK bigram，但该扩展不会自动安装到本插件数据库中 [M12]。

采用经过测试的 CJK 分词或 bigram 索引，或者为短词提供有界字面量回退；不得静默执行无界全表扫描。保留原文，并将规范化查询词元映射回原文。繁简转换、拼音、别名和实体链接是可选扩展，绝不用于静默合并身份。相似人名需要证据和作用域，而非嵌入距离。

评估精确日期和数字、中英混合项目名、同音词、短姓名、否定、时间变化和同名人物。在固定、经同意使用或合成的语料上，对比仅 FTS 与可选嵌入或重排序器。分别衡量检索召回率、回答证据准确性、过时事实暴露、错误人物合并和错误记忆写入；流畅的回答不是召回基准。

## 12. 写入、纠正与遗忘流程

模型提出候选；确定性服务验证检查来源与作者、信任模式、敏感性、作用域、冲突、限制和既有纠正。明确且获准的“记住”指令可以提交已确认事实；推断或第三方事实仍应明确标注，不能成为权限依据。自动提取需要单独主动启用，并受每回合或每日作业量及费用限制。没有充分证据时，不得从一次任务选择推断永久偏好。

纠正创建新修订并关联被取代事实。重新提取旧来源不能使旧事实复活：应保存来源覆盖及纠正或墓碑优先级。置信度是注明来源的 provider 或模型估算，不是身份验证。候选审查展示精确拟议变更及来源引用，无须用户阅读整个历史。

遗忘首先提交本地抑制或墓碑，并推进命名空间检索纪元。新读取、缓存上下文包、排队候选和索引查询必须在定义的读取准入顺序下立即遵守它。已经准入或送达的结果无法撤回。随后移除或删改规范载荷、FTS 或向量条目、生成的 Markdown、获准来源摘录及远程副本，并跟踪各目的地回执。对每个排队或在途的派生数据写入者应用第 4 节的发布隔离机制；只要较早写入仍能恢复内容，就不得报告某个目的地已清除。离线远程存储在本地仍被抑制，并报告 `purge_pending`；不得静默声称“已从所有地方删除”。

删除原生转录和删除原始外部服务上的数据，是另行授权的动作。解释备份保留、provider 保留、日志和实际安全删除限制。导出、导入和恢复必须携带墓碑及抑制优先级，防止旧备份重新填入已遗忘事实。仅按独立保留策略保留必要的非内容审计元数据；不得在不可变事件日志中保留完整已删除载荷。

## 13. 身份、不可信内容与秘密

可信配置档案模式继承 [28](28-profile-first-local-conversations-zh.md) 的单用户安装契约；它不会创建已验证的远程所有者身份。宿主授权的 `LOCAL` 控制器可以位于远程，同进程或同 UID 代码也不受隔离。模型工具在 [29](29-session-scoped-task-tools-zh.md) 规定的场景中需要显式会话激活。原生记忆配置或复制的配置档案目录都不会静默激活项目记忆。

已验证所有者模式还需要真实的宿主、签发方、租户和操作者绑定、当前策略或授权，以及资源接管。每个缓存、操作键、索引、provider 租户和后台上下文都必须受绑定命名空间或权限作用域约束。配置档案名称、路径、复制的安装 ID 和记录 ID 都是定位符，不是身份证明。跨配置档案传输是显式迁移或共享，不是搜索便利功能。可选 Primary Bot 指定只是优先协调目标，不代表记忆所有权。

检索内容是不可信证据：进行边界隔离和标注，保留归属，绝不执行其中嵌入的指令、URL、脚本或声称的权限。来源 ID 和结构化允许列表可以限制检索，但不会使第三方陈述变成事实。提示注入检测是纵深防御，不是授权。不得将模型摘要提升为系统级指令或覆盖原生 SOUL/AGENTS 策略。

通过经审查的原生秘密引用解析凭据，绝不将其放入记忆正文、配置导出、模型上下文或日志。分别披露外部存储、嵌入、提取和重排序接收方；发送查询本身也可能泄露私人信息。执行端点、源、TLS 及重定向和 SSRF 规则。本地后端配合云端提取仍会传输数据。不能绝对保证秘密脱敏；传输前最小化内容，并测试已知敏感模式。

## 14. 迁移、替换与故障恢复

替换后端是需要明确操作和预览的迁移，而不是改一个设置后期待两个存储自行一致：

1. 核验源和目标能力、版本、接收方、费用及所需权限。生成试运行清单，列出选定命名空间、数量、类型、引用及不支持字段。
2. 暂停新的记忆变更与提取，并隔离源写入者。完成待处理或未知提交，或对其进行对账。捕获一致水位，以及规范记录、保留事件、墓碑、纠正关系和回执。沿用命名空间发布隔离机制，并在两端使旧代次的投影和索引作业失效。
3. 导出可移植 JSON、可读 Markdown 及带哈希的附件或引用清单。排除凭据、当前授权、身份验证句柄、活动 provider 会话，以及未经另行选择和允许的原始转录。
4. 按迁移 ID 幂等导入未激活目标。保留稳定记录、来源和事件身份及来源沿袭；校验数量、修订、删除优先级和未解析引用。重建派生索引，绝不将不兼容模型间复制的嵌入向量当作等价数据。
5. 不启用用户流量，先执行有作用域的抽样查询以及策略、删除和恢复检查。在当前纪元下获得显式激活，单次切换指针，并停用源写入者。绝不自动保留两个权威写入者。
6. 保留有界回滚计划，并决定源数据保留方式。回滚必须纳入切换后的变更和墓碑，否则停下来对账；旧快照不能抹除之后的纠正或删除。

初期实现采用先停后启、单一权威的迁移，而非双活复制。源不可用或无法隔离时，按规定保持阻塞或只读；不得自动通过克隆接管。恢复的存储在提供私人数据前，必须具备已验证的当前权限和抑制账本。复制的数据库不能证明自身仍然最新。

本地投影或索引失败时，规范操作可能仍然已提交，而这些派生数据应标为过期并重建。规范存储失败时，拒绝新变更，而非回退到易失内存并给出虚假保存回执。采用有界重试、稳定操作身份及可见的待处理或未知状态。停用会停止新项目准入；它不会删除原生记忆、抹除已经传出的数据或卸载其他 provider。

## 15. 成本、延迟与可观测性

默认本地 CRUD、FTS 和投影工作不使用付费记忆 API。提取、摘要、嵌入、重排序、外部存储和原生 provider 同步可能消耗模型或 API 资源。跟踪单次操作及每日预算、模型或价格和配置修订、估算或报告及结算用量和未知费用；不得把 provider 缺失的用量字段视为零。

优先保障面向用户的检索。按来源水位合并后台提取，限制并发，批量处理有界更新并跳过未变化来源。不得反复发送整个对话或重新嵌入未变化记录。保留纠正与删除的 FIFO 依赖；后台工作不能覆盖较新的用户决定。原生生命周期回调不得因缓慢的远程提取阻塞对话。

在声明的语料、硬件和模型条件下，测量冷启动与热启动检索、上下文组装、提交、投影滞后和索引滞后的 p50/p95。示例中的 300 ms 本地查询超时是拟议运行限制，不是实测结果或通用 SLA。日志默认记录脱敏 ID、阶段耗时、数量、预算和降级原因，而非查询、事实文本、原始音频或转录及凭据。

## 16. 错误与验收矩阵

错误使用 `code`、`stage`、`operation_id`、`retryable`、可选 `retry_after_ms`、`outcome_known` 和有界脱敏消息。稳定错误码包括 `memory_disabled`、`scope_unavailable`、`permission_denied`、`capability_unavailable`、`revision_conflict`、`idempotency_conflict`、`budget_exhausted`、`index_stale`、`source_unavailable`、`checkpoint_unavailable`、`commit_unknown`、`purge_pending`、`migration_blocked` 和 `backend_unavailable`。原始 provider 异常不是用户可见数据。

| 场景 | 所需证据 |
|---|---|
| 默认安装、已有外部 provider | 不创建记忆存储、不摄取、不改变选择、不联网或启动后台作业；外部槽位不变 |
| 本地后端、进程重启 | 已提交记录和回执仍存在；Markdown 和 FTS 可从规范状态重建 |
| 提交后、投影前崩溃 | 原回执仍然有效；检测并修复过时文件，而非将其作为更新状态导入 |
| 重复来源或事件及变更重试 | 精确去重、变更载荷冲突，不产生重复候选或丢失纠正 |
| 并发纠正、删除和提取 | CAS 与墓碑顺序防止旧内容复活；在旧投影或索引作业读取载荷后将其暂停，完成遗忘，再恢复作业，且不得恢复 Markdown、FTS 或向量内容 |
| 错误配置档案、所有者、租户或复制 ID | 当前作用域验证前，不检索私人内容或查询 provider |
| 恶意来源或摘要 | 指令仍被视为证据；召回文本不能改变授权、任务完成状态或 SOUL |
| 长对话和反复压缩 | 上下文有界、来源沿袭可解析，不出现递归将摘要当作事实的漂移 |
| 必需检查点缺失或失败 | 在受支持边界如实阻塞，包括 cron 或子代理连续性；空操作、排队或部分写入及未解决的来源覆盖都不能报告 v2 成功 |
| Cron 或工作代理召回与候选生成 | 上下文特定权限和预算；非主要上下文不能自动规范写入 |
| 远程 ACK 丢失、最终一致索引或后端中断 | 对待处理或未知结果进行对账，不盲目重复变更或进行不安全缓存回退 |
| 跨缓存、索引、Markdown、provider 和备份的遗忘 | 即时本地抑制、跟踪远程清除、恢复墓碑 |
| Provider 切换和切换失败 | 试运行、未激活导入、单一写入者、稳定 ID 和安全回滚；不复制凭据或授权 |
| 中文短词、混合文字和冲突姓名 | 有界查询成本、实测召回率，不进行未授权人物合并 |
| Token、延迟或费用耗尽 | 返回较小安全包或明确不可用结果，不自动升级为云端处理 |
| 宿主或适配器升级和隔离模式 | 精确 ABI、配置和生命周期测试；不支持的 IPC、依赖或权限模式仍禁用 |

先运行合成语料与假后端测试，再进行经过批准的真实数据、provider 或设备探测。源码审查、文档检查或无关本地任务测试，都不能完成这些发布门槛。提供示例适配器，并让用户编写的适配器运行同一套一致性测试；通过单元测试样例并不证明能隔离恶意代码，也不证明覆盖每条 Hermes 入口路径。

## 17. 工作包与启用顺序

| ID | 里程碑、状态与依赖 | 交付物 |
|---|---|---|
| E0.9 核验 Memory Provider 契约 | M0；Backlog；E0.1/E0.2/E0.5 | 公共加载、生命周期、单槽位、配置档案、cron、工作代理、压缩检查点和来源引用矩阵；真实隔离缺口 |
| E2.6 定义可插拔记忆契约 | M1；In Progress（本地先导）；E0.9、E1.5 中的本地审计、数据分类和秘密引用契约，以及适用的本地 E2.1/E2.2 契约 | 带版本的后端和服务、记录、事件、回执及删除语义、SDK 测试样例和信任模式门槛 |
| E2.7 构建本地记忆后端 | M2；In Progress（本地先导）；E2.6、本地 E2.1/E2.2 及适用的 E8.1/E8.2 测试框架 | SQLite 规范记录、事件和 FTS、Markdown 投影、纠正与遗忘、有界检索和显式本地命令 |
| E2.8 集成原生记忆生命周期 | M2；Backlog；E0.9/E2.6/E2.7 及适用的 E6.8/E6.9 入口契约 | 可选单槽位桥接、经同意的候选与召回、定期或压缩检查点、来源覆盖和预算 |
| E2.9 验证记忆迁移与召回 | M3；Backlog；E2.7/E2.8、E8.1/E8.2/E8.3 测试框架 | 适配器一致性、导出、切换、恢复和删除故障测试，以及中文和长期召回评估 |

既有 E2.1/E2.2 schema 与检索、E2.3 纠正、遗忘和导出、E2.4 消歧与关联、E2.5 可选 provider 评估仍保留在当前 Epic 检查表中；扩展它们，而非创建重复事项。记忆不会阻塞已经实现的本地任务循环。已验证远程所有者模式还需要适用的 E1.1–E1.4 和资源接管门槛；HTTP、Primary Bot 和语音依赖只适用于所选对应模式。原生 provider 桥接层是可选项，不是本地显式记忆工具的前提，也不意味着获准替换用户现有 provider。

从显式本地记录和确定性检索开始，再加入经过测试、绑定来源的候选提取，最后加入可选原生生命周期集成。只有在有具体需求和实测收益时才添加远程或向量后端。最初发布设计时，所有工作包均为 Backlog。E2.6/E2.7 现有 [31](31-explicit-local-memory-zh.md) 中的狭窄 In Progress 先导，其他工作包仍为 Backlog。
