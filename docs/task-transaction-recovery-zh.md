# 任务事务进程崩溃恢复证据

[English](task-transaction-recovery.md) | 简体中文

## 范围

这是 Issue #21 中 E8.1/E8.2 的有限离线子集，不是完整 M1 验收。测试在云端使用合成 SQLite 数据库运行现有任务存储，不启动 Gateway，不使用提供方凭据，不执行外部写入，也不依赖用户的 MacBook。它补充而非替代 PR #52 的记忆候选恢复测试以及已有拆分操作的提交边界检查。

## 故障矩阵

`tests/unit/test_task_process_recovery.py` 在 SQLite DELETE 和 WAL 日志模式下运行 88 个用例。每个用例在独立 Python 进程中打开真实数据库并调用生产 `TaskStore.run` 方法。连接子类在指定真实 SQL 写入之后或 COMMIT 前后立即通过 `os._exit` 终止进程，防止 Python 异常处理和连接清理替崩溃进程完成回滚。

覆盖八种操作：捕获、更新、完成、取消、进度修改、依赖替换、批量计划捕获和任务拆分。每种操作均在首次任务写入、首个事件、回执插入之后以及提交前后中断。额外中断点覆盖旧依赖边删除和首个新依赖边插入之后、批量剩余部分写入之前。

重新打开时，所有提交前崩溃必须恢复完整的原逻辑数据库转储，而不仅是行数相同。所有提交后崩溃必须保留回执。重试完全相同的请求只产生一个结果或重放已有结果；再次新建连接必须重放同一回执且数据库不变。使用相同请求 ID 和不同负载必须失败且不产生变更。规范任务和父任务快照必须与原成功结果一致，SQLite 完整性检查必须通过。

## 限制

这是进程终止测试，不是断电、文件系统故障、磁盘损坏或备份恢复认证。两种日志模式只在临时测试数据库中显式设置，生产数据库配置不变。离线存储测试不覆盖宿主准入、撤销、真实原生传输、worker 派发或远程投递，也不能证明外部执行恰好一次。本测试子集不修改生产行为或数据库结构。完整 #21 保持开放。

使用项目的 Python 3.14 测试环境运行定向矩阵：

```sh
python -m pytest tests/unit/test_task_process_recovery.py -q
```

运行 `python scripts/check.py` 执行所有单元、lint、类型和双语文档检查。原生兼容性需要另行记录的固定宿主运行方式；仅本地检查通过不能描述为原生兼容性验收。
