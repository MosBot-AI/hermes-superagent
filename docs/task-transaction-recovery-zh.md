# 任务事务进程崩溃恢复证据

[English](task-transaction-recovery.md) | 简体中文

## 范围

Issue #21 中的这组 E8.1/E8.2 检查覆盖两类边界。离线矩阵使用合成 SQLite 数据库与独立子进程。运行包安装用例在隔离 profile 内使用原生 Gateway 及经过认证的本地传输。两者均使用合成任务数据，且无需模型或提供方凭据。[原始本地 M1 验收](90-local-m1-acceptance-zh.md)仍采用其固定证据检查点。

## 故障矩阵

`tests/unit/test_task_process_recovery.py` 在 SQLite DELETE 和 WAL 日志模式下运行 88 个用例。每个用例在独立 Python 进程中打开真实数据库并调用生产 `TaskStore.run` 方法。连接子类在指定真实 SQL 写入之后或 COMMIT 前后立即通过 `os._exit` 终止进程，防止 Python 异常处理和连接清理替崩溃进程完成回滚。

覆盖八种操作：捕获、更新、完成、取消、进度修改、依赖替换、批量计划捕获和任务拆分。每种操作均在首次任务写入、首个事件、回执插入之后以及提交前后中断。额外中断点覆盖旧依赖边删除和首个新依赖边插入之后、批量剩余部分写入之前。

重新打开时，所有提交前崩溃必须恢复完整的原逻辑数据库转储，而不仅是行数相同。所有提交后崩溃必须保留回执。重试完全相同的请求只产生一个结果或重放已有结果；再次新建连接必须重放同一回执且数据库不变。使用相同请求 ID 和不同负载必须失败且不产生变更。规范任务和父任务快照必须与原成功结果一致，SQLite 完整性检查必须通过。

## 已安装运行包的 Gateway 提交边界

手动原生 Gateway 测试在 Hermes `2281116525106e3c109993ccb5dc74d02bfc1427` 上通过官方扫描流程安装已验证的运行包。经票据认证的 WebSocket 提交一份包含三个任务、三条依赖边的合成计划。专用于测试的入口只对临时任务库中指定请求键的事务注入故障，在真实 SQLite `COMMIT` 前一刻或后一刻终止测试启动的 Gateway，斜杠命令处理器来不及返回。客户端读取直至连接关闭，并检查目标 RPC 未返回响应。两个 Gateway 进程都受测试的 socket 限制。

提交前崩溃后，只读查询将完整的任务、事件、依赖边和回执状态与基线对比。新的 Gateway 恢复原会话，精确重试仅创建一次计划。提交后崩溃时计划已经可见，精确重试返回已提交的回执和任务 ID。两种用例均检查规范任务及修订号、精确依赖边、事件行、保存的回执与就绪任务回读。再次精确重试以及使用相同请求键提交不同内容均不会改变数据库。恢复前后均检查 SQLite 完整性与引用关系。

第三个用例在提交后崩溃时关闭测试 profile 中的本地任务对话及依赖它的模型工具。后继 Gateway 仍能恢复原生会话。查询任务、精确重试计划和写入新任务都收到宿主返回的 `unsupported_command`，无任务结果。在停用的 Gateway 运行期间及停止后，只读检查将全部任务、事件、依赖边和回执行与已提交的快照对比。测试随后在 Gateway 停止时恢复启用配置。第三个实例恢复同一会话，重试时返回原任务 ID 和已提交的回执，数据保持不变。本用例覆盖按启动时载入的配置执行准入。进行中操作的即时撤销及远程所有者授权另有验收门槛。

可针对受测版本触发仓库的[手动原生 Gateway 工作流](../.github/workflows/native-gateway.yml)。本地定向运行时，使用已准备好的固定 Hermes 解释器，并按该工作流设置 `HERMES_TEST_ROOT`、`HERMES_RUNTIME_PACKAGE` 与 `HERMES_SOURCE_COMMIT`。测试使用暂存于本地 Git 目录的已验证运行包进行官方安装。

```sh
python -m pytest -q acceptance/live/test_packaged_gateway_tasks.py -k plan_reconciles_at_gateway_commit_boundary
```

## 限制

中断方式为进程终止。断电持久性、文件系统故障、磁盘损坏和备份恢复均不在此次证据范围内。两种日志模式用于离线矩阵。Gateway 用例测试已安装的运行包及其常规任务存储配置。#21 下更广泛的身份、撤销、worker 派发及外部投递验收继续开放。

使用项目的 Python 3.14 测试环境运行定向矩阵：

```sh
python -m pytest tests/unit/test_task_process_recovery.py -q
```

运行 `python scripts/check.py` 执行所有单元、lint、类型和双语文档检查。原生兼容性需要另行记录的固定宿主运行方式；仅本地检查通过不能描述为原生兼容性验收。
