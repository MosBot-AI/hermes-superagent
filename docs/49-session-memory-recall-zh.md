# 49. 会话级自动记忆召回

[English](49-session-memory-recall.md) | 简体中文

后续更新：[69](69-chinese-automatic-recall-zh.md) 以共享有限中文功能词切分及保守多项门槛更新下文历史查询描述。显式检索和权限不变，质量与漏召回见固定评估。

生产插件现可在受支持的原生主会话轮次开始时，经过独立会话授权自动读取相关
本地记录。它使用已有宿主 `pre_llm_call` hook，不依赖审阅中的工作器补丁。
不需要额外 provider 包、不替换已选择的 MemoryProvider，也不增加模型请求。
这是自动**读取**，不是提取、写入正式记忆、会话归档或 checkpoint-v2。

## 1. 只在允许的会话中启用

沿用已有[记忆工具配置](32-session-scoped-memory-tools-zh.md)：
`mode: local_tasks`、`local_conversation: true`、`local_memory: true` 和
`memory_model_tools: true`。不会自动更改这些设置。在可信原生 LOCAL 会话中使用：

```text
/personal-memory-tools enable-read
/personal-memory-tools recall-on
/personal-memory-tools status
/personal-memory-tools recall-off
```

确有写入需要时可另行选择 `enable-write`；自动召回本身不需要写权限。
`recall-on` 必须已有有效记忆授权，不延长其 30 分钟有效期。普通激活本身不会
开启自动召回。`recall-off` 只停止后续召回，保留记忆工具；`disable` 同时停止两者。
续期或改变激活等级后须再次明确 `recall-on`，过期或降级不会悄悄恢复自动召回。
重载、卸载和重启清除全部选择和激活状态。

会话 `status` 命令报告 `recall_enabled`。全局 `personal_agent_status` 不能观察
当前会话授权：配置了记忆工具时，其 `automatic_recall` 为 `null`，不表示已经
启用。应使用会话命令检查。上述命令和状态检查均不创建缺失的记忆数据库。

启用召回即允许后续符合条件的轮次把匹配记录送入该会话配置的主模型及正常
宿主历史，适用正常输入费用与保留规则。所有获准会话控制者共享此权限；LOCAL
不证明物理本地或每条指令来自真人。任务工具激活独立，不能授予记忆召回。

## 2. 每轮读取什么

查询仅来自宿主当前原始纯文本 `user_message`，不会从会话历史、工具结果、
多模态内容、声称的发送者字段或旧助手文本拼出查询。斜杠命令、空值/非法输入、
超长文本和简单确认语不会触发读取。检索是有界字面匹配，不是向量或语义搜索。

最多使用八个不同的字面词块。匹配区分大小写；中文按标点和空白分块，不使用
语言模型分词。例如，包含独立词块 `早餐` 的提问可以匹配早餐记录；连续的长
中文句子可能无法匹配其中相关短语。没有结果不证明偏好或事实不存在。

最多返回六条完整当前记录。整个转义 JSON 上下文连同说明和元数据限制为
6,000 字符，而不是 6,000 token。预算不够时省略整条记录，不把文本截断。
记录仍附 ID、版本、编辑来源标签、过期评估时间与遗漏数量。存储文本被明确
视为不可信证据，不是指令、授权或已经核实的事实。插件不会因此创建任务、
修改记录、联系他人或推断执行动作。

## 3. 新鲜度、撤销和历史

每个符合条件的轮次重新打开现有私有存储的只读连接，不缓存召回正文，也没有
后台队列。更正改变下一次符合条件的快照；遗忘和过期会把记录排除出新召回。
SQLite 读快照之后发生的写入，可能使已准入的上下文立即成为历史版本；不声称
数据库与模型提供方具有同一事务。

准入要求真实当前原生轮次、精确配置/会话/路由、主 CLI/TUI/Desktop 上下文、
当前配置、未过期记忆授权和独立召回选择。子代理、cron、远程、未绑定或托管
执行不能借用父会话选择。读取过程中观察到配置或授权变化，会在返回前丢弃
新上下文。观察到撤销即清除选择；没有宿主版本栅栏时，无法检测未观察到的
跨进程“关闭后再打开”。

**新召回不等于历史擦除。** 宿主可能把上下文保存进 `api_content` 并在以后重放。
关闭召回、更正或遗忘记录，不会删除此前消息、宿主历史、提供方保留内容、导出
或备份中的文本。新建会话也不会删除旧会话。不能声称遗忘后所有提示词都不再
含有旧记录。

## 4. 存储与 Provider 边界

召回 hook 使用已有的正式记录只读读取器，不创建、升级、修复或接管数据库，
也不推进记忆游标或 checkpoint。存储缺失、版本旧、不安全或不可用时，不返回
记忆正文。应在获准后通过已有操作者命令主动初始化或升级自有存储，不要复制
外部数据库或改权限强行打开。

原生 provider 的选择与配置保持不变。如果用户还另行选择 `personal-records`
provider，两条分别启用的召回路径可能产生重复上下文；不想重复时应选择一条
自动路径。本功能不会偷偷替换 provider，也不声称自动去重。其他 provider 和
工具仍遵循各自的行为与权限。

现有读取器文档披露的 SQLite/WAL 竞争限制仍适用：这是正式记录只读访问，
不是对抗同 UID 其他代码的操作系统/VFS 沙箱。插件不保护其他宿主工具。不支持
的隔离或托管执行必须继续拒绝，不能为使用召回关闭已有隔离。

## 5. 验证与剩余门槛

离线测试使用真实干净固定宿主的命令准入、轮次 hook、上下文组装与历史 API
侧车，并使用合成记录。覆盖独立激活、默认不读、重载/过期/撤销、更正和遗忘的
新鲜度、数据边界、配置/路由/子代理/cron 拒绝，以及原生配置不变。单测覆盖
非法查询和竞争边界，不调用真实模型、提供方凭据、安装器或 Gateway 监听器。

现有独立插件的记忆因此不再完全依赖模型主动调用搜索工具。真实模型的实用性、
中文语义召回质量、自动提取/候选审阅、持久会话覆盖和原生 checkpoint-v2 仍是
独立工作。原安装拒绝不会因这些测试被重试或豁免。
