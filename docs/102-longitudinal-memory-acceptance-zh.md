# 102. 合成长程记忆验收

[English](102-longitudinal-memory-acceptance.md) | 简体中文

## 范围与独立夹具

[Issue #145](https://github.com/MosBot-AI/hermes-superagent/issues/145) 新增面向 #46 的有界诊断，不是生产或真实模型验收。[夹具](../tests/fixtures/longitudinal_memory_recall.json) 由独立作者编写，并在执行任何生产查询评估之前冻结：SHA256 为 `4e504fd7b2c84bcf2418a482f5769eecf845e84b2a56cd1c6237f7c2bc5ed2dd`。看到结果后没有调整相关性标签或生产检索逻辑。原有 28 条记录评估器及文档 69 的历史证据保持不变。本地知识库不可用，没有据此编造历史决策；证据来自仓库契约。

累积合成存储从 28 行增长至 250 行，再到 1,000 行，保留行数包括墓碑和过期记录。新增内容是矿石目录填充记录及独立选定的八条同实体干扰事实。37 个固定查询覆盖短名字、同名实体、中文与混合文字表达、日期/数字、否定事实、带有指令注入特征的存储数据、更正、遗忘、过期以及不受支持的跨文字形式匹配。即使人物/项目匹配，不相关属性也不标记为相关。

阶段时钟推进并跨越明确的到期边界。普通记忆更正和遗忘，以及两条显式保留、以回执为依据的合成来源记录的更正/遗忘，均使用当前生产 API。回执标签经确定性 SHA256 编码，满足 SDK 摘要字段要求。这些是受信任的合成来源夹具，不是真实原生回执签发、来源真实性或自动摄取的证据。本语料中的过期适用于普通记录，而非保留来源记录。

## 运行时路径与安全判定

[运行器](../acceptance/memory/runner.py) 将当前源码复制到私有临时插件夹具，复用既有固定宿主契约辅助函数。真实插件加载器注册生产 pre-LLM 钩子；真实 LOCAL 命令分派激活记忆读取与回忆；真实 Relay 轮次协调器和原生钩子收集器覆盖 `RecallingSessionMemoryTools`、当前 profile 准入、原始输入查询规划、SQLite 只读打开、保守过滤和完整 ASCII 转义 JSON 组装。没有替换查询规划/回忆实现。已认证的内存传输夹具不是认证证明、正式安装或运行中的 Gateway。不启动监听器、模型、提供方凭证或外部连接。子进程使用白名单环境，并拒绝网络连接。

每个阶段在三个不同进程中读取：首次评估、状态不变的重启，以及受支持的同 profile 维护 preview/prepare/commit 之后。显式重新激活前，进程本地授权必须不存在。逻辑上下文封装、精确记录字段和封装大小必须一致。只有说明过的实时 `memory.evaluated_at` 时间戳可归一化；固定过期时钟通常也使它相同。不忽略任何 UUID、修订号、来源标记、来源字段、过期、遗漏或预算字段。读取、拒绝探针、历史重试及重打包前后，独立捕获全部数据库表行。这是当前存储重打包，不是历史恢复或对话压缩。

硬性检查与相关性测量分开：

- 每份完整上下文必须是 ASCII JSON，最多 6,000 字符和六条完整记录。ID 唯一，当前载荷/来源/修订字段与规范读取一致，遗漏、条目大小和过滤元数据内部一致。
- 规范内容、主题、修订号、过期和存储状态，还与根据夹具新增及修改独立推导的状态比较。被遗忘载荷保持清空墓碑；过期记录仍存储且可显式检查。新上下文排除该阶段禁止的 ID 与过时载荷标记。
- 每个阶段至少必须存在一份已准入上下文，避免完全失效的钩子空泛通过。该健康条件不是相关性门槛。空输入、斜杠命令输入和 recall-off 不返回上下文。
- 已遗忘记录拒绝更正。同一精确来源身份重新进入时返回 `source_identity_conflict`；新身份但相同指纹返回 `source_suppressed`。250 行时的探针独立于满容量限制验证抑制。原接受操作重试返回历史元数据，不改变当前状态。第 1,001 行保留记录以 `record_limit` 拒绝，不驱逐任何记录。
- 作用域限定的异常跟踪会观察生产代码捕获的异常；钩子失败日志也导致失败。单个查询吞掉异常的反例，防止把异常误标为相关性遗漏。反例测试证明会检测过时/截断载荷、完整封装超限、重复 ID、错误遗漏/过滤/预算元数据、重启后上下文/预算变化，以及全空钩子。相关性遗漏是如实报告的结果，不是重写标签的理由。

删除原生原始文本**不被视为**删除独立保留的规范记忆。该运行器不删除原生对话。来源丢失与真实打包 Gateway 行为仍属于独立的[文档 99 验收路径](99-packaged-memory-lifecycle-zh.md)。

## 保留来源迁移与维护组合

独立的[保留来源辅助模块](../acceptance/memory/retained.py) 使用 SDK/SQLite 夹具，不使用原生钩子。它创建 schema-12、以回执为依据的已接受/更正、已接受/遗忘、已丢弃和待决决策，通过普通可写打开器迁移到 schema 13，再添加同样的观察来源案例。旧请求摘要与回执必须在迁移后保留。待决决策、完成游标、状态、血缘和抑制元数据必须在受支持的重打包与全新进程重新打开后保留，包括精确历史重试和新准入拒绝。

两个全新 profile 分别覆盖正常切换，以及在保留旧数据库之后、安装暂存数据库之前的一次受控进程退出。显式恢复完成同一已记录意图。每个 profile 检查八个决策，共两个全新验证进程。这是现有机制的组合，不新增宽泛崩溃矩阵，不重打包原生对话，不转移权限，也不声称物理擦除。保留的旧文件可能含有历史明文。

## 实测相关性与限制

[机器可读报告](longitudinal-memory-acceptance-report.json) 包含每个查询检索、遗漏和不相关的夹具 ID、完整上下文、封装大小、可见遗漏、有范围说明的计时、进程证据、夹具/源码/运行器哈希及维护结果。源码哈希标识被测试的树；本地工作树提交不是已发布版本。测试使用 Python 3.14.9、SQLite 3.53.1 及干净 Hermes `2281116525106e3c109993ccb5dc74d02bfc1427`。

| 保留行数 | 相关返回数 / 全部返回数 | 相关返回数 / 标签对数 | 无结果的正例查询 | 完整封装最大值 |
| --- | --- | --- | --- | --- |
| 28 | 16/16（100%） | 16/32（50.00%） | 15 | 1,453 字符 |
| 250 | 13/14（92.86%） | 13/28（46.43%） | 14 | 1,709 字符 |
| 1,000 | 13/14（92.86%） | 13/28（46.43%） | 14 | 1,710 字符 |

这里是返回条目精确率和微平均召回率，不是固定六个位置的精确率，也不是答案正确性。为避免字面生命周期控制项抬高实用性，报告另行排除 `old_city_probe`、`empty` 和 `slash`：初始召回率变为 15/31（48.39%）；后续阶段仍为 13/28。初始六个、后续十个空真值查询均无返回。新增 `aurora_logo` 与 `mixed_owner` 无关，却在 250 和 1,000 行时返回。初始十五个、后续十四个查询遗漏相关证据，包括同名歧义、通勤、否定饮食/课程表达、航班、预算、混合文字数据库问题、冗长钥匙表达、电影、当前城市、注入样本及跨文字形式。报告保留精确的逐查询列表。

每阶段返回封装中有两条可见遗漏。初始 21 个、后续 24 个查询不返回封装，因此遗漏元数据是**未知**，不是零，也不是不存在的证明。实测最大封装远低于上限：本语料未填满 6,000 字符预算。独立超限反例和既有生产预算测试覆盖该边界；不声称是所有预算边缘的压力基准。大部分无关的填充记录及这份合成夹具，不构成总体质量、语义检索、长对话回答质量、模型成本节约或生产延迟证据。

## 复现与证据

使用已准备的 Python 3.14 解释器及精确的干净检出；运行器验证兼容性固定版本，并拒绝改变后的夹具摘要。它自行创建和删除临时合成 profile。不要指向真实 profile。

```sh
/path/to/hermes-test-venv/bin/python scripts/evaluate_longitudinal_memory.py \
  --hermes /path/to/pinned-hermes > /tmp/longitudinal-memory.json
/path/to/hermes-test-venv/bin/python -m pytest -q \
  tests/unit/test_longitudinal_memory_acceptance.py \
  tests/unit/test_retained_source_repack_acceptance.py
/path/to/hermes-test-venv/bin/python scripts/check.py \
  --hermes /path/to/pinned-hermes \
  --hermes-python /path/to/hermes-test-venv/bin/python
git diff --check
```

计时包围原生 pre-LLM 钩子收集，包括异常/日志观测开销、生产准入、全新只读连接/模式验证、查询/过滤、完整封装与最终门禁。不包括进程/宿主启动、写入、重打包、判定器及全部模型延迟。不清空操作系统缓存。每阶段在三个全新进程中共有 111 个测量值；最近秩 p50/p95 依次为 5.757/19.867 ms、5.080/6.362 ms 和 5.786/7.719 ms。环境与原始样本在报告中。这些是共享云环境观测，不是服务级目标。已执行的汇总检查通过 4,457 个单元测试、Ruff、ty、双语文档检查和 1,440 个固定宿主契约；36 个运行器/保留来源辅助模块专项测试也通过。代码与通过的测试不关闭更广泛的 #46，也不授权部署。
