# 持久化读取快照准备审计

[English](63-prepared-read-audit.md) | 简体中文

## 范围

内部[带栅栏读取协调器](27-fenced-read-admission-zh.md)现在会在允许脱离连接的结果离开 SQLite 事务前，提交最小化的 `snapshot_prepared` 事件。这补齐了 E1.4/E1.5 的一个审计缺口；它不是生产身份、登记激活、资源接管、传输层或完整 M1 验收。插件的所有正常入口仍对该协调器默认拒绝。当前身份权威与资源适配器仍只有合成测试实现。

记录表示协调器已验证并物化有界快照，成功关闭资源快照，并在持有宿主及策略栅栏时通过最终身份权威／时间检查。它**不能**证明调用者收到了结果、传输层发出了结果、用户看到了结果，或适配器真的认证了一个人。内部 API 仍属于受信代码，而非针对恶意 Python 的安全边界。

## 顺序与失败

`EnrollmentStore.with_audited_read(...)` 包装 `with_current_record(...)`。它在 `BEGIN IMMEDIATE` 下验证当前策略／修订，在调用资源操作前检查审计容量，验证返回的 `PreparedRead`，插入审计，然后提交。协调器在资源快照成功退出**之后**，从 `AdmissionGuard.validate_and_now()` 取得最终可信 UTC 时间，而不是使用请求输入。若快照退出使身份权威失效，或耗尽剩余有效期，则不能记录审计或返回数据。

插入或 COMMIT 失败会回滚且不返回数据。COMMIT 前崩溃不留下已提交事件。COMMIT 后崩溃，或退出宿主 guard 时抛出异常，可能已经留下事件却没有返回任何值，因此结果仅命名为 `snapshot_prepared`。本切片不记录被拒绝或失败的尝试，不是完整访问尝试日志。管理性的撤权／策略事件仍独立记录且保持不变。

锁顺序仍为宿主 guard → 策略事务 → 资源快照。先提交的撤权阻止读取；已经准入的读取可以先于等待中的撤权提交事件。后来的撤权不会抹除历史或撤回脱离连接的结果。事件不是可复用批准、重放许可或授权令牌。重试需要新的单次确认，成功时生成另一条事件；不缓存旧结果。

## 存储元数据与有界查看

新的 `read_admissions` 表仅保留库内序号、owner/profile/enrollment 选择器、登记／策略修订、epoch、可信 UTC 准备时间、资源数量（1–32）及固定结果。它不存储任务 ID、标题／详情、结果哈希、接收端、主体、会话、宿主 incarnation、grant ID、凭据或原始错误。选择器是普通明文管理元数据，不是所有权证明或加密秘密。

内部 `read_admission_history(key, after_sequence=0, limit=50)` 方法按序号返回精确作用域的元数据页，每次最多 100 行，附带 `has_more` 和 `next_after_sequence`。每页是新查询，而不是跨页冻结快照。格式损坏的持久元数据会被拒绝。它可查看已撤权记录的历史，但不能重新激活记录。没有命令、模型工具、HTTP 路由或 JSON `run()` 操作暴露该方法；外部调用者不能把审计行作为身份权威。

每个数据库的事件硬上限为 **10,000 条**。达到容量或序号上限后，在获取／读取资源快照前拒绝新读取。不会静默淘汰、重写时间戳或自动清理。到达此时，宿主单次确认可能已经被消费。管理性的策略／撤权操作仍然可用。此前驱实现没有受支持的裁剪、导出、恢复或容量恢复流程；不能通过删除或替换身份权威存储来绕过限制。保留期／运维处理仍是生产门槛，离线副本可能无限期保留这些元数据。

## Schema 兼容性

显式内部存储初始化只会对**精确匹配的自有 v1 schema**进行原子升级，添加审计表后变为 v2。现有登记行、管理事件、修订和终态撤权状态均保留，不会被重新解释为已激活权威。不会补造历史读取事件。新建 v2 与升级后的 v2 具有完全相同的受检 DDL。未知版本、额外对象、变更后的 DDL 及临时影子对象均被拒绝。建表、版本变更或 COMMIT 失败会保留 v1，存储仍为未初始化状态。

正常插件加载／状态查询不会初始化该存储。调用原有显式内部 opener 时，现在会执行 v2 升级。只理解 v1 的旧代码会拒绝 v2，不提供自动降级。每次操作前都会检查 schema，也不会接管其他数据库的快照数据。

## 验证

离线测试覆盖冻结 v1 的迁移与回滚、元数据最小化、分页／作用域隔离、撤权后历史查看、最终时间采样、格式错误的回调／记录、审计插入与提交失败、容量／序号拒绝、宿主退出失败，以及 COMMIT 前后的真实进程退出。既有真实 SQLite 竞争测试验证，审计会在等待中的策略变更之前保留准入时修订。这是进程崩溃测试，不证明断电持久性或抵御恶意同 UID 进程。

固定宿主契约检查包状态仍为阻止、显式私有 profile 持久化，以及持久审计不能激活缺失的身份权威适配器。它们不运行真实 owner/Bot 读取、供应商请求、Gateway 监听或外部传输。生产身份、受信适配器、资源归属／接管、恢复／克隆栅栏、完整拒绝尝试审计及真实入口验收仍未完成。
