# 任务到 worker 的委派提案

[English](48-task-worker-proposal.md) | 简体中文

## 本轮推进

[仅供审阅的文本 worker 工件](../experiments/text-worker/README-zh.md)把明确批准的本地任务修订，连接到一次原生宿主文本请求及生命周期结果。包含拟议宿主 API、准确路由 opt-in、受控单次执行、专用 no-redirect 客户端、持久单次领取/草稿回执、具体实验命令/模型消费者及可重现离线测试。生产插件不会加载它。

消费者的固定流程为：选择任务 → 短时单任务授权 → 真实主轮次准入 → 不可变任务快照 → 文本 worker → 带修订/过时标记的草稿。不会标记任务完成，不把返回指令视为授权，也不执行一般 worker 工具。

## 面向操作者的工作台

原生 `/personal-plan-worker` 命令现支持 `list [--after KEY]`、`status KEY`、`draft KEY` 和 `stop KEY`。默认输出可读文本，前置 `--json` 保留结构化响应。列表每页最多十条范围内元数据，不含任务正文或草稿。`receipt_saved` 表示有 worker 回执，不表示任务已执行。

`draft` 通过已审计的原生命令输出路径直接显示已保存终态回执，附当前修订/过时信息，并转义不可信文本。不轮询活跃 worker，不发起模型请求。该明确的操作者读取独立于模型工具，后者的准确路由披露检查不变。原生客户端可显示/缓存输出，LOCAL 不证明调用者是物理真人。

`stop` 只撤销尚未启动的授权。对已准入/结果不明的请求，它明确报告取消不可用，并保留已消耗记录，不伪造父绑定，也不创建新请求。工作台不恢复丢失结果、不删除保留 key，也不使提案成为受支持的已安装功能。

## 为何单独作为实验

基线公共生命周期的一般子代理启动会继承工具、已保存路由、MCP 工具集、递归委派和工作区行为。空列表或“不要使用工具”的提示词不能提供所需约束。全局改变这些默认行为也会影响宿主原本合法的行为。

因此提案增加独立的 opt-in 纯文本方法。窄化请求不构造完整 agent、不继承父对话、不进入完整子代理工作区/辅助模型流程。[工件说明](../experiments/text-worker/README-zh.md)列明已约束范围、合成证据及未验证的提供商边界。正式兼容性基线、普通模型工具表面和就绪声明保持不变。

## 重启及客户端行为

宿主提案不再借用父 HTTP 客户端，而为准确批准的路由建立独立的禁止重定向、不使用环境代理的客户端，不通过 SDK 构造器发现凭据，不改变共享客户端。现有宿主 payload 构造、请求/执行中间件、生命周期和响应归一化仍在链路中。这仍是需要正式采纳的宿主补丁，不是已安装的集成。

消费者在派发前，向独立私有 SQLite 账本记录单次领取。崩溃或确认丢失不会让同一请求重新可执行。领取及实时/保存草稿均绑定原准确路由指纹，在新工具返回前检查；这不能收回切换模型前已有的会话历史。已观察到的终态草稿会保存，可在重新加载后查看；未观察的结果保持不明，不推断成功或重试。待执行授权属于原消费者实例，新实例不能静默继承。有界账本保留终止记录，容量满时拒绝新授权。

## 后续验收

仍需上游采纳及真实获授权 OpenCode Go `deepseek-v4.1-flash` 验证。在持续自主 worker 编排前，必须完成生产级结果不明核对、提供商侧持久执行标识和成本/并发控制。本地账本不是提供商执行事务，也不保证远端恰好执行一次。带工具 worker 需要单独的可执行权限约束。Gateway 传输及自动记忆门槛仍未关闭。
