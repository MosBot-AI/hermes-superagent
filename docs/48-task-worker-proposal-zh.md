# 任务到 worker 的委派提案

[English](48-task-worker-proposal.md) | 简体中文

## 本轮推进

[仅供审阅的文本 worker 工件](../experiments/text-worker/README-zh.md)把明确批准的本地任务修订，连接到一次原生宿主文本请求及生命周期结果。包含拟议宿主 API、准确路由 opt-in、受控单次执行、具体实验命令/模型消费者及可重现离线测试。生产插件不会加载它。

消费者的固定流程为：选择任务 → 短时单任务授权 → 真实主轮次准入 → 不可变任务快照 → 文本 worker → 带修订/过时标记的草稿。不会标记任务完成，不把返回指令视为授权，也不执行一般 worker 工具。

## 为何单独作为实验

基线公共生命周期的一般子代理启动会继承工具、已保存路由、MCP 工具集、递归委派和工作区行为。空列表或“不要使用工具”的提示词不能提供所需约束。全局改变这些默认行为也会影响宿主原本合法的行为。

因此提案增加独立的 opt-in 纯文本方法。窄化请求不构造完整 agent、不继承父对话、不进入完整子代理工作区/辅助模型流程。[工件说明](../experiments/text-worker/README-zh.md)列明已约束范围、合成证据及未验证的提供商边界。正式兼容性基线、普通模型工具表面和就绪声明保持不变。

## 后续验收

仍需上游采纳及真实获授权 OpenCode Go `deepseek-v4.1-flash` 验证。在持续自主 worker 编排前，必须完成持久执行回执、重启/结果不明核对和成本/并发控制。带工具 worker 需要单独的可执行权限约束。Gateway 传输及自动记忆门槛仍未关闭。

参见[原子项目计划](47-atomic-project-plans-zh.md)、[worker 路由](11-worker-model-routing-zh.md)和[路线图](08-roadmap-and-acceptance-zh.md)。本原型推进可行性，不表示上述验收完成。
