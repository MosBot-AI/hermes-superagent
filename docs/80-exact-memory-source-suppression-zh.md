# 80. 精确记忆来源抑制

[English](80-exact-memory-source-suppression.md) | 简体中文

## 本地操作人员流程

满足已有显式本地记忆前提后，检查待审核候选并抑制其精确原始输入：

```text
/personal-memory candidate-show CANDIDATE_ID
/personal-memory candidate-suppress-source CANDIDATE_ID --expected-revision 1
```

此操作人员专用命令从已存待审核候选取得指纹，不接受提交的摘要或模型声明。它在当前 profile namespace 内原子登记抑制，并丢弃**完整输入 SHA256 相同的全部待审核候选**，清除其内容、引用、来源摘要及 session 字段。选中的候选返回终止元数据回执；完全相同的重试返回同一历史回执，而非新的删除数量。过时 revision、已过期或已终止候选不能建立新的抑制。没有解除抑制命令或静默淘汰。模型工具不能抑制、接受或移除这些标记。禁用、远程及未绑定入口保留已有拒绝门禁。

后续新提案和待审核候选接受，在产生效果的同一 SQLite 写事务中检查抑制。新的原生 turn、nonce、请求 ID 或 session 不能绕过相同输入指纹。相同旧提案请求仍可重放历史元数据；候选接受重试仍可返回历史 accepted 元数据，即使关联记录已经更正或遗忘。两种重试都不创建新候选或记录，也不证明当前状态。更改重放参数仍产生冲突。

## 更正和遗忘

schema 11 之后接受的候选，通过最小候选到记录关联保留原始输入摘要。`correct`、`forget`、编辑草稿更正及审核后的 `forget-expired` 使用同一 canonical 修改路径：抑制和待审核候选清理随 canonical 修改、事件及回执一起提交或回滚。单纯过期不抑制来源。普通显式 `remember` 仍允许作为有意的新记录，不伪造来源关联。

抑制**不会**删除来自同一输入但已经接受的兄弟记录。如果接受先提交，该兄弟记录保留，需要单独更正或遗忘；如果抑制先提交，待审核兄弟候选随后不能被接受。已有无来源显式记录及旧版已接受记录不会获得猜测的来源。更正抑制旧输入，而不是新提交的更正正文。

## 精确匹配及隐私限制

这是完整输入匹配，不是语义遗忘、来源作者认证或持久原生历史身份。`source_turn` 含 nonce，不用作持久抑制键。修改或追加文本、改变 Unicode 规范化形式、改写或在不同输入中提交同一事实，都不匹配。反过来，抑制一个候选会阻止相同完整输入中的其他拟议事实，包括无关事实。操作前应审核此范围。

SHA256 指纹可以关联，低熵输入可通过字典攻击猜测；它**不是匿名化或加密**。新关联和抑制仅保留最小标识及摘要，不保留原始输入或引用。已有事件及重试元数据继续保留。这不会擦除原生历史、先前结果、provider 上下文、物理介质或历史明文快照。快照仍可能包含后来遗忘或抑制的数据；不启用恢复或导入路径。

## 存储和迁移

schema 11 在同一自有 SQLite 数据库中增加 `memory_source_lineage` 和 `memory_source_suppressions`。授权可写打开以事务方式升级已知 schema 1–10；未知或外来 schema 仍被拒绝。此前已接受候选的摘要已经删除，因此迁移**不会**回填关联。待审核候选仍可使用显式命令；后续接受建立关联。只读召回不迁移且要求当前 schema。历史快照检查明确保留精确 schema 10/11 支持，不改快照字节，也不放宽 namespace、日志或 schema 检查。

每条关联以一个保留候选和一条记录为锚；每条抑制具有唯一候选锚及唯一摘要。已有永不淘汰的 1,000 候选上限，使每张新表最多有 1,000 行。不存在会新增遗忘拒绝的独立抑制配额：每个符合条件的新标记已经占用一个候选槽位。不静默淘汰终止标记。`exact_source_suppression` 是显式适配器能力；其他适配器不会悄悄收到新操作。
