# 39. 本地记忆元数据检查点

[English](39-local-memory-checkpoints.md) | 简体中文

状态：已实现本地记录存储的显式、仅含元数据的检查点。在调用方自行报告的[消费者游标](37-durable-memory-progress-zh.md)之外，新增事件与当前记录的一致性验证及持久恢复标记。它不保存原生会话检查点、不生成备份、不发布投影、不提取记忆，也不满足 Hermes 必需的 checkpoint-v2。后端仍不支持通用 `checkpoint` 和 `native_lifecycle` 能力。

## 1. 创建与查看

显式启用[本地记忆](31-explicit-local-memory-zh.md)后，在现有受信原生 LOCAL 会话中使用：

```text
/personal-memory changes
/personal-memory checkpoint --expected-watermark 2 --request-id checkpoint-pass-1
/personal-memory checkpoint-status CHECKPOINT_ID
```

把 `2` 替换为 `changes` 返回的当前水位，把 `CHECKPOINT_ID` 替换为创建结果中的 UUID。检查点在一个 `BEGIN IMMEDIATE` 事务内验证并记录当前保留的记录与事件元数据。它检查每条记录以 `remember` 开始、后续修订逐次加一、终结遗忘后没有新修改，以及每条当前记录的修订和状态与最后事件一致。扫描最多覆盖 1,000 条记录和 11,000 个事件，其中非终结修改最多 10,000 次。不一致或超限状态会失败，不生成检查点回执。

必须提供预期水位。如果观察后、创建前提交了更正、遗忘或新记录，操作以 `watermark_conflict` 拒绝。应先读取最新状态，再决定新请求，不能声称旧观察已被保存。空存储允许水位零。这是记录状态的事务边界，不证明任何消费者处理过事件。

回执包含检查点 UUID、请求 ID、事件水位、记录及事件数量、有效及遗忘数量，以及按序排列的记录 ID／修订／状态和事件元数据的 SHA-256。不含记录正文、正文哈希、主题、来源标签或会话标识。该哈希不是身份签名，也不校验正文完整性。元数据标识和哈希仍可能属于个人信息。回执明确返回 `restorable: false` 和 `native_checkpoint: false`。

## 2. 历史回执与当前状态

创建及回执沿用现有 SQLite 持久性设置，在同一事务提交。完全相同的重试返回原始不可变回执及 `replayed: true`，即使后续修改已改变存储。同一请求 ID 携带不同预期水位会返回 `idempotency_conflict`。请求 ID 与原始记忆修改、消费者进度的键空间分开。命令会回显自动生成的键；结果不确定时应复用原键和原参数，不能随意换键重试。

`checkpoint-status` 在单个读取快照中重新计算元数据，返回 `is_current` 和 `current_watermark`。后续记忆修改使旧标记过时，消费者游标变化不会。这一状态只对本次读取快照成立，之后可能立即过时；已返回的结果无法撤回。查询不存在的 UUID 返回 `checkpoint_not_found`，不会伪装为空成功。回执重放和状态查询均不修改或恢复记录。

每个存储最多保留 256 份不可变检查点回执。达到配额后仍可完全相同地重试。`checkpoint_limit` 不影响原始记录的更正／遗忘，也不影响读取既有标记。没有实现删除、裁剪、自动检查点调度或重置。不要把重复创建检查点用作无界心跳。

## 3. 范围与后续生命周期工作

创建操作在任何回执查询前，都要求现有受信操作员绑定的后端。模型绑定的后端无法创建或重放这些回执。新增创建／查询操作没有加入模型工具 schema，不会随任务或记忆工具激活而开放。斜杠命令保留显式本地记忆的原生主机会话准入及配置目录／私有文件检查，并不构成经过验证的远程所有者身份。

内部已审阅适配器协商可选能力 `local_metadata_checkpoint`；创建还要求持久写入、CAS 和幂等。内部操作为携带 `expected_watermark`、`request_id` 的 `checkpoint_create`，以及携带 `checkpoint_id` 的 `checkpoint_status`。没有增加提供方加载器，也不是设计中的公共生命周期 SDK。

这些标记不保留原生来源／消息范围、待处理批准、任务真值、外部动作、Markdown 文件或个人正文。它不能恢复已遗忘文本、授权动作、证明外部发布、识别整库恢复到旧版本，也不能防护同 UID 篡改。旧备份仍受尚未完成的抑制／恢复协议约束。不会选择或替换原生提供方，不会编辑主机记忆文件，也不会声明严格原生压缩前检查点成功。原生来源覆盖、可选桥接选择、关闭／排空语义及投影发布隔离仍是独立后续工作。

## 4. Schema 与验证

受管理的 SQLite 记忆 schema 从 v3 升到 v4，新增 `record_checkpoints`。完全匹配的 v1／v2 数据库先执行之前的迁移，再添加检查点表，全部位于同一个写事务内。获取写锁前及锁内都会检查命名空间和精确 schema。失败回滚整个迁移。原有记录、墓碑、事件顺序、消费者状态及原始回执字节保持不变。读取时打开数据库也可能触发迁移；旧版本拒绝 v4。升级前应备份私有插件数据，但不能用旧备份覆盖当前数据并重新引入已遗忘文本。

合成测试覆盖空／当前／过时标记、更正／遗忘、有界元数据隐私、缺失能力、严格输入验证、配额隔离、同键并发、写入竞争、回滚及不确定提交恢复。精确迁移测试覆盖 v3 消费者回执保留，以及 v1／v2／v3 失败回滚。原生分发测试验证主机准入和提供方配置不变。独立受保护进程覆盖重启、过时检测、模型操作拒绝和终结遗忘后的历史重放。

这些是离线存储和原生分发契约，不是真实模型或原生生命周期验收。没有使用在线提供方、账户、socket 监听器、生产配置或远程写入。
