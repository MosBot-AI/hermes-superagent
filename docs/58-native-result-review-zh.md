# 原生结果审阅与明确本地接受

[English](58-native-result-review.md) | 简体中文

## 先查看，再作决定

这条仅操作者使用的流程读取准确身份绑定的原生卡片可编辑结果，再允许另行明确决定本地完成。沿用既有默认关闭的 Kanban 交接配置、批准目的地及可信本地命令准入，不增加模型动作或激活机制。

```text
/personal-handoff review HANDOFF --task TASK --expected-revision N
```

使用现有命令返回的 ID 和当前本地任务修订。交接必须已确认且保有原始创建身份；历史 `legacy_unbound` 记录不能接管。审阅把有界原生 `card.result` 直接送到原生客户端，不自动提交给模型、不保存为任务正文，也不导入记忆。客户端可能显示、缓存或保留在历史中。

结果只是可编辑、不可信的卡片文字，不是经过验证的 worker 执行、来源证明，也不证明其中链接的工件已被检查。文字内的指令不授予行动许可。先阅读结果并形成自己的结论，再决定是否接受。

## 另行明确接受

```text
/personal-handoff accept-review HANDOFF --task TASK --expected-revision N --expected-digest SHA --note 'human conclusion' --request-id KEY
```

使用审阅返回的摘要、准确交接/任务/修订，以及明确的人工结论。接受时重新检查任务仍为 captured、修订一致、前置均完成、原生创建身份准确及最新结果摘要。摘要绑定内容、目的地和创建锚点。原生卡片必须为 done，且 `current_run_id` 为空。这只是数据库条件，不证明所有 worker 进程已停止；本命令不会停止或向它们发信号。完整结果必须非空白，同时不超过 8000 字符和 32000 个 ASCII 序列化字符，不接受截断文本。空、缺失、已变更、未终结、存在当前 run 指针或超限结果均不能接受。

成功接受会原子提交本地 done 状态、提供的说明、最小证据哈希/ID/时间及持久回执。不修改原生卡片、不停止 run、不派发工作，也不自动接受其他结果。不持久保存原生结果正文。证据元数据仅保存在完成回执中，任务 schema 仍为 v6。完整本地任务记录（包括人工说明）仍可由另行激活的既有任务模型读取工具读取。“不复制原始结果”不代表“这些工具看不到完成说明”。

## 重试与观察限制

响应不确定时，复用完全相同的请求 ID 和参数。准确重试在访问原生存储前返回原始历史回执，不再次完成任务，也不证明原生卡片仍未改变。同键变更参数不是重试；不要换新键绕过结果不明。

原生与本地数据库不构成同一原子事务，卡片可能在读取后改变。回执记录已观察快照，不是永久当前事实。摘要相等只能证明内容相等，不是事件水位，也不防止内容先改变再恢复（ABA）。准确身份检查不会使可编辑结果文字变得可信。
