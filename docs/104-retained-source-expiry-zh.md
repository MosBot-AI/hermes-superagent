# 104. 保留来源的到期与清理恢复

[English](104-retained-source-expiry.md) | 简体中文

## 目的与范围

[Issue #149](https://github.com/MosBot-AI/hermes-superagent/issues/149) 增加确定性验收链，覆盖独立保留来源到达原始保留截止时间，随后执行显式审阅清理和本地维护。先前证据分别覆盖了捕获时已经过期的观察来源（[99](99-packaged-memory-lifecycle-zh.md)）、普通记录跨越截止时间，以及保留来源的迁移/重打包（[102](102-longitudinal-memory-acceptance-zh.md)）。本链路组合这些机制，不引入自动删除或另一种检索启发式。

合成[夹具](../tests/fixtures/retained_source_expiry.json) 包含具有未来截止时间的旧版回执来源和观察来源记录，以及一条永久保留的召回对照。测试时间分别是原始截止时间前一秒、恰好相等和后一秒，均为 UTC。仅控制过期判断时钟，不替换生产过期比较、存储、查询规划、召回过滤或清理实现。冻结的相关性语料及其标签保持不变。这是生命周期测试，不是召回质量评分或模型答案评估。

## 实际覆盖路径

[运行器](../acceptance/memory/expiry.py) 使用隔离临时配置和精确固定的干净 Hermes 兼容性版本，复用[长程运行器](../acceptance/memory/runner.py) 中已注册的生产 pre-LLM 钩子及原生 LOCAL 读取/召回激活。每次观察使用新进程，且重启不得继承激活状态。检查完整 ASCII JSON 信封、完整记录预算、永久正向对照和预期返回 ID。被生产召回路径吞掉的异常也属于失败，不能当成成功的空结果。

先把回执来源种子元数据转成历史 schema-12 夹具布局，再由常规受支持的可写打开路径迁移到 schema 13，随后使用独立来源标签接受观察来源记录。这种夹具构造不会签发真实原生回执，也不验证原文作者身份。来源接受和清理通过生产本地 API 使用可信合成调用方元数据；召回链路使用真实注册钩子。本测试不导入或删除原生对话记录。

预期生命周期严格区分三种状态：

- 截止时间之前，两条保留记录必须与永久对照一起进入新召回。
- 恰好到期及之后，存储状态和修订仍为 active 且不变，但新召回排除它们。过期不会遗忘载荷，也不会推进来源进度。
- 显式审阅的 `forget-expired` 批次执行后，当前记录成为已清空的终态墓碑。原始接受回执仍是历史 active/修订 1 结果，不能用来证明当前状态。

判定器比较固定夹具预期、规范 SQL 行和当前原生结果。完整逻辑数据库快照包含 schema、规范表、派生 FTS 行、事件、回执及保留来源决策。读取、拒绝的操作和精确历史重试都不得改变这些数据。测试通过不相关的规范变更主动使审阅清理预览失效；旧预览应用必须无变更地拒绝，然后才执行重新审阅的批次。重试证据必须区分回放原批次与遗忘另一条符合条件的记录。

## 重启、抑制与维护

在重启、正常受支持的重打包，以及旧数据库已保留但暂存数据库尚未安装时的一次受控中断之后检查最终状态。现有显式恢复 API 完成已记录的维护意图。这是有界组合测试，不是另一套穷举崩溃矩阵、历史备份还原或原生对话压缩。

历史接受及清理回执、当前遗忘元数据和已完成来源游标必须保持一致。复用来源身份必须被拒绝；改变请求、消费者、身份和来源路径，但保留被抑制的指纹，也必须被拒绝。当前输入的候选接受同样必须遵守该抑制。精确历史接受重试不得恢复已遗忘文字或再次推进游标。负向对照主动破坏证据或行为，以证明这些检查确实能够失败。

## 复现与证据

使用准备好的 Python 3.14 解释器和精确固定的干净 Hermes 检出。运行器自行创建并删除合成配置，不要指向真实用户配置。

```sh
/path/to/hermes-test-venv/bin/python scripts/evaluate_retained_source_expiry.py \
  --hermes /path/to/pinned-hermes > /tmp/retained-source-expiry.json
/path/to/hermes-test-venv/bin/python scripts/check.py \
  --hermes /path/to/pinned-hermes \
  --hermes-python /path/to/hermes-test-venv/bin/python
git diff --check
```

[机器可读报告](retained-source-expiry-report.json) 的六个阶段全部通过：到期前、恰好到期、到期后、清理、正常重打包及中断重打包。报告记录十二次新进程原生召回观察及三个独立终态验证进程。原始两条目标在到期前被召回，恰好到期时被排除；清理后，历史接受回执仍为 active/修订 1，当前墓碑则为 forgotten/修订 2。来源游标仍为已完成序号 1。随后符合清理条件的另一条记录在清理重试中保持 active。本次运行未发现生产缺陷，也没有修改生产代码。

针对性执行通过了 65 项单元/判定器测试及新增的固定宿主原生契约。固定版本契约测试套件会实际执行本验收链，而不只依赖提交的报告。完整汇总检查、独立最终审查、精确 head/main CI 和下载包证据记录在 Issue 与 PR 中；报告中的本地代码提交不是部署或已发布版本标识。

## 限制

不使用模型、提供方凭据、外部连接、安装、运行中的 Gateway、个人数据或桌面电脑。原生传输夹具不构成实时认证或投递验收。生产存储仍为明文；逻辑遗忘与重打包不保证物理介质擦除，保留的旧文件、原生历史、备份、导出或先前返回的上下文仍可能包含文字。抑制是精确匹配保护，不是对转述的语义擦除。本证据不完成 #46、一般语义召回、远程适配器迁移、配置模型的实际有用性或生产部署。
