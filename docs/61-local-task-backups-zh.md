# 显式本地任务备份

[English](61-local-task-backups.md) | 简体中文

## 状态与范围

这是 #17（E2.1/E8.3）已实现的开发切片，不代表完整备份/恢复或 M1 验收。本地操作员可以创建和检查当前配置分区 `tasks.sqlite3` 的一致独立快照。内容包括任务文本、历史回执、修订号、依赖边和保存的原生观察记录；不包括记忆、登记/授权、凭据、宿主会话、原生 Kanban 状态及其他数据库。这不是整个配置分区的备份、加密保险箱、跨分区迁移，也不授权重放外部操作。

只有原生本地 CLI 暴露此操作。没有对话命令、模型工具、调度器、网络传输、自动备份或自动恢复。必须已显式选择现有 `mode: local_tasks`，每次命令都重新检查模式和绑定分区。不选择新配置或提供方。

## 使用方式

```bash
hermes personal-agent task-backup create --name before-upgrade
hermes personal-agent task-backup inspect --name before-upgrade
```

名称为 1–64 个 ASCII 字母、数字、下划线或连字符，以字母或数字开头。不接受任意目标路径或覆盖选项。文件存放在当前分区的 `plugin-data/hermes-personal-agent/task-backups/NAME.sqlite3`。目录为私有（0700），快照为私有普通文件（0600、单硬链接）。拒绝已存在的不安全文件或目录，绝不自动修复。不输出私有路径或任务正文。

两个命令都返回 `personal.task-backup.v1` JSON，包括名称、任务数据库版本、结构/完整性结果、任务/回执/事件/依赖数量、字节数及 SHA256。快照未变化时，成功的 `inspect` 返回相同元数据。摘要可与另行保存的回执比较以检测字节变化，但不能证明所提供数据库的真实性或可信性。`automatic_restore: false` 明确区分快照与可恢复的整分区导出。

## 一致性与失败行为

创建时只读打开已有任务数据库并开始读事务。在不初始化、迁移或 checkpoint 源库的情况下，检查精确的当前结构并执行 SQLite 完整性及外键检查。SQLite 备份 API 将同一快照（含已提交 WAL 内容）复制到私有临时文件，输出转为 DELETE 日志模式，关闭、检查、计算摘要并同步，再以不覆盖方式原子发布。返回成功前同步目录。

源快照建立后提交的写入不会部分混入备份。备份是时间点视图，不保证是命令返回时的最新状态。长读事务可能延迟回滚日志模式下的写入，因此备份不宜频繁。支持最多 512 MiB 逻辑数据库页/输出，处理预算为 30 秒并有有界 SQLite 锁等待。这不保证实时截止，也不保证任意文件系统的断电持久性。

名称已存在时返回 `backup_exists`，绝不覆盖。存储不存在时返回 `backup_not_found`，不会创建任务库。外来、修改或非当前结构均拒绝处理。检查快照时拒绝任何 journal/WAL/SHM 旁文件。发布前超时或验证失败不会留下已命名备份；正常清理会删除临时文件。进程被终止可能留下私有 `.pending-*` 文件，它不是完成的备份，也不会被自动接纳。发布后目录同步或结果传递失败时，应先检查同名快照再决定重试；不能假设失败代表文件不存在。不自动重试或清理用户快照。若进程在链接发布后、临时名称删除前退出，已命名快照和 `.pending-*` 别名可能指向同一 inode。检查会有意返回 `unsafe_storage_file`，直到操作员核实匹配 inode/所有权，并离线仅删除该临时别名。不要删除未经核实的链接或绕过硬链接检查；核实源库后也可以使用新备份名称。

文件系统检查覆盖预先存在的符号链接、硬链接、非私有文件和可被其他用户写入的目录；不能隔离恶意同 UID 或同进程代码的文件竞争。快照是明文，即使实时任务已修改，也可能保留历史文本。保留期限和后续共享由用户控制；禁用/卸载不会删除快照。

## 恢复边界与验证

没有命令替换实时存储或整体导入旧快照。下文介绍选择性复制到新任务。恢复旧任务状态可能复活终态任务、旧修订或原生引用；完整恢复需要独立的先停止再启动且理解授权的流程。不要把备份覆盖到运行中的分区，也不要借此触发旧外部工作。目前它是供主动离线检查的已验证恢复材料，不是自动恢复功能。

合成测试覆盖 DELETE/WAL 快照、并发提交、隔离测试副本中的完整数据与回执重放、安全发布、重复名称、不安全文件、不修改源库的结构拒绝、损坏/旁文件、大小/时间限制、发布后同步失败及 CLI 错误脱敏。固定宿主测试覆盖原生注册、创建、重载/检查和实时模式撤销。本切片不使用个人数据、真实模型、Gateway、提供方调用或 MacBook。准确数量和 CI 对应最终提交，#17/E8 的更广泛验收仍开放。

## 历史恢复读取

现在可通过显式本地 CLI 浏览并读取历史任务字段，而不替换运行中的数据库：

```bash
hermes personal-agent task-backup tasks --name before-upgrade --sha256 DIGEST --limit 10
hermes personal-agent task-backup tasks --name before-upgrade --sha256 DIGEST --after TASK_UUID
hermes personal-agent task-backup show --name before-upgrade --sha256 DIGEST --task-id TASK_UUID
```

使用 `create` 或 `inspect` 返回的完整小写 SHA256。每次分页或读取单个任务都会先复核摘要，再返回内容；备份变化时返回 `backup_changed`。这将分页绑定到选定的字节内容，但不证明来源可信。没有任意路径、模型工具、原生对话命令或网络上传。仍执行当前 profile 和模式检查。即使当前任务数据库丢失，也能读取有效的指定备份，读取不会重新创建当前数据库。

`tasks` 按从新到旧顺序返回 ID、标题、保存时的状态/版本、到期日、项目和工作状态，使用不透明任务 ID 游标，默认 10 项、最多 20 项。`show` 返回选定任务保存的字段，包括详情和备注。两者均不返回回执正文、依赖边或原生观察元数据。返回文本是历史不可信数据，不是指令、当前任务状态、所有者权限或重放副作用的许可。备份之后已完成或修改的任务在当前库中保持不变。已从当前库编辑移除的内容仍可能存在于备份和终端输出中；这是明确请求的恢复检查，不是遗忘或重新激活。

所有读取保留私有路径、精确 schema、完整性、附属文件和处理预算检查。计算摘要及读取记录时保持 SQLite 读事务，防止普通 DELETE 日志写入者在两个步骤之间提交不同快照。仍不承诺隔离恶意同 UID 代码的文件系统竞争。选定记录超过 32,000 存储字节，或历史结果超过 80,000 个 ASCII 序列化 JSON 字符时，整次失败，不返回部分结果。`invalid_cursor`、`not_found`、`backup_record_too_large`、`backup_result_too_large` 是明确的读取失败。SQLite 和路径错误会脱敏。不会初始化、迁移、修改任务、重放回执、导入或恢复。

检查和恢复读取现在会在打开文件前拒绝非 DELETE 的 SQLite 文件头模式（`backup_not_standalone`）。即使修改为 WAL 模式的备份正常关闭且起初没有附属文件，也可避免 SQLite 创建 WAL/SHM 文件。

## 明确恢复为新任务

本地操作者可以预览并将一条选定的历史任务复制到当前配置：

```bash
hermes personal-agent task-backup recover-preview --name before-upgrade --sha256 DIGEST --task-id TASK_UUID
hermes personal-agent task-backup recover-copy --name before-upgrade --sha256 DIGEST --task-id TASK_UUID --request-id recovery-1
```

预览校验快照与任务，只返回允许复制的字段，从不打开或创建实时任务库。它是有用的检查步骤，不是一次性批准令牌：`recover-copy` 本身就是明确的本地操作者命令，可以独立调用。两者都要求所选快照的精确摘要。CLI 保留实时配置、模式和私有文件检查；没有模型工具或会话别名。

复制创建一条修订为 1、具有新 ID 和当前时间戳的**新** captured 任务，进度与完成备注为空，工作状态为正常 ready。只复制标题、详情、可选项目标签和到期日期。绝不导入旧 ID、状态、时间戳、进度、依赖、回执、原生观察或权限。即使历史任务已经完成，结果也是新本地记录，不是撤销原任务完成状态。不替换现有任务，不执行外部工作，也不派发 worker。旧到期日期仍是明确的历史信息，不是新通知请求。这是选定文本恢复，不是数据库恢复或完整配置迁移。`automatic_restore` 仍为 false。

原快照 SHA256、原任务 ID 和规范化复制字段绑定到实时存储的持久请求回执。响应不确定时，使用相同请求 ID 和完全相同的选择重试。成功重放返回原先创建的新任务 ID 和历史修订，不重复创建，也不撤销后续修改。同一键对应不同来源、任务或字段时返回 `idempotency_conflict`；新键代表有意再建一份。任务、`recover_copy` 历史事件和回执一同提交或回滚。不增加架构迁移。

每次重试仍先校验并读取具名源快照。恢复结果确定前，请保持快照不变。若源快照删除或改变，重试会封闭拒绝，而非绕过来源重放回执；此时应查看实时任务，不要随意生成新键。另一个合法名称下完全相同的快照字节代表同一来源。SHA256 绑定内容，不证明真实性。历史文本可能含不可信指令，打开实时库前会按普通任务字段重新校验。明确命令会在终端显示复制文本，不会自动发给提供方。

测试覆盖实时存储缺失时的纯预览、新记录语义、原任务不变、后续完成后的持久重放、来源/键冲突、无效文本/摘要/任务/请求拒绝、事件失败原子回滚，以及真实固定宿主的 CLI 重载与模式撤销。这些是隔离合成测试，不是真机或提供方验收，也不宣称完整备份恢复。

## 描述符生命周期与并发检查（#94）

头部与哈希共用一个禁止跟随符号链接的描述符，直到 SQLite 连接关闭才释放，涵盖 schema、摘要、reader 和连接初始化失败。过早关闭原始描述符会释放进程级 POSIX SQLite 锁，即使读事务仍保持打开。受控的元数据检查、检查和恢复读取在进程内通过不可重入锁串行执行；等待消耗同一协作式截止时间，并以 `backup_timeout` 失败。这可防止重叠的插件读取相互释放锁。实时源文件验证仍只使用 lstat，不打开或关闭源 inode，也不干扰已有本地 SQLite 事务。

合成测试使用真实独立进程的 DELETE 日志写者，检查摘要完成时及历史行读取期间提交被阻止，并在检查关闭后成功。测试还覆盖源锁保留、失败清理顺序和有界并发读取准入。本修复解决摘要与正文一致性，并非声称已经发生损坏。它不协调在同进程中由外部任意打开的快照 SQLite 连接，也不防御恶意同 UID 文件替换。截止时间是协作式的，不会强制中断文件系统调用。恢复语义及全部发布门禁保持不变。
