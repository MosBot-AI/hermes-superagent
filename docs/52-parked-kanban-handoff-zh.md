# 停放式原生 Kanban 交接

[English](52-parked-kanban-handoff.md) | 简体中文

## 范围与启用

这是明确的本地任务到原生卡片交接，不是 worker 启动、通用任务映射或完成证明。默认 `kanban_handoff: false` 禁止创建。启用需要 `mode: local_tasks`、`local_conversation: true`，并明确填写符合 `[a-z0-9][a-z0-9_-]{0,63}` 的 `kanban_handoff_board`。即使使用 `default` 看板也必须显式填写。原生看板跨宿主 profile 共享，不是插件私有存储。

只要启用本地会话，就注册 `/personal-handoff`，即使交接创建关闭也保留记录查看和取消入口。注册及状态查询不导入原生 Kanban、不探测版本、不打开数据库。状态只报告配置，不证明宿主支持已验证。原生来源/会话控制检查不证明操作者是物理人类或已认证的远端所有者。

## 明确操作流程

- `prepare TASK --expected-revision N --request-id KEY` 预览一份准确的任务快照。仅包含标题、详情、任务 ID 和修订，并展示批准的原生根目录、看板及数据库路径。
- `commit ID --expected-digest SHA` 批准该预览而非更新后的任务。预览 15 分钟后过期；重新检查来源修订，并在原生写入前持久提交单次领取记录。
- `list [--limit N --after ID]` 仅返回元数据，不含预览标题或正文。批准摘要之前，须用 `show ID` 或原始 `prepare` 响应检查准确正文及目标。
- `cancel ID --expected-digest SHA` 取消尚未领取的预览，不撤销原生卡片，也不证明远端取消。
- `reconcile ID` 有界只读查询准确交接键，包含已归档卡片。缺失、重复和冲突都明确保留，绝不再创建卡片。

创建的是固定阻塞、无受派者的停放卡片，使用 scratch 工作区语义，不指定项目、父任务或提供商。不派发也不执行工作。已领取或结果不明的操作不会自动重试或重置；换一个键不是恢复不明操作。只有明确从未尝试提交的已取消或已过期预览，才允许用新请求键重新明确 prepare。原请求键保持终态且不能复用；已领取、结果不明或已确认记录继续阻止同一来源修订和目标的重复交接。领取、取消或惰性过期时清除正文，最多保留 1,000 条元数据记录，没有后台过期服务。清除仅指逻辑正文移除，不抹除日志、备份或原生历史。其他已授权原生操作者可以随后解除卡片阻塞；本交接不授予执行权限。

## 原生边界与证据限制

适配器针对宿主提交 `2281116525106e3c109993ccb5dc74d02bfc1427`、已有且 schema 准确匹配的私有原生数据库，以及宿主跟踪连接和 `write_txn`/`create_task` 路径。不调用 CLI、不初始化看板、不迁移或修复存储。原生版本/schema 检查只在操作期间发生，失败时拒绝继续。 打开看板前拒绝已有回滚日志；只有本适配器已核验并持有的 DELETE 模式写事务可以保留本次创建的日志。原生 WAL 安全回退保持不变，测试覆盖原生默认及显式 DELETE 模式。只读观察 SQL 仍可能触发 SQLite WAL 记账，不能声称文件系统绝无变化。固定版本检查在原生导入之后发生，仅验证可信已安装宿主的兼容性，不是针对恶意宿主或同进程插件的执行前完整性沙箱。本地项目标签、依赖、记忆和会话正文都不会导出或同步。

本轮仅使用离线夹具，不宣称真实 Kanban、安装、Gateway 或模型验收通过。现有扫描及安装限制不变。参见[路线图](08-roadmap-and-acceptance-zh.md)、[本地任务依赖](51-project-task-dependencies-zh.md)及 [worker 提案](48-task-worker-proposal-zh.md)，这些是不同的未完成门槛。

[建议性进度同步](53-native-progress-observation-zh.md)为新身份绑定的交接增加明确元数据观察，不派发或自动完成本地任务。

[明确原生结果审阅](58-native-result-review-zh.md)另增操作者决定：检查并重新核对有界原生结果文字后，明确完成本地记录。交接创建与建议性同步仍绝不自动完成任务。
