# 明确把任务拆解为本地子计划

[English](57-task-breakdown.md) | 简体中文

## 把既有任务拆成可操作步骤

`breakdown` 在一笔事务中记录明确提供的步骤，并关联到既有任务。这是用户指示的本地任务操作，不是自动模型转换或 worker 派发。来源任务必须为 captured、有非空项目标签，且不能处于进行中。使用它当前的 UUID 和修订：

```text
/personal-tasks breakdown TASK_UUID --expected-revision N --tasks-json '[{"title":"Prepare draft","details":"Use the agreed outline"},{"title":"Review draft","depends_on":[1]}]' --request-id breakdown-1
```

把 `TASK_UUID` 与 `N` 替换为任务 show 返回值。CLI 使用相同参数的 `hermes personal-agent tasks breakdown`。`--tasks-json` 是有序内联 JSON 数组，不是文件名，须按 shell/客户端正确引用。不接受项目参数：每个新步骤继承父任务的准确项目标签，不是原生 Project ID。既有明确写入激活之后，任务模型写入工具支持同一 `breakdown` 动作；这不允许模型在没有用户指示时自行拆解。

每步使用[原子计划](56-atomic-plan-dependencies-zh.md)字段 `title`、可选 `details`、可选 `due_date` 及可选 `depends_on`。依赖数字指向本次新批次中从 1 开始的位置；允许前向引用，拒绝环、自引用、重复、越界和非整数。不推断顺序。步骤文字和日期须明确提供，不复制父任务私密正文。

## 依赖语义，不是隐藏层级

父任务原有前置全部保留，并由**每一个**新步骤继承。父任务还依赖**所有**新步骤，不只是最后一项。父任务已有前置数量加新任务数量不得超过 20，否则整笔操作失败。既有依赖及同项目限制不变。

新步骤为 captured、修订 1，记录的工作状态为 ready。父任务修订递增一次，工作状态不变。所有新任务、边、元数据事件、父任务更新及共享回执一起提交或全部不提交。

继承使用拆解事务当时的快照：之后修改父任务前置不会传播至步骤，修改步骤前置也不会重写父任务的依赖集合。

这些是可明确编辑的普通依赖边，不是持久且排他的父子层级。步骤可以参与其他明确记录的关系。取消父任务不会取消步骤；完成步骤只能满足前置，绝不自动完成父任务。已取消的前置不算 done。

## 人工跟进流程

1. 检查返回的父任务、步骤 ID 及依赖。
2. 使用 `/personal-tasks ready --project "Exact label"` 查看符合条件的本地任务。新任务记录为 ready 不代表能绕过继承的前置。
3. 另行开展工作，用当前修订及请求 ID 明确记录进度/完成。既有开始和完成门控要求前置已 done。
4. 父任务所有既有前置及新步骤完成后，再检查现实工作是否完成，并明确完成父任务。不会自动推进或完成。

完全相同的重试即使在之后编辑任务，也返回原始持久回执。这是历史，不是当前状态。不确定结果后复用相同键与参数；不要换新键或拆成逐项 capture，避免产生重复任务。

## 范围与剩余门槛

既有任务配置、本地命令准入及已激活模型写入检查保持不变。不增加提供商请求、原生 Kanban 写入、调度、worker 执行、安装重试或 Gateway 动作，不宣称真实模型或已安装宿主验收。它完善任务到子计划的本地记录流程，但不完成 E3.2/E3.3 或[后续编排路线图](08-roadmap-and-acceptance-zh.md)。
