# 私有 Markdown 记忆投影

[English](68-private-memory-projection.md) | 简体中文

## 显式本地操作流程

SQLite 仍是唯一权威记忆存储。生成的 Markdown 文件让用户可以在命令视图之外查看完整记录，不启用导入器、文件监听、模型文件工具或外部集成。

```text
/personal-memory projection-status
/personal-memory projection-refresh
/personal-memory projection-disable
/personal-memory --json projection-status
```

首次显式刷新启用投影。状态、刷新和停用返回结构化元数据，不修改模型工具 schema，也不赋予模型调用这些操作的权限。既有本地记忆准入和 profile 检查仍然适用。查询状态不会启用投影或生成 Markdown 文件；普通原生存储打开过程仍可能初始化或迁移 SQLite 存储。

唯一目标是当前 profile 私有 plugin-data 目录内、与 `records.sqlite3` 并列的 `memory/records.md`。不接受任意输出路径，不修改 Hermes 的 `MEMORY.md` 或 `USER.md`。保留暂存文件名为 `.records.md.pending`，它是受管理的恢复状态，不是可编辑文档。要求 POSIX 私有目录及当前用户拥有的普通单链接文件；新生成文件使用 `0600` 权限。

## 快照含义与编辑

文件包含 namespace、权威事件水位、评估时间以及完整 active 记录，包括 ID、revision、来源元数据和到期信息。已到期但仍为 active 的记录保留并标注；已忘记的正文不包含在内。缩进 Markdown 代码块中的带引号 JSON 保持中文可读，同时转义控制字符，避免存储的 Markdown/HTML 变成生成的标题或链接。存储文本不是指令、授权或经过核实的来源证明。

这是快照，不是备份或实时视图。通过状态查询检查 `current`、`dirty`、`stale_by_time`、正式/暂存文件是否存在以及 published/pending 元数据。跨过下一到期时刻即使不产生新事件，也会使快照过时；时钟回退到评估时间之前也会将其标为过时。状态本身只描述一次观察，不能保证之后没有变化。

不要编辑受管理文件。通过显式记忆更正后再刷新。内容 hash 不符合预期表示冲突，不代表允许覆盖。在投影启用期间，不安全文件或冲突也可能阻止权威记忆更改，因为更改前必须安全地使旧视图失效。应由本地操作人员处理文件状况，而不是绕过保护。没有自动刷新或 Markdown 导入。

使用 `projection-disable` 停止管理投影。它在写入隔离范围内核验并移除已知生成目标和受控暂存文件，同步目录，然后移除投影元数据。权威记忆不变。已经停用且不存在未知文件时可以安全重复停用；未知或已编辑文件仍然是冲突，不代表允许强制删除。后续显式刷新可以重新启用投影。

## 发布、修改与恢复

Schema v8 新增持久投影元数据。兼容的可写打开过程会迁移此前受支持的存储；只读访问不能执行迁移。投影启用后，后续权威修改（包括候选接受）必须使用正确绑定的私有文件适配器。裸 backend 不能绕过文件失效处理。

刷新使用两个持久阶段，不是 SQLite 与文件系统之间的原子事务：

1. 在 SQLite 写入隔离范围内渲染权威快照，提交待发布身份、水位、摘要和评估元数据。
2. 再次获取相同写入隔离，核实待发布身份与当前水位，重新生成并核实摘要，然后写入并 fsync 暂存文件、原子替换目标并 fsync 目录，最后提交发布回执。

并发权威更改会使待发布快照失效。在权威事务能够提交之前，它会在同一写入隔离范围内移除已知正式文件和受控暂存正文。因此，暂停的旧渲染器不能在成功忘记后重新发布被忘记的内容。文件失效处理失败会阻止该次权威更改提交；调用方不能把错误当成编辑成功。

崩溃可能留下待发布元数据、暂存文件、缺失的投影，或已生成但最终数据库回执尚未提交的文件。持久 pending 摘要用于区分已知生成内容与未知的已编辑目标。后续显式刷新会协调状态并基于当前权威记录重建，而不是重放旧缓存快照。如果文件已移除而数据库提交失败，可能留下旧权威记录但没有投影；刷新会重新构建。重试结果不确定的写入前先检查当前状态，并在适用时保留原请求 ID 和完全相同的参数。

本机制无法撤回已经打开的文件描述符、复制出的文档、备份或文件系统快照。同一用户恶意修改文件系统不在可信本地部署边界内。投影不承诺安全物理擦除、跨平台支持或真实用户验收。

## 验证范围

验证必须覆盖 schema 迁移与只读拒绝、普通修改与候选接受、幂等重试、刷新/忘记并发、崩溃边界、待发布恢复、手工编辑文件、不安全路径/链接、仅时间到期导致的过时和渲染注入。离线合成 profile 不是部署证据。实际完成的测试结果和兼容 revision 见关联 PR。
