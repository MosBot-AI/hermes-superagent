# 97. 原生来源审阅工作台

[English](97-native-source-workbench.md) | 简体中文

## 已实现的边界

[Issue #135](https://github.com/MosBot-AI/hermes-superagent/issues/135) 在生产插件的 `/personal-memory` 命令中新增 `source-list` 和 `source-show`。它们通过公开的 `hermes_state.SessionDB` 读取 API 审阅原始会话行，无需宿主补丁。兼容性目标仍为 Hermes `2281116525106e3c109993ccb5dc74d02bfc1427`。代码进入生产包不代表已经安装、生产部署或完成真实个人数据验收。

仍须满足既有的显式本地记忆配置与来源门禁：`mode: local_tasks`、`local_conversation: true`、`local_memory: true`、已经准入的当前配置档，以及准确的当前 Gateway 支持的 LOCAL 会话绑定。读取器仅以 `read_only=True` 打开该配置档已有的固定 `state.db`。请求不能选择路径、配置档或会话，不能搜索其他存储，也不包含祖先会话、非活动行或已压缩行。缺失、不安全或畸形的存储会被拒绝，不会被创建、迁移、修复或修改权限。配置档选择不是经过验证的用户身份，可信进程内 Python 也不是安全沙箱。

## 列出、选择与查看

在已经准入的本地会话中使用原生命令：

```text
/personal-memory source-list
/personal-memory source-list --limit 20
/personal-memory source-list --limit 10 --after UID --expected-snapshot HASH
/personal-memory source-show UID --expected-snapshot HASH
```

将 `UID` 替换为返回的 `message_uid`，将 `HASH` 替换为该列表的 `snapshot`。UID 是 32 位小写十六进制字符，快照是 64 位。默认每页 10 条，最多 20 条。首页也可选择提供 `--expected-snapshot HASH`。每次使用 `--after` 继续分页以及每次查看都必须提供预期快照。使用返回的 `next_after` 获取下一页；null 表示没有下一页。这是绑定观察结果的分页，不是持久处理游标。

列表仅返回元数据：UID、原始角色、字符数、UTF-8 字节数、精确内容 SHA-256 和吸收 UID 数量，不返回摘录。查看会返回一条选中的完整原始 `user` 或 `assistant` 行及其吸收 UID，不截断或总结内容。两者均报告快照、合格/排除/扫描数量及读取一致性。仍可使用既有的 `--json` 前缀，例如 `/personal-memory --json source-list`。

只有合格的原始行可被选择。工具相关行、展示行、空白内容及保守识别出的压缩摘要都会被排除。引用已识别摘要标记的行也可能被排除；该分类器不能证明作者身份或权限。被排除的行仍参与验证和观察身份计算。身份或谱系存在歧义、畸形时会拒绝整次观察，而不是默默丢弃证据。格式正确但不在合格集合内的 UID 也不可选择。

## 有界观察与新鲜度

每一页和每次查看都读取并验证完整且有界的当前会话活动观察，而非仅验证请求页。上限为扫描 256 行、每行 16,384 字符、合计 65,536 字符，并遵守既有来源谱系限制。超限观察会失败，不会返回部分扫描。宿主解码器可能在插件载荷验证之前分配已存行；这些限制不保证分配前的字节数或内存上限。

摘要绑定配置档的临时文件系统身份、原生会话 revision，以及完整已验证观察中的行 ID、UID、内容和谱系，包括被排除的行。读取器使用公开会话快照并验证其代次，返回前再次检查固定文件绑定。`read_consistency` 区分 `pinned` 和 `generation_validated`。这可检测受支持的观察变化，但不提供任意篡改检测、持久存储身份，也不保证发现绕过这些观察的旧备份替换。

摘要变化会返回 `source_snapshot_changed`；检测到读取期间的代次或绑定变化会返回 `source_generation_changed`。应重新列出、再次审阅，并从新快照中选择，不要盲目替换为新摘要。参数无效、来源不受支持、存储不可用及读取不完整/不受支持也会失败关闭。成功读取不会锁定未来发布，也不保证来源之后仍然可用。

原生斜杠命令派发本身不会将这些请求/回复追加到会话记录。验证目标包含真实的列出到查看派发序列，且原生 revision 保持不变，而不是假设每个命令必然使自己的快照失效。其他会话活动或记录变化仍可能使快照失效。

## 隐私与尚未完成的接受集成

这些操作不写入原生会话或规范记忆，不保留插件侧来源回执，不推进游标，不自动摄取，不提供模型工具，不改变 HTTP 契约，不安装提供方，也不启用 checkpoint-v2。返回的观察不是持久检查点、原生来源回执、稳定存储身份或授权。内容指纹只是精确匹配元数据，不是匿名化、事实核验或许可。来源文本仍是不可信证据。

查看内容可能将私密会话文本暴露到用户客户端或历史中。之后删除原生来源无法撤回已经展示或保留在那里的副本。元数据和指纹也需要私密处理。插件的只读边界不保证客户端会忘记回复。

[保留来源接受](96-retained-source-acceptance-zh.md) SDK 路径具有独立的、以回执为依据的来源与保留契约。此工作台不会调用该路径。将观察来源连接到规范接受仍需要如实标记的来源/稳定身份设计及显式保留授权。不要伪造 `receipt_id`，也不要将观察摘要冒充为 #134 接受实现中的回执。原生来源生命周期、规范保留和客户端副本仍相互独立。

## 验证

运行 `python scripts/check.py` 检查仓库单元测试、静态分析和双语文档。使用独立 Hermes 检出与解释器运行[固定原生开发检查](../README-zh.md#开发验证)，以建立宿主兼容性证据。仅使用隔离的临时 home 和合成会话记录。

审查解析器上限、仅元数据分页、精确完整行选择、快照不匹配/重新列出、排除/歧义行、畸形或不安全存储、行/内容上限、只读行为及当前配置档/会话门禁。原生检查应覆盖真实公开 SessionDB API，以及不改变会话 revision 的实际命令列出到查看派发。在 PR 中记录实际执行结果、精确修订和独立审查；本文不声称测试数量或生产验收通过。更广的来源生命周期、规范接受集成和完整记忆路线图仍未完成。
