# 共享客户端 API 对齐

[English](82-shared-client-api.md) | 简体中文

## 目标与当前证据

用户在 2026-11-10 要求手机和电脑客户端共用一套 REST 契约，可选择 Hermes 或 DSH 后端。客户端选择后端基础 URL，而非不同业务协议。原生运行时仍是权威；本工作不得另建 agent 循环、认证签发服务或授权捷径。

本首切片实现**版本化 schema、共享正反例及失败关闭的 Hermes 元数据**，通过现有本地状态诊断中的 `client_api` 提供。它**没有**注册 HTTP 路由、暴露个人数据、启用原生手机登录，也不表示两端功能已完整对齐。对应 DSH 切片通过现有移动端认证边界增加发现功能；其实现与验收在 DSH issue #23 独立跟踪。原有 DSH 快照、SSE 和审批路由不会自动成为共享契约实现。

## 权威来源与版本

本仓库 `contracts/personal-api/` 是唯一权威来源。`schema.json` 使用 JSON Schema 2020-12，`openapi.json` 使用 OpenAPI 3.1，`fixtures.json` 是可执行共享证据，`manifest.json` 记录三者的 SHA-256 和契约版本 `0.1.0`。JSON 信封使用 `personal.api.v1`。这些机器可读产物无需翻译副本。

DSH 复制完全一致的字节，并另行记录不可变来源提交。消费者在测试前验证全部摘要，不得独立修改复制的契约。变更须一起更新权威产物、fixture 和 manifest，再显式升级消费者。在 `0.x` 阶段，不兼容变更递增次版本，兼容修复递增补丁版本。本切片不声明最终稳定主版本或发布。存放仓库不意味着协议专属于 Hermes。

## 客户端行为与边界

- 将相对路径 `/capabilities`、`/tasks` 解析到配置的 `/v1` 挂载点。后端元数据仅作诊断，不是客户端授权或分支开关。
- 发现信息区分 `supported`、`enabled`、`available`。可用必然已支持且启用；不可用项有原因，可附带类型化处理提示。它们描述**共享端点**，而非原生 CLI 功能或名称相近的旧 API。
- 能力标识是稳定业务操作。初始注册表包括任务列表、审批、变更、原生会话续接和记忆。未来未知能力不得被视为执行许可。
- Hermes 将全部共享业务操作标为不可用。本地操作者权限不能升格为可信 HTTP owner/profile。原始转发头、客户端提供的 owner、私有引导凭据或 hosted 认证布尔值均不能填补缺口。
- OpenAPI 将现有 `__Host-dshpa-mobile` cookie 声明为首个已实现 HTTP 认证绑定，不是共享 token 签发方，也不承诺 Hermes 使用此 cookie。由浏览器管理；本切片不支持原生 App bearer 登录。
- 认证保留在受支持的原生边界。未来认证发现或跳转描述必须保持提供方回调、撤销与凭据生命周期；API 门面不能凭空制造兼容的手机登录。
- JSON 轮询是基础设计。SSE 可以加快更新，但正确性不能依赖它。发现中的传输标志描述已实现的共享表面，而非旧传输是否存在。
- 拟议任务页最多 64 条，明确 `consistency: live`，不是不可变快照。任何适配器在实现并测试授权分页和重置行为前，都不能宣称 `tasks.list` 可用。DSH 现有 64 条快照不是完整列表。
- ID、revision、cursor 对客户端均为不透明值，不建立授权。原生 cancelling 操作不能映射为取消完成；对账不确定状态仍为 `unknown`。平台专有原因可以解释不可用，但不能增加权限。
- 类型化错误区分认证、无效 cursor/输入、拒绝访问、能力不可用和暂时内部故障。`retryable` 从不授权重复副作用。未来写操作必须先有自己的幂等、并发、回执及结果未知契约，再启用。

## 差距矩阵与顺序

| 范围 | Hermes 已观察情况 | DSH 已观察情况 | 所需共享工作 |
|---|---|---|---|
| REST 准入 | 拟议领域 API，未注册领域路由 | Cookie 配对及 Origin 检查的移动监听器 | 经验证的后端适配器，不另建签发服务 |
| 任务读取 | 本地 CLI/模型工具，不是 HTTP 授权 | 脱敏有界快照，无完整分页 | 共享任务投影及作用域分页/恢复测试 |
| 审批决定 | 领域 HTTP 门控未实现 | 现有精确设备绑定响应 | 相同不可变意图语义及重复/竞态 fixture |
| 恢复 | 拟议持久 JSON 变更流 | 现有有界 SSE 任务回放 | 可轮询共享变更，重置/ACL/撤销测试 |
| 会话 | 仅原生运行时续接 | 原生 DSH 协调 | 适配回执，绝不另启 agent 循环 |
| 记忆 | 本地显式启用的原生记忆 | 原生个人记忆实现 | 经授权的共享读写契约，不自动暴露 |

1. 建立本权威契约和摘要校验的消费者发现。作为 Hermes #29 和 DSH #23 的部分证据。
2. 在两端适配器增加作用域任务分页/投影及共享读取一致性测试。Hermes 必须先证明所用宿主模式的可信 HTTP principal 传递；独立读取投影工作可以继续，但不启用 HTTP。
3. 扩展共享审批、操作回执和 JSON 变更/恢复契约。复用现有授权及持久账本，在 Hermes #30/#31 和 DSH #23 下逐个实现有界纵向切片。
4. 会话、记忆、产物及原生 App 认证仅在对应明确门控满足后加入。真机手机、部署 HTTPS、多设备故障验收仍单独保留并明确展示。

## 验证限制

单元测试验证两端共享 fixture 形状、反例、产物摘要，以及本地任务工具已启用时 Hermes 诊断仍失败关闭。它们既不建立已部署 HTTP 端点，也不证明生产认证、原生手机回调或完整功能对齐。原有客户端 API 设计仍为未来操作语义提供参考；本共享 wire 基线仅对明确规定的公共发现、错误和任务页形状优先。
