# 原生时间规则预览

[English](62-native-schedule-preview.md) | 简体中文

## 显式本地规划，不是提醒

`hermes personal-agent schedule-preview --schedule '0 9 * * *' --timezone Asia/Shanghai --after '2027-01-01T08:00:00+08:00' --count 3`

仅操作者可用的原生 CLI 复用固定 Hermes 的 `parse_schedule` 和 `compute_next_run`，从明确带偏移的参考时刻和 IANA 时区展示最多 20 个名义候选时刻。只读模式下也可用，但不注册模型工具、斜杠命令或远程 API。它既不读取个人 job 记录，也不创建、修复、运行、取消或发送 job。`scheduled` 与 `delivery_verified` 始终为 false。切换 profile、在托管 worker 中执行、使用非文件配置后端，或插件卸载后调用保留的处理器，都会拒绝。

支持原生重复间隔（`30m`、`every 2h`）、cron 表达式及原生星期短语，以及明确带偏移的绝对 ISO 单次时刻。裸时长表示重复而非单次。拒绝 `in 30m` 这样的相对单次和不带偏移的单次时间，因为其原生解析会使用当前 profile 时钟，而非提供的参考时刻。绝对单次直接与参考时刻比较，不宣称符合原生错过窗口或宽限条件。

每个候选包含原生时间、UTC、本地时间、`fold` 和 `wall_time_valid`。间隔按真实经过的时间跨越夏令时。Cron 候选遵循实际宿主算法；不存在的春季跳时时刻会标为 `dst_gap_requires_review` 并停止预览，不悄悄改变用户指定时刻。秋季重复小时保留明确偏移与 fold。这**不是**对真实 ticker、错过补发、重复小时交付、停机、暂停状态或外部回执的模拟。预览成功不代表计划已启用或通知会送达。

## 为什么还没有只读 job 检查器

在 Hermes `2281116525106e3c109993ccb5dc74d02bfc1427` 中，`get_job`/`list_jobs` 调用 `load_jobs`，后者会创建目录，还可能写入 `jobs.json` 修复异常记录。本切片故意不调用这些方法，也不绕过公共接口另写原生存储读取器。创建仍缺少调用方幂等键；取消运行中的执行不会停止未来触发；local 交付仅保存输出，不会通知所有者。E4 的准入、核对和交付门槛仍未完成。

## 证据与限制

单测和固定宿主契约覆盖明确参考时刻/时区、非法及有界输入、重复与绝对时间语义、夏令时缺口/重复小时、卸载/profile 隔离以及 cron 文件不变。原生加载可能在命令执行前初始化普通宿主目录；预览本身相对于加载后的快照进行检查。测试使用临时 profile 和合成时间规则，不启动 Gateway、ticker 或外部模型，不是提醒交付验收。
