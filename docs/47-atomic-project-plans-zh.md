# 47. 原子化项目计划录入

简体中文 | [English](47-atomic-project-plans.md)

## 1. 用户流程

把明确要求保存的项目计划一次录入为 1–20 条普通本地任务。所有任务、各自初始历史事件和一份共享重试回执要么共同提交，要么全部不提交。这样，多任务录入被打断并重试时，不会只保存半个计划或重复创建任务。

每条任务仍可通过现有工具独立编辑、回顾、聚焦和完成。共同项目是精确标签，不是原生 Project。没有另建可修改计划实体、依赖图、优先级顺序、worker 派发或提醒。计划可以追加到已有标签，不会替换该标签下的任务。允许同名任务，因为文本相同不证明意图相同。

## 2. 原生命令与 CLI

使用现有可信本地任务配置。原生对话命令从第一次尝试起就要求稳定请求 ID：

```text
/personal-tasks plan --project "演示发布" --task "准备初稿" --task "审阅初稿" --request-id launch-plan-1
/personal-tasks list --project "演示发布"
/personal-tasks review --on 2030-01-01 --project "演示发布"
```

原生命令默认返回易读文本及精确 ID/修订。使用 `/personal-tasks --json plan ...` 前缀可获得 JSON。CLI 使用 `hermes personal-agent tasks plan` 和相同参数；默认 JSON，`--format text` 选择易读视图。计划回执保留输入顺序，普通任务列表仍按原有的最新优先顺序排列。两种顺序都不构成依赖或优先级语义。

需要详情或明确日期时，用 `--tasks-json` 替代重复的 `--task`。其值是内联 JSON 数组，不是文件名。请按所用 shell/平台正确引用；原生命令使用 POSIX 引号规则。

```text
/personal-tasks plan --project "演示发布" --tasks-json '[{"title":"准备初稿","details":"使用已确认的提纲"},{"title":"审阅初稿","due_date":"2030-01-02"}]' --request-id launch-plan-2
```

两种形式不能同时提交。未知字段或嵌套的身份、批准、项目、依赖和重试键字段会被拒绝。JSON 对象重复键、非 JSON 常量、无效日期、超限输入或任一无效任务，都会在打开存储前拒绝整个计划。

## 3. 现有模型工具

在现有 `/personal-tools enable-write` 激活之后，请主代理把你想保存的任务录入指定项目标签。已有 `personal_tasks_write` 工具现支持：

```json
{
  "action": "capture_plan",
  "project": "演示发布",
  "tasks": [
    {"title": "准备初稿", "details": "使用已确认的提纲"},
    {"title": "审阅初稿", "due_date": "2030-01-02"}
  ],
  "request_id": "launch-plan-2"
}
```

此工具复用单任务写操作的有效轮次/profile/会话/路由检查。仅有读激活不够。不会调用第二个规划模型、切换提供器、向 worker 授权或扩大记忆访问。结果按已有任务工具披露进入已配置模型；真实自然语言验收仍待完成。

每条任务必须有标题，可含详情和到期日期。标题上限 240 字符、详情 5,000、项目标签 80。标准化后的完整请求包含项目、请求 ID、默认空详情和 JSON 转义，必须不超过 32,000 个 ASCII 序列化字符。日期必须明确指定，不推断时钟/时区。回执返回每条任务的规范 UUID、初始修订和已有记录字段。

## 4. 重试与恢复

结果不确定时，复用相同请求 ID、任务顺序和项目。重放已提交计划会返回原保存回执，不再次插入任务，即使已经重启或单条任务后来被修改。请读取各任务的当前状态：回执可能描述旧修订。重排条目、改变字段/项目或重用单任务写键，会产生 `idempotency_conflict`，不改变任何数据。省略详情与显式空详情字符串标准化结果相同。

不要把结果不确定的计划拆成单条 `capture`，也不要仅为重试而生成新的计划键。那是新操作，可能制造重复。只有确实有意保存另一份新计划时才使用新键。无效输入没有部分效果；存储中断可能使响应结果不确定，因此应检查/重试原请求，而不是假设已经失败。

任务 schema 保持 v4。已有存储和历史回执不需要新迁移。每条新任务获得修订 1 的 `capture_plan` 元数据事件，不向历史增加旧任务正文。计划回执与普通录入回执一样包含任务文本，是本地明文，不是秘密存储。

## 5. 为什么 worker 派发仍独立处理

固定版本的公共原生生命周期接口不是按插件隔离的执行契约。空 `allowed_toolsets` 会变成继承工具；不支持单次启动超时和逐工具屏蔽。宿主委派策略可在收窄请求之后追加继承的 MCP 工具集或递归委派能力。请求中的角色是兼容元数据，构造器根据深度/配置决定实际角色。这些是宿主语义，不是本插件新授予的权限。

因此，计划录入不会启动一个声称“无工具”的 worker，不会改变宿主隔离/委派设置，也不声称完成 E3.3/E3.5。未来受控派发流程还需要核验实际工具、固定路由/回退约束、持久尝试/对账和取消语义。“只做规划”等提示文字不能替代这些控制。

固定源码：[公共子代理生命周期](https://github.com/NousResearch/hermes-agent/blob/90d6b98fd86d20981ee06ddd5b7d93e4320f26a4/agent/subagent_lifecycle.py)、[子代理工具集](https://github.com/NousResearch/hermes-agent/blob/90d6b98fd86d20981ee06ddd5b7d93e4320f26a4/tools/delegate_tool_toolsets.py)及[子代理构造](https://github.com/NousResearch/hermes-agent/blob/90d6b98fd86d20981ee06ddd5b7d93e4320f26a4/tools/delegate_tool.py)。

## 6. 验证与限制

测试覆盖嵌套验证、转义预算、持久有序回执、相同请求并发、冲突键、插入/事件/回执阶段失败时的整笔事务回滚、批次未完成时进程退出、重启重放及 schema 不变。原生测试把命令/模型/CLI 写入接到项目回顾、单任务进度和任务聚焦，覆盖只读拒绝、其他会话/worker 范围拒绝和插件重载。

两个固定宿主边界测试验证空允许列表的继承行为，以及配置相关的 MCP/编排工具追加，不构造真实 worker，也不解析凭据。所有测试使用合成数据和临时 profile。本切片不涉及 Gateway socket、提供器请求、真实账户、main 分支更新或生产部署。已有发布门禁仍为 blocked。
