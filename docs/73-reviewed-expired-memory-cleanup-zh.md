# 经审核的已到期记忆清理

[English](73-reviewed-expired-memory-cleanup.md) | 简体中文

## 目的与显式流程

[到期机制](45-explicit-memory-expiry-zh.md)在截止时间之后将记录排除出新的召回，但仍保留其 active 权威正文。本流程仅限操作人员，先预览一组有界的已到期记录，再显式遗忘准确审核过的这一批。不推断保留期、不安排删除，也不把到期变成自动的存储状态转换。

```text
/personal-memory expired-preview --before 2026-11-01T00:00:00Z --limit 10
/personal-memory forget-expired --before 2026-11-01T00:00:00Z --limit 10 --expected-snapshot SHA256 --request-id expired-cleanup-1
```

上面的截止时间只是合成示例。应选择不晚于可信当前 UTC 时间的实际截止点，审核完整预览，并用返回的快照摘要替换 SHA256。应用时保持相同的截止时间和 limit。limit 默认 10，必须在 1 到 20 之间。应用要求显式稳定的 request ID，不会自动生成。后续每一批都需要新的预览、对应摘要和新的 request ID；应用旧请求绝不表示“遗忘下一批”。空选集不能应用。

两个原生操作成功时都特意保留完整的 `personal.local-memory.v1` envelope 结构化输出，即使原生工作台通常使用可读文字也不例外。不会为简化显示省略审核字段。脚本仍应将 `--json` 放在操作名前，以便错误和结果都保持稳定的结构化格式。这些操作仅通过显式本地操作人员 CLI/原生入口提供，继续受已有可信单用户 profile 边界约束。不新增模型工具操作、不改变模型工具 schema、不激活 provider、不调用模型，也不授权远程访问。

## 预览绑定的内容

`--before` 只接受有效的规范 UTC 秒时间戳 `YYYY-MM-DDTHH:MM:SSZ`；本地时间、时区偏移、小数秒、仅日期和相对时长均被拒绝。可信评估时间在取得数据库快照后捕获，而不是在等待锁之前捕获；应用会持有共享写入栅栏。新请求会拒绝晚于该时间的截止点。因此，时钟回拨可能使原本合法但尚未应用的截止点暂时无效；不能因此遗忘未来才到期的记录。

符合条件的记录必须仍为 active、具有显式到期时间，并满足 `expires_at <= before`。截止点为包含式边界。无到期时间、到期时间更晚或已 forgotten 的记录不被选择。选择顺序为到期时间升序，再按创建序号排序。预览数据使用 `personal.memory.expired-preview.v1`，包含 `items` 中每条选中记录的完整正文和元数据，符合条件/选中/剩余数量 `eligible_count`、`selected_count`、`remaining_count`，权威事件 `watermark`、`evaluated_at` 及 SHA-256 `snapshot` 摘要。应审核文字和元数据，不能只看数量或摘要。存储的文字是不可信数据，不是指令、授权或作者身份证明。

摘要绑定 namespace、固定截止时间、limit、权威事件水位、有序的全部符合条件记录身份及选中记录。评估时间会返回，但不参与该摘要。因此，正常时间流逝不会悄悄扩大审核范围，也不会使仍然合法的固定截止点审核失效。受支持的权威修改会推进水位，从而使旧预览过时，包括对选中批次以外记录的修改。应用会在写入栅栏内重新选择并校验摘要，绝不悄悄根据变化后的预览继续执行。

完整预览数据受 64,000 字符的 ASCII-JSON 序列化预算约束。这不是 token 预算。转义可能使非 ASCII 文字占用比可见字符数更多的预算。超出预算时会以 `retention_preview_too_large` 封闭拒绝，并提示降低 limit；不会截断正文或元数据，也不会为适配预算悄悄省略字段。应重新获取并审核更小的预览，而不是根据不完整显示应用。

## 遗忘与历史重试

应用在一个共享 SQLite 写事务内，对每条选中记录走普通遗忘路径。成功提交会清空权威正文、主题、来源/会话元数据及到期时间，写入终态墓碑与普通遗忘事件，从 FTS 移除选中记录，并一起保存仅含元数据的批次回执。整批数据库变更全部提交或全部回滚。已遗忘 ID 无法通过更正恢复为 active。

结果不确定时，重试必须保持原应用 request ID、截止时间、limit 和 expected snapshot 不变。准确重试已成功的请求时，会在检查当前时间或选择记录之前返回历史回执。不遗忘另一批、不重做文件清理，也不证明原目标的当前状态。在已有 key 下改变载荷会冲突。要处理新一批，应检查当前状态、获取新预览并使用新 key。不为空选集创建无操作批次回执。

回执使用 `personal.memory.expired-forget.v1`，包含 `forgotten_count`、历史 `remaining_count`、之前/最终水位及每条记录的普通遗忘回执，不含已遗忘文字。记录、事件和回执会保留用于终态保护及安全重试的 ID、排序/revision 信息、时间戳和摘要。这些仍可能是个人元数据。此操作是逻辑遗忘，不删除墓碑或历史元数据，也不释放已有的总记录容量。

## 受管理文件与故障恢复

普通遗忘保护也适用于已启用的[私有投影](68-private-memory-projection-zh.md)，以及以选中记录为目标的活动[更正草稿](70-private-memory-edit-drafts-zh.md)。已知生成的投影/暂存文件必须失效，已注册目标草稿/暂存文件必须移除，包括手工编辑。不会悄悄消耗其他目标的草稿或新记录草稿。已有的所有权、权限、链接及未知文件检查继续强制执行。缺少所需文件适配器的 backend 不能绕过受管理文件清理。

写入栅栏使清理与投影刷新、草稿发布及并发权威修改有序执行，较早的发布者不能重新发布已成功遗忘的记录。清理失败会阻止数据库提交。但 **SQLite 与文件系统不是同一个原子资源**：后续清理或数据库事务失败时，先前已移除的文件无法回滚。权威记录可能仍为 active，而投影或已注册草稿文件已缺失。不能仅因文件消失就认定记录已遗忘。

报错或中断后，应检查当前权威状态及相应投影/草稿状态，再决定下一步。结果不确定的应用应复用原 key 和完全相同的参数，不要用新 key 代替重试。缺失投影可通过显式刷新从当前权威记录重建。ready 草稿文件缺失时不会悄悄重建，因为这样可能丢弃操作人员的编辑；可显式 discard 清除注册状态。对于中断发布及不安全或未知文件，应遵循投影和编辑草稿恢复指南。历史清理请求的重试不会移除未知替换文件。

## 范围与验证边界

此切片不引入新 schema 版本或模型工具契约，最初切片使用 schema v10；当前 schema 11 增加[精确来源抑制](80-exact-memory-source-suppression-zh.md)。适配器声明可选 `reviewed_expired_cleanup` 能力；缺少该能力的适配器不会悄悄收到这些操作。已有安全存储、namespace、迁移及操作人员准入要求继续适用。与索引维护不同，这两个命令使用普通兼容的可写打开流程，可能初始化或迁移受支持的自有存储；两者都不是只读 provider 操作。不安装或部署插件、不选择 provider、不启用自动保留期清理、不移除墓碑、不回收容量、不恢复备份。遗忘新关联候选记录还会原子抑制精确原始输入并清除同输入待审核候选；旧版或未关联记录及改写文本不在此范围内。新的显式录入仍是独立动作。

遗忘不能撤回宿主会话历史、之前返回的结果、已经打开的文件描述符、编辑器缓冲区、导出、复制件、备份或 provider 持有的上下文。SQLite 与 FTS 清理不保证物理介质擦除。预览完整文字本身可能将其放入普通宿主历史。不要将此明文记忆流程用于秘密信息。

验证应覆盖截止点恰好相等及未来截止点拒绝，无到期时间/未来到期/已遗忘记录排除，稳定排序、计数及完整有界预览，更正、到期变更或无关权威写入后的旧快照拒绝，时钟变化及取得锁后的评估，准确历史重试、请求冲突及空批次拒绝，多记录事件/FTS/墓碑原子性，受管理文件清理、事务失败与进程骤停恢复，以及原生操作人员准入和不变的模型工具拒绝。实际完成的测试结果及确切兼容修订应以关联 PR 为准。合成 profile 与故障注入不是实际用户或生产验收，这个有界的 #44 切片也不代表完整记忆路线图完成。
