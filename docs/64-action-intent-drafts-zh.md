# 持久化内部 ActionIntent 草稿

[English](64-action-intent-drafts.md) | 简体中文

## 范围与权限边界

此 E1.2 前置切片在调用方保护的专用 SQLite 连接上实现内部 `ActionIntentStore.prepare`、`inspect` 和 `cancel`。它为未来审批集成提供持久请求标识与精确元数据绑定，不批准、授权、发送、执行、登记人员、推断资源归属或适配宿主审批。没有 CLI、模型工具、hook、HTTP 路由或自动存储 opener 暴露此存储。E1.1 与完整 E0.4 覆盖仍是生产受控副作用的前置条件；#15 尚未完成。

owner/profile/request 标识与 operation 名称是有界的不透明管理选择器，不是已验证身份或权限。调用方必须独立建立连接、作用域、策略/资源版本和可信时钟。任意进程内 Python 与直接数据库修改不在此前置模块的信任边界内。恢复或克隆的数据库不是当前权限证据。不存在 `approved: true`、grant 签发、副作用回调、执行状态或重试引擎。

## 精确绑定与最小化

准备操作接收精确的 owner/profile/request 选择器、operation、策略 revision、epoch、资源 revision、UTC 到期时间，以及非空的目标/内容**字节**。目标最多 4,096 字节，内容最多 65,536 字节。适配器必须在调用前定义精确序列化；此模块不规范化空白、JSON 键顺序、接收人别名、URL、币种或 Unicode。同一请求 ID 下，语义相同但字节不同也会冲突。

原始目标和内容在内存中以不同版本化域计算摘要，不进入存储或返回元数据。另一个版本化绑定摘要覆盖这两个摘要及所有拟议选择器/版本/到期字段，包括请求 ID。存储保留选择器、operation、版本、摘要、时间戳、状态和 revision。事件仅保留选择器、revision、固定结果和时间戳。不主动持久化凭据、消息正文、目标文本或原始错误文本。调用方不得把秘密放入选择器或 operation 名称；语法校验不等于敏感数据分类。

摘要不是加密或匿名化：低熵值可被离线猜测，相等性也可能暴露关联。临时输入字节仍受调用方内存/生命周期行为影响。这不是秘密保险库。查看摘要不能还原供人审阅的动作，也不能取代未来可信审批界面展示精确动作。

## 状态、时间与重试

唯一状态转换是 revision 1 的 `draft` 到 revision 2 的 `cancelled` 或 `expired`。没有更新、续期、重新激活、覆盖拒绝或删除。新草稿必须晚于可信准备时钟采样到期，且不超过其后 24 小时。UTC 必须是使用 UTC 单例且无 fold 的精确内建 datetime。可信时钟在取得数据库事务锁**之后**采样，不能作为请求参数提供。早于创建时间的时钟会被拒绝。到期一旦被观察并提交，即使之后时钟回退仍保持终态；这不能防御恶意时钟或整个数据库的回滚。

精确的准备重试返回当前元数据，包括终态。同一 owner/profile/request 键改变任何绑定字段都会冲突，即使已经取消或到期。不同命名空间可以使用相同请求 ID，但不表示共享权限。重试不会增加重复审计事件。新请求 ID 不代表可以重新提交结果不确定的外部动作；此模块从未发送动作。

`inspect` **不是纯读取**：它可能原子地保存到期状态。`cancel(..., expected_revision=1)` 只取消尚未到期的草稿。精确取消重试返回相同取消结果。如果到期先发生，则返回 `expired`，不虚称已取消。它不能停止宿主 worker、暂停调度器或撤回交付。其他 expected revision 会被拒绝。

## 事务、完整性与限制

每次操作均使用 `BEGIN IMMEDIATE`，校验精确的自有 DDL/application/schema 版本，并拒绝临时遮蔽对象或未知 schema 增项。新的空专用数据库必须显式初始化，不迁移或接管现有领域存储。intent 变更和元数据事件一起提交。返回记录前校验事件链、绑定摘要及持久化元数据。COMMIT 结果不确定时应检查或精确重试同一请求，不创建新 ID。

每个数据库最多保留 **1,000 个 intent**，每个最多两个事件。达到容量后拒绝新草稿，不驱逐旧记录或已取消记录；精确重试、检查和取消仍可用。没有受支持的清理、导出、恢复或还原流程。到期是状态截止，不是删除期限；元数据可能无限期保留。COMMIT 前崩溃会回滚记录与事件；COMMIT 后崩溃可能留下持久记录，即使调用方未收到响应。此语义不证明任意调用方数据库配置或存储硬件的断电持久性。

错误仅包含固定代码，不含动作内容、摘要、选择器或 SQLite/时钟异常文本。审计仅是草稿账目，不证明认证、批准、实际副作用、交付，也不是完整的拒绝尝试日志。

## 验证与剩余工作

合成测试覆盖精确字节绑定、作用域重试标识、取消/到期终态、时间校验、容量拒绝、损坏元数据/事件链、严格 schema、事件/COMMIT 失败、真实 SQLite 并发准备，以及 COMMIT 两侧的进程退出。原生包测试验证内部模块保持未暴露，不能激活生产权限。本切片未使用网络、provider、真实账户、Gateway 或真实动作。

剩余门禁包括已验证 owner/接收通道上下文、可信人工审批回执、各动作种类经审阅的内容/目标 schema、当前策略/撤权准入、资源归属、原子执行/outbox 对账、如实处理在途取消、隐私/保留运维与完整替代路径约束。草稿账本通过不代表 E1 完成，也不启用受控外部动作。

## 显式原子批量取消

`cancel_many(requests)` 在一个事务中取消 1 到 100 个显式选定的现有草稿。每项必须且只能包含 `owner_id`、`profile_id`、`request_id` 和先前检查得到的 `binding_digest`。所有项目必须属于相同 owner/profile，请求 ID 不重复，摘要格式有效且精确匹配。不支持通配符、发现、隐式包含新建草稿或跨配置取消。范围标签及持有摘要仍不构成身份认证或授权。

存储在同一写锁下先验证所有选定记录、事件链和绑定，再修改任何状态。任一项目缺失、损坏或不匹配都会拒绝整个批次。整个批次使用同一个可信时钟采样：过期草稿变为 `expired`，有效草稿变为 `cancelled`，原有终态保持不变。结果保持输入顺序，如实返回混合终态。响应丢失或进程重启后的精确重试不会追加重复事件。调整显式重试顺序或缩小集合不会授权任何新项目。并发重叠批次串行执行；未选中的新建草稿保持不变。

所有状态和审计变更一并提交。处理后续项目或 COMMIT 时出错会回滚此前的变更。COMMIT 后进程退出可能导致整个批次已提交却没有响应；调用方应检查或使用相同绑定精确重试。这不是持久化批次回执、全局策略撤销、审批取消或正在执行的外部操作中断。不增加存储模式、入口或生产能力。保留 1,000 条意图的容量限制不变；取消不会释放容量。

合成验证包括无效选择、混合范围、摘要变更、过期、终态重试、事件/提交失败、并发重叠事务，以及写入中间事件后、COMMIT 前后突然退出进程。固定宿主包契约检查相同的内部行为和未改变的生产拒绝。上述检查不证明硬件断电持久性或外部取消能力。
