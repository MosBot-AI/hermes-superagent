# 项目任务整体改期

[English](71-project-task-reschedule.md) | 简体中文

## 预览整个变更

项目延期一周不应要求逐条修改任务并承担部分成功的风险。本显式本地操作人员流程会预览并原子平移一个精确项目标签下活跃且已有日期的任务。

```text
/personal-tasks project-reschedule-preview --project "Launch" --days 7
/personal-tasks reschedule-project --project "Launch" --days 7 --expected-snapshot HASH --request-id launch-delay-1
```

使用预览实际返回的 snapshot。负数表示提前日期。对应 CLI 前缀是 `hermes personal-agent tasks`；原生输出默认为可读文本，可在前面添加 `--json`，CLI 则支持 `--format text`。应用必须提供显式且稳定的请求 ID。两条命令都不询问模型、不联系看板、不修改原生卡片、不安排提醒，也不发送通知。

精确项目标签沿用现有区分大小写的校验：1–80 字符，无首尾空白或控制字符。未分配任务不是一个项目标签。`--days` 必须是 -3650 至 3650（含边界）的非零整数。平移的是公历**日历日期**，不是经过的小时数、时区、工作日、节假日或提醒时刻。不推断当前日期。

预览包括所有受影响任务的 ID、标题、revision 和旧/新到期日，以及因已完成/已取消或活跃但没有日期而被排除的数量。不自动分配日期。活跃指 `captured`，包括已记录的 ready/in_progress/waiting/blocked 工作状态；日期平移不会解除阻塞或启动工作。已有项目组即使没有符合条件的任务也可预览，但应用会被拒绝。

每个项目最多包含 100 个任务，包括排除项。完整 ASCII 转义 JSON 预览数据（不含传输外层封装）必须不超过 16,000 字符（不是 token）；项目组或输出过大会被拒绝，不会截断成部分批准。不包含任务详情、进展说明、结果文字或原生输出。判断日期需要更多背景时，请另外查看单个任务。若整组预览超限，请改用显式单条更新，不要假定此操作只覆盖可见部分。

## 快照、事务与重试

快照绑定精确项目、偏移天数，以及按序排列的完整成员集，包含各成员 ID、revision、状态和到期日，也包括排除项。新增成员、任务移出、revision 变化或终态变化都会令旧预览过时。快照是并发校验，不是授权令牌，也不是跨命令持有的锁。既有 profile 与本地操作人员准入仍适用；模型工具 schema 不获得这项批量写能力。

应用在一个 `BEGIN IMMEDIATE` 事务中重新检查整个项目组。每个符合条件的任务获得平移后的日期、一次 revision 递增、时间戳，以及一条 `reschedule_project` 元数据事件。任何无效日期、溢出、过时快照或写入失败都会回滚整批。超出所支持公历范围的日期会被拒绝。既有任务状态、依赖边、工作状态、说明、解决证据和保存的原生观察保持不变。不根据依赖推断日期先后，也不改变依赖就绪状态。

新 revision 会使已有绑定版本的编辑、授权和快照失效。原生卡片及此前移交证据不会同步或刷新。已提供给模型的上下文不会被重写。

结果不确定时，使用**相同请求 ID 和完全相同的参数**重试，包括原 snapshot。即使后来又有编辑或进程重启，准确重试也只返回历史回执，不会再次移动日期或碰触后来新增的成员。同一键携带不同参数会冲突。新键代表新的变更，不是重试。收到历史回执后请读取任务当前状态。没有自动重试、自动改期、取消外部工作或通用终态任务编辑权限。

没有引入 schema 迁移。与现有任务命令相同，即使逻辑操作只是预览，打开受支持的旧存储也可能执行其正常初始化/迁移。输出限制不等于大型存储的延迟保证。明文本地存储与原生历史仍保留既有隐私限制。

## 验证边界

验证覆盖完整预览和排除项、精确标签和限制、正负偏移、闰日和跨年、溢出、过时成员集/revision、并发、事务中途失败、进程崩溃及历史重放。Pinned 宿主原生命令/CLI 契约在不调用模型或实时 Gateway 的情况下核验解析、准入及可读/JSON 行为。

最终运行数量与精确提交见关联 PR 证据。这是 #40 下的本地任务日期切片，不代表全部 E6/M1 验收完成、生产部署、真实用户验收或提醒投递证明。
