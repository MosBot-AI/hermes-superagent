# E0.8 Online Voice Protocol Comparison

English | [简体中文](voice-provider-protocol-comparison-zh.md)

Official documentation checked on 2026-11-12. The comparison covers GPT-Live, OpenAI Realtime speech-to-speech, and the Gemini Developer API Live interface. It records documented wire behavior and its implications for E0.8. See the [current-pin compatibility inventory](voice-compatibility-inventory.md) for what the Hermes fixtures actually exercised.

## GPT-Live

- **Connection and media.** The application server uses its project API key to exchange JSON session configuration and the client's SDP offer with `POST /v1/live/sessions`. The client applies `transport.sdp` and waits for `session.started`. WebRTC negotiates media and carries application events on a data channel. The vendor also documents a separate server WebSocket on `/v1/live/sessions` with `session.start` and `session.input_audio.append`. The WebSocket uses a fixed format for both directions. It defaults to mono signed PCM16 little-endian at 24 kHz and also supports PCM16 at 16 kHz or 8 kHz G.711 μ-law/A-law. The pinned Hermes host implements the SDP exchange with client delegation configured. [WebRTC guide](https://developers.openai.com/api/docs/guides/voice-webrtc?api=live) · [Create session](https://developers.openai.com/api/reference/resources/live/methods/create) · [WebSocket guide](https://developers.openai.com/api/docs/guides/voice-websockets?api=live)
- **Speech, interruption and delegation.** The application streams input continuously. GPT-Live handles overlapping input and output and decides when to speak or delegate. The application associates `session.delegation.created` with its own context and task state, then sends updates using the delegation ID. Input mute affects provider input. The player or media relay must separately stop or flush output. Output speech screening needs application-side segmentation/VAD, and withheld speech can remain in provider context. The reviewed controls describe local playback and corrective instructions without a played-offset truncation operation. Finishing or cancelling client-delegated work remains the application's responsibility. [Turn ownership](https://developers.openai.com/api/docs/guides/live-migration) · [Session guide](https://developers.openai.com/api/docs/guides/live-conversations) · [Client delegation](https://developers.openai.com/api/docs/guides/live-delegation?delegation-mode=client) · [Playback controls](https://developers.openai.com/api/docs/guides/voice-server-controls?api=live)
- **Recovery and finalization.** `session.closed` provides terminal reason and final usage, including `expired` when the duration limit is reached. When a connection fails before that event, final usage is unconfirmed. The documented fork requires a completed recording stored with project permission. It creates a new connection and session ID and uses recordings retained for 30 days. Otherwise start a new session with permitted text history. A sideband can reattach to a still-live primary session and receives only the preceding three seconds of events. Replayed events keep their original `event_id` where present. This replay does not confirm playback or effects. The adapter must check outstanding backend work before attempting it again. The reviewed fork procedure supplies no replay guarantee for uncertain media or side effects. [Session guide](https://developers.openai.com/api/docs/guides/live-conversations) · [Sideband attachment](https://developers.openai.com/api/docs/guides/voice-server-controls?api=live)
- **Usage and data.** `session.usage.updated` and `session.closed` report cumulative voice seconds. Backend model/tool usage is tracked separately. WebRTC session creation itself bills initialization time, credited once the session starts. Optional completed-recording storage defaults off. OpenAI lists default abuse monitoring retention of 30 days and conditional Zero Data Retention (ZDR) eligibility. ZDR forces `store` off and removes recording download and fork support. Check separate retention for any delegated backend. [Usage and cost](https://developers.openai.com/api/docs/guides/voice-latency-cost?api=live) · [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data)

## OpenAI Realtime Speech-to-Speech

- **Connection and media.** WebRTC uses `/v1/realtime/calls`. The unified setup sends SDP and session configuration through the application server. An alternative uses a short-lived secret minted with `/v1/realtime/client_secrets`. Audio travels on negotiated media tracks and events on a data channel. A server WebSocket uses `/v1/realtime` and exchanges events with base64 audio. For WebSocket PCM use mono signed PCM16 little-endian at 24 kHz. The session schema also lists G.711 μ-law/A-law. [WebRTC guide](https://developers.openai.com/api/docs/guides/voice-webrtc?voice-api=realtime) · [WebSocket guide](https://developers.openai.com/api/docs/guides/voice-websockets?voice-api=realtime) · [Client secret and session schema](https://developers.openai.com/api/reference/resources/realtime/subresources/client_secrets/methods/create)
- **VAD and interruption.** Supported speech-to-speech models default to `server_vad` and can use `semantic_vad` or client-managed boundaries. With VAD off, the client commits the audio buffer and explicitly requests a response for the manual turn. When automatic interruption is enabled, VAD can cancel the current response. WebRTC manages the output buffer and truncation on the server. WebSocket clients stop the local player and send `conversation.item.truncate` with the played duration in `audio_end_ms`. For manual interruption, send `response.cancel` for an active response, then clear WebRTC output with `output_audio_buffer.clear` or perform the WebSocket stop and truncation. Observe cancellation as `response.done` with status `cancelled`. Provider buffer accounting and actual device playback are distinct evidence. [VAD guide](https://developers.openai.com/api/docs/guides/realtime-vad) · [Audio and interruption lifecycle](https://developers.openai.com/api/docs/guides/realtime-conversations)
- **Recovery and expiry.** Client-secret expiry limits new session creation, and an already-started session may continue beyond the secret expiry. A secret can create more than one session while valid. The documented default lifetime is 600 seconds, configurable from 10 to 7,200 seconds. The speech-to-speech guide lists a 60-minute session limit. The reviewed client connection flows provide no resumable handle for replaying uncertain audio or recovering the full conversation after disconnect. When the original session cannot be recovered, create a new one and restore only authorized, committed context with a visible discontinuity. [Client secret reference](https://developers.openai.com/api/reference/resources/realtime/subresources/client_secrets/methods/create) · [Realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations)
- **Usage and data.** `response.done` includes response status and can include token usage with modality details. `rate_limits.updated` reports rate-limit state. Continuous Realtime transcription/translation use separate duration-based rates where specified. The OpenAI data table lists `/v1/realtime` with no application-state retention, 30 days of default abuse monitoring retention and conditional ZDR eligibility. [Server events](https://developers.openai.com/api/reference/resources/realtime/server-events) · [Usage and cost](https://developers.openai.com/api/docs/guides/voice-latency-cost?voice-api=realtime) · [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data)

## Gemini Developer API Live

- **Connection and media.** `v1beta` is a stateful WebSocket interface marked preview in the API reference. The `gemini-3.8-live` model's general availability is a separate release fact. Send `setup` first and wait for `setupComplete`. For client-side access, a trusted backend can mint an ephemeral token for the constrained WebSocket endpoint. A server-side connection can use an API key. The audio contract uses raw signed little-endian PCM16 with native 16 kHz input, MIME-declared input rate and resampling, and 24 kHz output. [Wire reference](https://aistudio.google.com/api-reference/live/bidi-generate-content) · [Audio formats](https://aistudio.google.com/docs/live-api/capabilities#audio-formats) · [Model changelog](https://aistudio.google.com/docs/changelog#09-15-2026) · [Ephemeral tokens](https://aistudio.google.com/docs/live-api/ephemeral-tokens#create-a-token)
- **VAD and interruption.** Automatic activity detection is the default. A client can disable it and send `activityStart`/`activityEnd`. On `serverContent.interrupted`, stop and flush local playback. The history described by Google includes content already sent by the service. The reviewed public schema mentions optional playback status but supplies no documented equivalent to exact played-offset truncation. `toolCallCancellation` identifies tool calls to cancel. Track actual effect outcomes separately. [Activity and interruption](https://aistudio.google.com/docs/live-api/capabilities#interruptions) · [Server content](https://aistudio.google.com/api-reference/live#BidiGenerateContentServerContent) · [Tool cancellation](https://aistudio.google.com/api-reference/live#BidiGenerateContentToolCallCancellation)
- **Recovery and expiry.** `GoAway` warns of connection turnover. Opt-in resumption uses the latest applicable `resumable: true` handle, with a documented two-hour validity after termination. A handle can precede non-resumable generation or tool work, so it cannot prove delivery or exact replay. The guide lists roughly ten-minute connections. Without context compression, it lists session limits of 15 minutes for audio-only and two minutes for audio and video. The default ephemeral credential permits a new session within one minute and messages within 30 minutes. Resumption within expiry can reuse the token without consuming another use. [Session management](https://aistudio.google.com/docs/live-api/session-management) · [Resumption update schema](https://aistudio.google.com/api-reference/live#SessionResumptionUpdate) · [Token lifetime and uses](https://aistudio.google.com/docs/live-api/ephemeral-tokens#create-a-token)
- **Usage and data.** `usageMetadata` reports token counts with modality detail. Limits vary by model, project and tier. The reviewed sources give no fixed Live quota or complete WebSocket close-code retry map. Generating a resumption handle can retain audio, video and text conversation state for up to 24 hours. Disabling resumption avoids that specific storage. The paid service has separate limited abuse logging, and the unpaid terms have different data-use conditions. Check the applicable account, region and service terms. [Usage](https://aistudio.google.com/api-reference/live#UsageMetadata) · [Rate limits](https://aistudio.google.com/docs/rate-limits#current-rate-limits) · [Data retention](https://aistudio.google.com/docs/zdr#customer-data-retention-and-achieving-zero-data-retention) · [Service terms](https://aistudio.google.com/docs/terms)

## Compatibility Boundaries

Use distinct adapter protocol IDs, events, credential scopes, stop semantics and recovery policies. File ASR/TTS compatibility does not establish any of these realtime transports. Provider credentials grant access to the vendor service. Hermes owner identity, targeted cancellation, actual playback and native effect confirmation each need separate evidence.

These sources describe provider contracts on the verification date. The native GPT-Live fixture verifies request construction and refusal paths with a synthetic upstream. Live transport, account limits, prices, retention settings, audio quality and device behavior were skipped. The project has no selected production Realtime or Gemini Live adapter.
