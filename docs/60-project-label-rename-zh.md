# 60. 原子重命名本地项目标签

[English](60-project-label-rename.md) | 简体中文

这条显式本地命令可以整体重命名任务标签组，包括已完成和已取消任务，而不破坏同项目依赖。
它是 E2.1 的本地域功能切片，不是原生 Project 身份、worker 操作，也不表示整个 E2 已完成。
不会联系提醒、看板、目录、外部资源或模型。

## 预览并显式应用

```text
/personal-tasks project-rename-preview --project "Old name" --new-project "New name"
/personal-tasks rename-project --project "Old name" --new-project "New name" --expected-snapshot HASH --request-id rename-1
```

使用第一条命令实际返回的 `snapshot` 哈希。预览提供精确的新旧标签、总数和
captured/done/cancelled 数量，不包含任务正文。如有需要，另行查看任务列表。
对应 CLI 前缀为 `hermes personal-agent tasks`；原生输出默认是可读文本，支持前置
`--json`。CLI 默认 JSON，支持 `--format text`。

两个标签都沿用精确、区分大小写的验证规则（1–80 字符，无首尾空白或控制字符），且必须不同。
来源标签必须存在，最多包含 1,000 个任务。目标标签必须**没有任何任务**，包括终态任务；
操作不会合并标签组，也不包含未分配任务。

快照绑定两个标签及按顺序排列的来源任务 ID、版本、状态。新增任务、任务移出组或任何版本
变化都会使快照失效。应用时还会再次检查目标标签是否被占用。快照是并发检查，不是授权令牌，
也不是跨命令持有的锁。现有本地配置分区／操作员准入仍然适用；复制哈希不会增加访问权限。

## 事务和恢复

应用在一个 `BEGIN IMMEDIATE` 写事务中验证当前标签组及全部依赖引用，比较快照后才整体
更改标签。每个受影响任务增加一个版本和时间戳，并记录 `rename_project` 元数据历史事件。
依赖边、任务状态、到期日、工作／进展说明、解决证据以及已有原生观察均保留。终态任务仍为终态：
这是范围明确的标签变更，不是重新打开任务或编辑完成证据。任何步骤失败都不会提交部分重命名。

新版本会使旧任务编辑和绑定版本的授权／快照失效。已有原生卡片、移交账本和保存的进展不会
被重命名或刷新；本地标签改名不等于与它们同步。使用旧移交前应检查其现有版本／身份校验。
保存的历史和旧重试回执仍是历史记录，已提供给模型的上下文不会被重写。

必须提供稳定且显式的请求 ID。精确重试返回原有仅含元数据的回执，即使后来又重命名或进程
重启也一样。重试不会重命名后来复用旧名称的新任务。同一键携带不同参数会冲突。结果不确定时，
使用同一键和相同参数重试，不要悄悄生成新键。过时预览需要显式重新检查。

没有引入数据库模式迁移。与现有任务读取一样，即使逻辑操作只是预览，打开存储也可能初始化
或迁移受支持的旧模式。输出有界，但不承诺大型存储的扫描延迟。没有自动重命名、新的模型工具
动作、远程 API 或通用终态修改权限。

## 验证边界

合成单元测试覆盖相连的活跃／终态任务、解决和进展字段保留、相同请求并发、过时预览、目标冲突、
精确标签、有界标签组、损坏依赖、存储失败回滚以及重启重放。原生命令解析和呈现不依赖模型或
Gateway。离线测试不代表完整实时 Gateway／用户验收。本变更不证明断电持久性、备份恢复或
外部投递恰好一次。
