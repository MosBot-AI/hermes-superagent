## Current E0.1 target

The current [compatibility record](../compatibility.json) targets Hermes `2281116525106e3c109993ccb5dc74d02bfc1427`, the latest upstream main observed on 2026-11-08. We test a fixed observed revision rather than following moving `main` during a run. Exact clean-Git identity checks remain mandatory; official source archives lacking `.git` do not satisfy those checks. No broad version range is claimed.

The earlier MacBook probe of this revision passed all three official real Gateway lifecycle tests and a synthetic plugin ticket/WebSocket task/restart/deduplication flow. Its archive-based contract run passed 1,037 tests and failed two Git identity guards, not behavior assertions. This is not official installation or real-provider acceptance, and does not repair the cloud executor's socket restriction. The latest source hashes used by the Kanban guard are unchanged.

Review-only host proposals keep their historical base and isolated interpreter. They are not silently rebased or counted as latest-host support. New clean-checkout results are recorded in the linked Issue/PR for [E0.1](https://github.com/MosBot-AI/hermes-superagent/issues/1).

## E0.2–E0.3 native lifecycle scope (22811165)

The [native lifecycle contracts](75-native-lifecycle-contracts.md) add actual operator Project/Kanban/cron creation, queries and archive/cancel/history probes in disposable synthetic profiles. The target and plugin runtime dependencies are unchanged. The exported plugin API includes `cron.execution_identity`, not a Project/Kanban/cron CRUD SDK; test-only imports of native consumers do not make private internals production seams.

The evidence distinguishes weak native deduplication, Project metadata archive, limits on Kanban archive side effects, a saved-but-unregistered cron job, cancel-request acknowledgement and an abandoned attempt's `unknown` result. An actual one-off constant-output `no_agent` script supplies a local completion receipt with suppressed delivery. No model, live daemon, real account or external delivery is involved. Exact executed results belong to [Issue #11](https://github.com/MosBot-AI/hermes-superagent/issues/11) and its linked PR, not the historical totals below. E3/E4 and live acceptance remain separate.

## E0.4 RPC/MCP boundary scope (22811165)

The [write-path evidence](13-enforcement-contracts.md) adds actual RPC server/default nested dispatch and the generated persistent client's response-loss retry over an in-memory wire. Actual MCP discovery and SDK stdio probes distinguish registered plugin veto from direct-registry bypass, and native untrusted approval denial from a dishonest read-only declaration. The only new approval substitution is the test UI endpoint; no action gate is replaced.

These 21 focused cases test synthetic effects, not a shell/browser sandbox, real socket transport, connector batch, live worker or production account. Every controlled-write release gate remains blocked. Exact aggregate results belong to [Issue #12](https://github.com/MosBot-AI/hermes-superagent/issues/12) and its linked PR; this does not replace historical counts below or complete E0.4.

## E0.4 actual-package exposure scope (22811165)

[Production-exposure contracts](../tests/contracts/test_production_exposure.py) cold load the actual installed-shaped package, with staged module-origin checks and no repository import fallback. They verify default/read-only negative model/registry dispatch, real ordinary-managed/config-only frozen configuration, safe-bootstrap omission, unsupported text-worker refusal and native blueprint consumers. Independent storage and endpoint-call oracles accompany paired loading/opt-in controls; real providers, scheduled jobs and external effects are not invoked.

The [boundary matrix](13-enforcement-contracts.md#27-actual-production-package-exposure-and-fallback) separates unavailable verified-owner/controlled-effect adapters from explicitly enabled local features and ordinary native planning-blueprint scheduling. `read_only` does not override `planning_blueprint: true`, restrict its native delivery destinations or stop pre-existing jobs. A clean-host `llm.text_worker` consent setting is not a granted capability or fallback permission. Concurrent/alternate execution routes, full lifecycle and actual containment remain separate gates. Exact aggregate evidence belongs to [Issue #12](https://github.com/MosBot-AI/hermes-superagent/issues/12), not the historical counts below.

## E0.5 synthetic MCP fixture scope (22811165)

The [offline synthetic connector harness](74-synthetic-connector-fixtures.md) targets the current exact host without changing `compatibility.json`. Its [native contracts](../tests/contracts/test_synthetic_connectors.py) use real MCP discovery, registry/model dispatch and SDK stdio sessions with a durable fake remote. Tests cover lost responses after commit, restart reconciliation, and declaration-driven retry of a deliberately dishonest read-only tool. The session-expiry error is injected after a real stdio RPC; it is not evidence of actual HTTP session expiry.

The test file checks both the host commit and the host-declared MCP SDK pin. Exact executed results belong to Issue #13 and its linked PR; this paragraph does not update the historical counts below. No actual account, provider, OAuth flow, network listener or production connector is enabled. The counterexample is evidence against trusting `readOnlyHint`, not proof of E0.4 enforcement or E1/E5 completion.

## E0.9 native memory scope (22811165)

The [native memory contract matrix](76-native-memory-contracts.md) separates provider discovery/admission, builtin capacity/reload, native history retrieval and lifecycle/context wiring from the existing recall and checkpoint boundaries. Exact execution results belong to [Issue #42](https://github.com/MosBot-AI/hermes-superagent/issues/42) and its linked PR; this addition does not replace historical counts below.

This test-only verification does not enable automatic capture, remote identity, a second provider slot or a production deployment.

## Historical E0.1 evidence (90d6b98)

The previous compatibility baseline pinned Hermes `90d6b98fd86d20981ee06ddd5b7d93e4320f26a4`. The verified environment was Linux, Python 3.14.9 and the pinned Hermes PM environment with `dev` and `test` groups. Most plugin contracts exercise native `in_process` loading in temporary profiles. Keep `semver_support_range` at `null` and leave `requires_hermes` out of the [manifest](../plugin.yaml) until there is versioned compatibility evidence. That exact commit was the development target for the historical evidence below.

The [main push run](https://github.com/MosBot-AI/hermes-superagent/actions/runs/42377180370) on [plugin commit `eefa8845b1ed66b740d9e46de2b8aee77917db0a`](https://github.com/MosBot-AI/hermes-superagent/tree/eefa8845b1ed66b740d9e46de2b8aee77917db0a) passed 2,534 unit tests, 1,039 pinned-host contract tests, lint, formatting, type and bilingual documentation checks. A separate disposable host checkout with the text worker proposal passed 357 tests and two production entry point harnesses. The push also built, scanned and cold loaded the [offline runtime artifact](https://github.com/MosBot-AI/hermes-superagent/actions/runs/42377180370/artifacts/13575019987). These are exact-commit CI results. The deployment and real-provider acceptance gates remain open.

## Reproduction and source notices

Use the [development checks](../README.md#development-checks) with an exact, clean Hermes checkout and its separate Python 3.14 interpreter. The [check script](../scripts/check.py) records the host lock and installed package fingerprints. The [CI workflow](../.github/workflows/check.yml) runs the proposed host patch in its own worktree and builds and checks the offline package separately. See [runtime distribution](runtime-distribution.md) for package provenance and the blocked installation record.

Hermes is MIT-licensed at the pin. The [third-party notices](../THIRD_PARTY_NOTICES.md) identify the upstream license, test dependency provenance and preserved notices for the voice, command-context and text worker patches. The production plugin has no third-party Python runtime dependencies of its own. The package and compatibility evidence cover the current development baseline and leave the wider E0 and release gates open.
